## 零、结论

1. **能合法吸的（MIT / Apache）恰好是我们不需要的**：谬误分类、可信度评分、多 agent 编排、
   辩论聚合。它们都指向「让模型给出结论」，而 2026-11-04 写下这句时以为判定由本地裁决兜住——
   **2026-11-12 更正：那句是错的**。判断由模型写出，十一道裁决只在输出越界时纠偏；
   已定定位见 [产品定位](产品定位.md)。保留原文，是为了让这处改口看得见。
2. **我们真正缺的（判定口径、评测语料、真实使用证据）不在别人的代码里**，
   在论文、数据集和别人的失败里。搬代码解决不了这件事。
3. 所以落地的是**三样入口与格式层面的东西、一个验证方法**：
   Argdown 导出（`5dfa30c`）、全局快捷键读剪贴板（`cac1edf`）、
   画布工程导出（2026-11-08，见下），
   以及「拿对方的解析器当裁判」——让「兼容」变成可断言的事，而不是一句自我声明。
   **没有动过判定，也没有动过提示词。**

## 一、许可证事实

| 项目 | 许可证 | 能不能进 exe |
|---|---|---|
| Criticaide | MIT | 能，保留版权声明 |
| ARGUS | MIT | 能 |
| sophistry-skills | MIT | 能 |
| `@argdown/core` | MIT | 能，已作为 devDependency 装进仓库 |
| logikon | **AGPL-3.0** | **不能**。分发即触发，要求整体源码以 AGPL 开放 |
| LogicShield | GPL-3.0（二手来源，未核 LICENSE 文件） | **不能**，同上 |
| Project Graph 桌面应用（`graphif/project-graph`，2026-11-08 核） | **GPL-3.0** | **不能**。分发即要求整体以 GPL 开放；它的格式可以照着写，实现不碰 |
| Project Graph 的 `packages/serializer` | MIT | 能（已发布到 npm），但没用上：我们要的是 `.prg` 的容器格式，不是一个「实例 → 对象」的工具 |
| Skeptik | 未见公开仓库（论文原型） | 只能吸设计，不能吸实现 |
| 得到「拷问」 | 闭源商业 | 只能看行为 |

AGPL 那一条不是谨慎，是硬约束：这个应用要打成 exe 分发给真实用户，
一旦链进 AGPL 代码，整个项目就得按 AGPL 开源。**用户没有同意过这件事，所以不做。**
LogicShield 的 GPL-3.0 是二手来源，真要吸之前必须核它的 LICENSE 文件。

## 二、判据与逐件结论

### 已吸（3 件，都带提交号或日期，可查）

**Argdown 格式** — `5dfa30c`。吸的是**语法与验证器**，不是实现：`@argdown/core` 只在
`check:argdown` 里当裁判，是 devDependency，不进打包产物。改动面见该提交。
为什么值得：Markdown 带走的是「我该改哪一句」，Argdown 带走的是「谁支撑谁」，
后者进了 git 才有 diff。三处边界写进了断言：档位只在注释里且带「不是判决书」；
「接不上」只做注释，不伪造成 `-`（攻击）关系；「此处合法」是孤立节点，不连边。

**全局快捷键的「入口」这一半** — `cac1edf`，来自 Criticaide 的
「选中文本 + 全局快捷键直接分析」。**只吸了一半，这个差异必须说清**：
我们做的是 `Ctrl+Alt+A` 读剪贴板，用户自己先复制；**没有模拟 `Ctrl+C` 去抓选中的文字**。
原因是验证成本——「抓别人窗口里的选中内容」无法无人值守地断言，
而做不到的东西写进界面就是「文档比软件更自信」。判定在 `@shared/capture.ts`（纯函数）：
框里是用户自己的字时只问不覆盖，空剪贴板与超长文本都要说话、不悄悄截断。

**画布工程格式（`.prg`）** — 2026-11-08。吸的是**格式**，不是实现：对方桌面应用是 GPL-3.0，
一行代码都不进这个仓库；我们照着它的容器结构（zip + 四个 msgpack 条目 + 版本 2.7.0）
写了自己的编码器（`@shared/prg-pack`，无运行时依赖）。为什么值得：前两种导出带走的是文件，
这一种带走的是可以自己摆的画布——同一条论证线，有人要按原文顺序排，有人要把反驳挪到旁边写批注。
兼容性照旧由对方判定：`check:prg` 拿 `@msgpack/msgpack` 与 `@zip.js/zip.js` 读回我们编的字节，
另外用**它自己的 CLI** 读过一份导出件（7 节点、6 线，坐标与朝向都对）。
边界与未验的部分见 `docs/与画布工具互通.md`。

### 核过，结论是不改（1 件）

**把 `withdrawIf` 摆到显眼处**（来自 Steelman 的「可证伪条件」）。
清单初版写「先核界面，可能只是挪一处」，2026-11-04 核了：
字段、界面、Markdown 导出三处都有（`src/shared/types.ts`、`Diagnosis.tsx` 自检块、
`report-markdown.ts`），但确实埋在报告末尾，12px 灰字，前面压着 P1–P7 七格与「总分 /14」。

**决定不改**，理由是代码里已经有一条写清了的相反设计：
`Diagnosis.tsx` 边界栏的注释说「放在最后不是因为它不重要——放在最后是因为它说的是
这份报告自身，读者得先看过报告才知道它省掉了什么」。`withdrawIf` 正属这一类。
初版清单建议「摆显眼处」时不知道这条理由；现在知道了，而**没有任何使用证据表明用户找不到它**。
为了显得推进了融合去推翻一条有理由的设计，代价与证据不成比例。

重新打开的条件：有第二个使用者说「没看见撤回条件」，或界面改版顺带重排这一块。
另外记一处**易误读但不撞判据**：报告自检块的「总分 /14」是这份分析自不自信的
自检分（P1–P7），不是 Criticaide 那种 overall credibility score；首屏空态
`App.tsx` 已经写明「这里不给总分，也不替你站队」。两处说的是不同的东西。

### 卡在外部条件（2 件）

| 件 | 来自 | 卡在什么 | 什么条件下重新打开 |
|---|---|---|---|
| 第三层解释「下次怎么认出来」 | Skeptik | **动提示词** → 版本号与指纹变化 → 新旧报告不可比 → 必须重跑 `eval`，而余额为空跑不了 | 有余额、能跑完 `eval` 并比对新旧指纹；且路线图「缺证据不缺功能」的处境变了 |
| 用公开语料做外部对照评测 | CoCoLoFa / MAFALDA | 公开语料是英文，中文这一格是空的；跑一次要钱 | 用户决定接受先做英文对照，或提供中文标注语料，并有余额 |

`docs/同类项目.md` 里还记了 CoCoLoFa 的一条实证（微调 BERT 的 F1 0.86 / 0.87 高于当时
SOTA 大模型），那是「专用小模型 + 高质量标注在分类任务上仍可能赢」的提示，
**不是我们的评测结论**——我们一次都没在它上面跑过。

### 只吸设计，不吸代码（1 件）

**logikon 的指标口径**：AGPL 不能吸代码，但「一条推理轨迹该按哪几个维度审」是学术公共物，
可以当 `eval` 的外部参照，不引进任何一行实现。

### 不吸（逐条写清撞哪一条）

| 他们的做法 | 撞哪条不可动摇 |
|---|---|
| Criticaide 的 Overall credibility score | 第 1 条：不给单一判定。它把「哪里接不上」和「整体可信不可信」压成一个数字 |
| ARGUS / Hegelion / Socratic Council 的聚合收敛 | 第 3 条：分歧本身是输出。它们把分歧当噪声，我们拿它当结论 |
| adversaria 的 Judge 给 verdict | 第 1 条。三 agent 的图再漂亮，最后一行仍是裁决 |
| 多模型投票决定档位 | 判定必须在本地、可复算。投票把判定搬回模型，`replay` 也就失去意义 |
| 各 fallacy finder 以谬误名为主输出 | 查谬误模式已经有四样代价（原文哪句、凭什么是这条、何时其实合法、最可能错在哪），不能再简化 |
| LogicShield 的「论证强度评分」 | 同第 1 条；且 GPL-3.0 不可吸 |
| 把 Project Graph 的画布嵌进来 | GPL-3.0，链进 exe 要整个项目开源；而且它要 Tauri + Rust，与 Electron 打包链不同 |
| 读 `.prg` 反向导入（让画布去改报告） | 报告是判定的产物；读回来之后还得决定「改了哪一句」，那就是第二个判定出口 |

## 三、这份清单回答不了什么

- **没有把任何 GPL / AGPL 代码带进仓库**；只装了一个 MIT 的 devDependency。
- `@argdown/core` 只验了**语法解析**，没验**渲染**：MapPlugin + graphviz 那条路没跑过。
  所以「能在 Argdown 编辑器里画出来」这句话，现在只到「解析器读得进去」为止。
- **真按一次 `Ctrl+Alt+A` 没验过**：自检造不出全局键盘事件；键还可能被输入法或截图工具占用。
  读剪贴板抛错时的现象是「按了没反应」，只在文档里写了，没有端到端覆盖。
- 「快捷键提升了使用频率」**没有证据**，需要第二个使用者与真实使用记录。
- 上面每件「卡在外部条件」的，都只是**判据与卡点**，不是进度；进度看路线图阶段状态。

这份文档不再列「下一件做什么」。结论变了意味着设计变了，那种改动本来就该由人重新写一遍，
不该靠一张会自动过期的待办表提醒。
