# 融合清单：能吸什么、吸了会撞什么

> 与 `docs/同类项目.md` 配套。那份写「外面有什么」，这份写「我们能拿什么、代价是什么」。
> 判据不是「他们的功能好不好」，是**吸进来会不会撞五条不可动摇**（见 AGENTS.md）。
>
> 2026-11-02。许可证一项是 GitHub API 实测（`spdx_id`），其余是读 README / 论文。

---

## 零、先说结论

1. **能合法吸的（MIT / Apache）恰好是我们不需要的**：谬误分类、可信度评分、多 agent 编排、
   辩论聚合。它们都指向「让模型给出结论」，而我们的判定在本地裁决里。
2. **我们真正缺的（判定口径、评测语料、真实使用证据）不在别人的代码里**，
   在论文、数据集和别人的失败里。搬代码解决不了这件事。
3. 所以这一轮只吸了两样：**一种格式（Argdown）**，和**一个验证方法（拿对方的解析器当裁判）**。
   前者让结构能离开窗口，后者让「兼容」变成可断言的事，而不是一句自我声明。

## 一、许可证事实

| 项目 | 许可证 | 能不能进 exe |
|---|---|---|
| Criticaide | MIT | 能，保留版权声明 |
| ARGUS | MIT | 能 |
| sophistry-skills | MIT | 能 |
| `@argdown/core` | MIT | 能，已作为 devDependency 装进仓库 |
| logikon | **AGPL-3.0** | **不能**。分发即触发，要求整体源码以 AGPL 开放 |
| LogicShield | GPL-3.0（二手来源，未核 LICENSE 文件） | **不能**，同上 |
| Skeptik | 未见公开仓库（论文原型） | 只能吸设计，不能吸实现 |
| 得到「拷问」 | 闭源商业 | 只能看行为 |

AGPL 那一条不是谨慎，是硬约束：这个应用要打成 exe 分发给真实用户，
一旦链进 AGPL 代码，整个项目就得按 AGPL 开源。**用户没有同意过这件事，所以不做。**

## 二、四档

### 档一 · 已经吸了：Argdown 格式（1 件）

吸的是**语法与验证器**，不是实现：`@argdown/core` 只在 `check:argdown` 里当裁判，
是 devDependency，不进打包产物。

改动面：`src/shared/argdown.ts`、`src/main/report-export.ts`、IPC、preload、
报告页第二个导出按钮、`check:argdown`、AGENTS/README。

为什么它值得：Markdown 带走的是「我该改哪一句」，Argdown 带走的是「谁支撑谁」，
而后者进了 git 才有 diff。这是唯一一件**既不撞立场、也不动判定**的融合。

撞了什么：没有。但有三处必须守住，写进断言了——
档位只在注释里且带「不是判决书」；「接不上」只做注释，不伪造成 `-`（攻击）关系；
「此处合法」是孤立节点，不连边。

### 档二 · 可吸，但先算账（3 件）

| 件 | 来自 | 撞不撞 | 代价 |
|---|---|---|---|
| 选中文本 + 全局快捷键直接分析 | Criticaide | 不撞 | main 进程常驻快捷键 + 剪贴板读取 + 一屏状态 + 端到端断言；权限与误触要设计 |
| 第三层解释「下次怎么认出来」 | Skeptik | 不撞，但**动提示词** | 版本号 + 指纹变化 + 新旧报告不可比 + `eval` 要重跑（余额为空，跑不了） |
| 用公开语料做外部对照评测 | CoCoLoFa / MAFALDA | 不撞 | 英文语料，中文这一格仍是空的；跑一次要钱 |

排序理由：快捷键提升的是**使用频率**，而项目最缺的正是「真人在真事上用」的证据；
第三层解释提升的是**单份报告的可读性**，但那属于功能，路线图说这个项目不缺功能。

### 档三 · 只吸设计，不吸代码（2 件）

- **Steelman 的「可证伪条件」**：`Diagnosis.selfCheck.withdrawIf` 已经是这个字段。
  要补的不是字段，是**界面有没有把它摆到显眼处**——先核，再决定改不改。
- **logikon 的指标口径**：AGPL 不能吸代码，但「一条推理轨迹该按哪几个维度审」是学术公共物。
  它可以当 `eval` 的外部参照；不引进任何一行实现。

### 档四 · 不吸（逐条写清撞哪一条）

| 他们的做法 | 撞哪条不可动摇 |
|---|---|
| Criticaide 的 Overall credibility score | 第 1 条：不给单一判定。它把「哪里接不上」和「整体可信不可信」压成一个数字 |
| ARGUS / Hegelion / Socratic Council 的聚合收敛 | 第 3 条：分歧本身是输出。它们把分歧当噪声，我们拿它当结论 |
| adversaria 的 Judge 给 verdict | 第 1 条。三 agent 的图再漂亮，最后一行仍是裁决 |
| 多模型投票决定档位 | 判定必须在本地、可复算。投票把判定搬回模型，`replay` 也就失去意义 |
| 各 fallacy finder 以谬误名为主输出 | 查谬误模式已经有四样代价（原文哪句、凭什么是这条、何时其实合法、最可能错在哪），不能再简化 |
| LogicShield 的「论证强度评分」 | 同第 1 条；且 GPL-3.0 不可吸 |

## 三、下一件该做什么

按性价比排，不是按「谁的功能更酷」：

1. **全局快捷键**（档二第一件）。它不碰判定、不碰提示词，只碰入口；
   而入口决定这个工具会不会被日常用起来。
2. **把 `withdrawIf` 摆到显眼处**（档三第一件）。先核界面，可能只是挪一处，不必新增字段。
3. **第三层解释**（档二第二件）。要动提示词，必须等有余额、能跑 `eval` 的时候，
   否则改完只有静态检查绿，判断质量无从比较。
4. **外部语料对照**（档二第三件）。等中文语料，或者接受先做英文。

## 四、没做 / 没验

- 没有把任何 GPL / AGPL 代码带进仓库；只装了一个 MIT 的 devDependency。
- `@argdown/core` 只验了**语法解析**，没验**渲染**：MapPlugin + graphviz 那条路没跑过，
  所以「能在 Argdown 编辑器里画出来」这句话，现在只到「解析器读得进去」为止。
- 快捷键、第三层解释、外部评测都只是清单，没有动手。
- LogicShield 的 GPL-3.0 是二手来源，没核它的 LICENSE 文件；真要吸之前必须核。
