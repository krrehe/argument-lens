# 通俗与可视化

这份文档回答一个问题：**为什么一份准确的报告还需要重做一遍呈现。**

---

## 一、问题不在准确，在入口

第一版报告把每件事都说对了，但读者要读懂它，得先接受三件事：

1. 记住「前提 / 隐含前提 / 中间结论」三个词的差别；
2. 知道「担保」和「理由」不是一回事；
3. 把上方那张检查表和下方那段原文在脑子里对上。

这三件事对一个学过非形式逻辑的人是常识，对其他人是三道门。**门槛不在结论，在词汇和对位。** 一个工具的价值等于「它给出的判断」减去「读懂它的成本」，成本太高，判断再准也等于零。

所以改造分两条线：**让人话先进来，让关系能被看见。**

---

## 二、通俗：不是换词，是重写

### 2.1 每一栏顶上的一句人话

每一栏（原文、结构图、逐关检查、判读、重构、反驳……）在标题下多了一行浅蓝底、带「人话」标签的说明。它只回答一个问题：**这一栏在说什么，我为什么要看它。**

例：

> **击败类型**　削弱 ≠ 反驳
> 人话：分两件事：是他这一步推不出来（削弱），还是你要他信的那句话本身被证伪了（反驳）。绝大多数批评只能做到前者。

这行字是手写的，不是模型生成的，也不随分析结果变化。理由：它是版式的一部分，必须稳定、可校对；让模型每次重新表述，只会引入不稳定。

### 2.2 术语表与悬停解释

`glossary.ts` 收录 40 余个术语，每个都有：

- `plain`：一句人话，**里面不许再出现任何术语**（这是硬规矩，否则等于把解释做成了第二个谜语）
- `more`：为什么它要单独成一个概念（可选）
- `eg`：一个具体例子（可选）

界面上两处入口：正文里带虚线下划线的词（悬停出解释），以及顶栏「术语表」（全量查阅，按骨架 / 评价 / 型式法 / 图尔敏 / 十规则 / PTA 分组）。

顶栏还有「大白话」开关，控制三样东西：每栏的人话说明、透镜芯片与侧栏里的通俗版文案、以及是否展开解释。默认**开**——第一次打开这个软件的人，正是最需要它的那个人。

### 2.3 六副透镜各有一句人话

`theories.ts` 里每个透镜多存一个 `plainClaim` 与 `plainUnit`。它们不是 `claim` 的同义改写，是重写：

| 透镜 | 术语版 | 人话版 |
|---|---|---|
| 型式·CQ | 论证套用惯用型式却未回答其自带的批判性问题 | 这段话用了一个大家惯用的说法——「专家说的」「前后脚发生所以有因果」。套路本身没错，错在这个套路自带的那几个问题，他一个都没回答 |
| 图尔敏 | 担保未被说出，或说出的担保撑不住那一跃 | 把这段话画成一副骨架：他要你信什么、他摆出了什么、凭什么这些理由能推出那个主张。最常见的毛病是那根「担保」根本没说出口 |
| 名录对照 | 把论证映射到传统谬误名录的条目 | 只查字典：这段话像教材里的哪一条。它给名字，不给判决——因为同一个地方往往能对上好几个名字 |

**只替换术语的同义词不算通俗。** 「担保」改成「保证」，「型式」改成「模式」，读者照样不懂。必须换掉整句的构造。

## 三、可视化：每张图各治一种「看不懂」

原则是**图负责关系，文字负责理由**。图不重复文字已经说过的事，也不再承担解释；每张图下面都有图例和一句读法。

### 3.1 结构图（思维导图）

治的是「他在论证什么」。

- 左列：他摆出的依据；中列：中间结论；右列：他要你信的那句。
- 连线＝支撑关系。**实线**是原文说出的支撑，**虚线**是他没说出口的（推定）。
- 节点左侧色条＝这条依据**听众认不认**（可接受 / 可疑 / 不可接受）。注意不是客观真假。
- 节点边框实线 / 虚线＝这句话是原文说的，还是替他补的。**边框只说来源，色条只说评价**，两个维度不混。
- 线上打红叉＝判定这一步接不上。
- 点击任一格 → 上方原文与下方主张卡同步高亮。

连线来自数据契约里的 `supports` 字段（`Claim.supports: string[]`）。模型漏填、写错 id、指回自己，都会在 `analyze.ts` 里统一收口：丢掉未知 id、丢掉自指、空的落到 `["C"]`，并写一条 `SUPPORTS_UNRESOLVED` 留痕。**宁可画成最朴素的重构，也不画一根猜出来的线。**

### 3.2 判读刻度尺

治的是「所以到底算不算站得住」。

三档横条（站得住 / 被削弱 / 不成立），指针指在本次判定所在的那一格，指针上方写「在这里」。若透镜不适用或证据不足，整条变成灰色虚线，写「判不了」。

比原来那枚彩色小标签多出来的信息是**位置**：看见指针停在中段，人才会明白「被削弱」不是「不成立」的委婉说法，而是另一个位置。

### 3.3 逐关检查（跑道 + 表）

治的是「检查表那么多行在说什么」。

上方一排关卡，每关一个按钮：✓ 过 / ✕ 没过 / ? 没答 / – 不适用，附统计「共 4 关：过 1 / 没过 2 / 没答 1」。点任一关，下方表格对应行高亮。

跑道回答「整体如何」，表格回答「凭什么」。两者是同一份数据的两种分辨率。

### 3.4 六透镜地形图

治的是「为什么要换透镜」。

横轴：只管这一段话 ↔ 管整场讨论；纵轴：给你看结构 ↔ 给你个名字。六个点在图上各占一处，点一下即切换。

并排六个芯片会让人以为「随便选一个，精度不同而已」。画成二维之后才看得出：左下三副在拆结构，上边两副在给名字，最右边一副看的是这场讨论还能不能谈下去。**选错不是换了个粗一点的尺子，是换了一把量别的东西的尺子。**

### 3.5 型式族收窄路径（型式·CQ 透镜）

治的是「为什么认定它是这一类套路」。

型式法先归族再落型式，族认错，后面那几个批判性问题会全部问偏——这是日常批评最常见的失误。所以这张图画的是「四扇门里选了哪一扇」，**并且同时画出另一扇可能是哪一扇**（`alternativeFamily`）。族误认要留痕，不能只给一个自信的结论。

### 3.6 图尔敏六零件布局（图尔敏透镜）

治的是「六个零件怎么接」。

文字版把六个零件列成六行，看不出担保架在理由与主张之间、支援撑在担保下面、限定与例外打在主张上——而这套拓扑正是图尔敏那本书的全部主张。

关键的一处：**担保常常没说出口**。所以 `warrantStated=false` 时担保框画成虚线。延续结构图的规矩——**边框只说来源，不说对错**：实线框是原文说出的，虚线框是我们替他补的或空缺的。

### 3.7 ARS 缺口位置（ARS 三标准透镜）

治的是「该补哪」。

三标准查的是同一段论证的三处不同地方：这个前提你认不认（可接受性）、它跟结论有没有关系（相干性）、加起来够不够（充分性）。缺口在哪一处，补法完全不同——补前提是找证据，补联结是补担保，补未说出的前提是把话说明白。

**一处必须克制**：`gapAt=premise` 时数据只知道「某个前提」，没说是哪一条。图上就写「未指名」，不猜。点错一条比不点更糟——用户会照着错的图去补那条不该补的。

### 3.8 PTA 三特征定位（型式周期表透镜）

治的是「三个特征怎么合成一个型」。

原来三个特征各占一个方盒，看不出它们是相乘关系、也不知道合出来的型落在哪。更重要的是必须画出这一点：**特征都定了、型名给不出，是合法输出**。这一栏的价值在于它是「你不同意我的入口」——你可以不同意阶的判定，而不必先否定整个型名。

### 3.9 跑道上的「倒在哪一关」与元问题闸门

治的是「判读和检查表之间的因果」。

跑道原来只回答「整体如何」，判读在另一栏说「被削弱」，两者要读者自己接起来。而 `defeat.checkId` 明写着倒在哪一关——不画出来，等于让读者去做程序本来能做的一步。

此外，`CheckItem.meta` 为真的是**元问题**：答否的话后面几关全部免除。它不是并列的一关，是排在前面的闸门，所以带上一个「闸」字并加左侧色条。

### 3.10 修订走向图

治的是「数字表格看不出方向」。

六项数字并排摆着，读者得自己在脑子里把它们合成一个判断。这张图把每条检查项的移动画成一根线——**斜率是方向，颜色是好坏**。

只在可比的时候画。透镜换了、模式换了、文本改动过大时，同一条检查项在两个刻度上不是同一件事，画一根「从没过到过」的线等于宣布一个并不存在的进步。

### 3.11 专题分析（六个专题，命中与未命中都列）

治的是「检查项只回答这副透镜的问题，别的共识问题没人问」。

六个专题——类比／因果与统计／来源与权威／实践推理／定义与含混／预设与问句——各自是一类论证在文献里的共识问题清单。命中的展开问法，并写明本次逐关检查是否已经问过；未命中的**不消失**，写明为什么没命中。只显示命中的，用户就分不清「没命中」和「没检查」，后者是假绿的另一种写法。

它不给档位（档位只有判读一处），也不调模型——由本次分析已经落盘的判断（型式族、担保类型、命题类型）与原文用词本地推导，零成本、可复现。命中依据全部写明强度：结构信号是硬依据，字面线索是最弱的一档，并且照实承认。

### 3.12 谬误落点图（查谬误模式）

治的是「名字看得懂，但它说的是我哪句话」。

查谬误模式的输出是名字，而名字最容易被当成贴标签——读者看到「事后归因」的第一反应就是「我哪句这样了」。引文块能回答，但要读者自己拿眼睛去对原文；句子一多，对的成本就是怀疑发酵的成本。

- 每个格子是原文的一句，按原文顺序排，不做重排。
- 挂着候选的句子：底色 + 文字转可疑金（与命名卡左条同一语义）；句子下挂胶囊「名字 → 落到的检查关」。
- 点胶囊 → 该命名卡亮边框；反过来点卡上的名字 → 图上对应胶囊亮。**双向**，因为更常见的动作是从卡出发：读完四样代价，回头想知道那句在原文第几句。
- 定位失败（span 质量 failed）或压根没给 span 的命名**不画**，在图下逐条写明原因与名字。宁缺毋错：画一个猜出来的格子，用户会拿着错的句子去质问原文。

对应关系由 `span` 下标与句子的交集算出（`src/shared/fallacy-map.ts`，纯函数、可单测），不靠人眼匹配引文。

### 不做：十规则 × 讨论阶段网格

`PRAGMA_RULES` 里没有阶段字段。语用辩证学确有「哪条规则属于哪个阶段」的经典划分，但按记忆补一份映射，正是「断口不许瞎画」要拦的那种事。要画这张图，得先给规则加 `stage` 字段并核实出处——**记在这里，作为待办，而不是画一个看起来合理的图**。

## 四、让各部分互相指认

单栏写得再清楚，读者仍然会问「我该先看哪」。所以有一层把各栏串起来的结构：

- **开头四句话**：他要你信什么 / 最薄的一处 / 这说明到什么程度 / 想让它站住得补什么。每句都可点，点了滚到对应栏并闪一下边框。
- **跳转条**：结构图 · 逐关检查 · 判读 · 反驳 · 修补 · 透镜产物。
- **同选中状态贯穿全文**：在结构图里点 P2，原文里对应的句子、重构区的主张卡同时亮；在检查跑道点 CQ2，表格对应行亮。

这是「相辅相成」的实际含义：不是再加一段说明文字，而是让读者随时能在**结论**与**依据**之间来回跳，且每次跳转都看得见自己落在哪。

---

## 五、三条自我约束

1. **图的每一处都要有图例。** 没有图例的图只是装饰，用户会按自己的想当然去读，读出的意思可能正好相反。
2. **断口不许瞎画。** `defeat.cuts` 里点名了哪两个主张，就只切这两者之间那根线；点不出名字就不画，图下写明「本次击败位置未能对应到具体连线」。画错一根线比不画更糟——用户会照着错的图去改论证。
3. **术语解释里不许出现新术语。** 违反这一条，解释就会退化成同义词循环，等于没解释。
