## 一、十条操作规则

这十条是硬约束。任何一条被违反，输出的可信度就不成立——不是「不够好」，是「不该发出去」。

| # | 规则 | 出处 | 对产品的强制后果 |
|---|---|---|---|
| R1 | **结构先于评价**。「展示论证的结构……是评估这些论证的先决条件」 | p379 | 没有结构图就不出强度判断。认不出结构时，只能说「无法评估」，不能降级成「凭语感打分」 |
| R2 | **先定门槛，再称重量**。充分性 = 支持力 ≥ 语境 T 所要求的支持力；T = T₁（证据）＋T₂（门槛规范） | p581 | 每条分析必须先填「这个场合要求多强的支持」（必然／高概率／相对优势）。不填，后面的「够不够」是空的 |
| R3 | **三标准不对称，顺序不可平列**。相干性是致命条件，一旦判不相干即决定性反驳；可接受性逐个前提；充分性整体（含辩证层） | p602、p575 | 评估顺序固定为 相干 → 可接受 → 充分。不是三个勾选框，是一条漏斗 |
| R4 | **先认族，再认型式**。四族按「从前提走到结论靠哪种担保」分：后果与替代手段／概括与干预变量／来源与引述／相似与差异 | 附录 A | 族判错，后面问什么都失焦。所以族必须单独一栏，且必须允许填「两族之间」 |
| R5 | **CQ 的肯定回答是击败者，不是证伪者**。削弱性击败切断联结，反驳性击败否定结论 | p562 | 判「削弱」时禁止出现「结论为假」。这两类击败必须分栏，且 UI 上用不同的视觉重量 |
| R6 | **命名是倒数第一步，且可以完全不命名**。每条谬误必须以「使它是该谬误而非别种的条件」表达；标签「价值主要是帮助回忆」 | p707 | 名字可以缺省为空。写不出条件就收回标签——这条要在代码里做成校验，不能只写在 prompt 里 |
| R7 | **谬误 ≠ 结论假**。「即使论证是谬误的，也并不意味着结论假」 | p613 | 每次判完必须接「怎么修补」。修补不出，才说论证不成立；修补得出，正确说法是「型式不当，但结论仍可能真」 |
| R8 | **证明责任二分，不可混**。批评 I（前提可疑、概括不可靠、强度不足）责任在提议者；批评 II（另有反证）责任在回应者，且「仅仅提出这种问题没有规范力量」 | p466–467 | 批评 II 不能单独构成击败。软件不许把「你能证明我说的不对吗」当作得分 |
| R9 | **必须有「这里合法」这一栏**。清单法最深的病：四个名字里有一个其实是对方做对的地方时，你不改判，因为清单没有「合法」这一栏 | 《评估的僭越》 | 每条分析强制检查一遍「有没有哪处看似可疑其实正当」。这一栏不是加分项，是防误伤 |
| R10 | **对话类型先于对错**。同一句威胁在谈判里合法、在说服里是谬误；「重大的错误和误解可能在出现从一个对话类型到另一个对话类型转移时产生」 | p685–687 | 对话类型与阶段是第一个字段，不是最后一个。类型不明写 unknown，不许猜 |

补一条派生规则：

| R11 | **演绎沙文主义是主要误判源**。以「无效」为轴评价一切论证，会把回溯、类比、引导、似真论证系统性判成谬误 | p350、p663 | 只有能给出反例模型时才许说「无效」。否则改说「前提未获担保」「相干性失败」「某条 CQ 未答」 |

## 二、一次完整分析的八步

顺序是刚性的。第 4 步（结构）必须在第 5 步（型式）之前，因为结构决定攻击策略。

### 第 1 步 判功能：这段是不是论证

- **做什么**：判定语篇履行的是「支持」还是别的东西（说明、警告、劝告、报道、举例、条件陈述）。
- **判据**：支持关系是根本标准（p381）；指示词只是线索。区分论证与说明用两把尺：戈维尔的起点差异（从被怀疑的论点 vs 从已承认的事实）、沃尔顿的未决性、恩尼斯的实用检验（作者是否已假定该结果为真）。
- **失败模式**：把因果说明当成论证。汉语里「因为」尤其危险——「她离开了他，因为他酗酒」是说明，不是论证。
- **对应字段**：`context.issue`；若判定非论证，直接退出，不给 verdict。

### 第 2 步 定坐标

- **做什么**：对话类型（八类＋制度性对话）、批判性讨论阶段（对抗／开始／论辩／结束）、争议之点、听众、**门槛 T₂**。
- **判据**：功能变体——「仅当清楚了属于解决过程的特殊阶段要满足的哪个特殊规范没有被满足，才能决定犯了哪个谬误」（p679）。
- **失败模式**：把网络评论区当学术研讨评。这一步错了，后面全错，且错得很有说服力。
- **对应字段**：`context.dialogueType` / `stage` / `audience` / `threshold` / `thresholdBasis` / `contextGaps`。

### 第 3 步 重构

- **做什么**：结论、显式前提、**隐含前提**、中间结论；标准化四转换（删除／补充／替换／排列）。
- **判据**：隐含前提两种，别混——「使用的假设」是作者事实上省略的，「需要的假设」是使论证成立所必需的（p401）。**分析用前者，评估用后者**（p406）。慈善原则取「适度」档：几种解读同等受支持时，取能产生最似真论证的那一个（p405）。
- **失败模式**：强慈善——替作者补最强前提，造成反向稻草人；或补「关联条件句」式空洞前提（p407 明令禁止）。
- **对应字段**：`premises[].implicit` / `implicitBasis` / `implicitKind: 'used' | 'needed'`。

### 第 4 步 定结构

- **做什么**：判四种结构类型——连续（串行）、组合式（linked）、收敛式（convergent）、发散式；处理混杂论证。
- **判据**：主检验是沃尔顿的支持程度检验：「一前提被悬疑时，是否仍给结论足够支持」（p421）。操作化为一句话：**抽掉这条理由，论证还站得住吗**——站得住即收敛，站不住即组合。
- **为什么这步不能省**：它直接决定反驳策略。组合式**打最弱环**即可全塌；收敛式**打最强支柱**才有意义，「一柱断不等于论证垮塌」（p409、p420）。
- **失败模式**：把组合式画成收敛式，后果是低估脆弱性——以为要打三条，其实打一条就够。
- **诚实条款**：这一判别被作者判定为可能不可判定。六种检验（托马斯、弗里曼、戈维尔、亚那尔、沃尔顿、沃罗比基）各有反例，「没有一种检验能捕捉我们关于组合式和收敛式的全部直觉」（p422）。所以字段设计必须是「主判＋次判＋所用检验＋置信度」，并且允许用户一键切换。
- **对应字段**：`structure.type` / `groups[]` / `edges[]` / `testUsed` / `alternativeType`。

### 第 5 步 认族、认型式

- **做什么**：先落到四族（实效／因果／信息源／比较），再落到具体型式 id，再标 `inferenceKind`。
- **判据**：不是看话题，是看担保。靠后果与替代手段→实效；靠概括与干预变量→因果；靠来源引述可靠性→信息源；靠相似与差异的相关性→比较。
- **失败模式**：混用四族的证据逻辑。这是日常论证批评最常见的失焦（第 12 章 Takeaway）。
- **`inferenceKind` 的作用**：决定走哪套评估程序。
  - 演绎 → 反例法（抽型式，问「前提全真时结论可能假吗」，造内容具体、前提肉眼真、结论肉眼假的反例）
  - 归纳／统计 → 查样本、抽样方式、统计口径
  - 回溯 → 不问有效性（按演绎标准它像肯定后件，p350），改问说明力、竞争假说、探查深度、出错代价
  - 类比 → 相似点是否相干、能否举出反类比
  - 引导 → 正面因素分量是否优于反面，有无未被提及但相干的潜在因素
  - 似真／假设 → 资源可靠性排序、举证责任是否正当转移、能否被反证撤回
  - 检证 → 是否老实使用限定词（典型地、其他条件均同、据初步印象）

### 第 6 步 逐条问 CQ

- **做什么**：把该型式的 CQ 清单逐条打勾：yes / no / 未回答 / 不适用。**元问题优先**——「此语境用实效论证恰当吗」「类比是恰当型式吗」「品性在此对话类型中相干吗」，元问题答否，后面全免。
- **判据**：论证强度 ≈ 未被充分回答的 CQ 数目（p562 的近似处理，注意书中未给聚合规则，这是已知缺口）。
- **失败模式**：不问元问题就逐条打勾。结果是拿一套用错的型式问了一堆无关的问题。
- **对应字段**：`criticalQuestions[]`，每条带 `meta` / `answer` / `basis` / `whatItGuards`。

### 第 7 步 判击败、定责任、分级

三个动作必须分开做，不能揉成一句结论。

1. **击败类型**：削弱性（切断联结）还是反驳性（否定结论）。绝大多数 CQ 属于前者。
2. **证明责任**：批评 I 还是批评 II；批评 II 只有启发功能，不构成击败。
3. **分级**：实际支持力（四档：必然／较高概率／相对优势／悬而未决）对门槛 T₂。结论的模态必须与之匹配——只到「相对优势」就只能写「更可能／更可取」。

- **失败模式**：把「支持力只到相对优势」写成「必然」；或把「削弱」写成「该论证不成立」。
- **对应字段**：`defeat.kind` / `criticismClass` / `supportStrength` / `verdict` / `conclusion.modality`。

### 第 8 步 修补、命名、自检

- **修补四问**（每次判完必答）：缺哪条未表达前提？换哪个型式能救？哪条 CQ 可正面回答？证明责任是否已转移到我这边？
- **命名**：可选。写不出「使它成为该谬误而非别种的条件」＋「它对谁、在哪一阶段显得有效」两句，就收回标签。
- **自检**：EPI 七项（P1 出处／P2 语境／P3 位置／P4 撤回／P5 自我适用／P6 完备性／P7 可回应性），单项否决：P3=0 且 P4=0 → 判为「贴标签」。

## 三、三样东西不能给

### 1. 不能给「某论证无效」——除非给得出反例模型

书里两次封这条路：以「无效」为轴是演绎沙文主义（p663）；而「无效性理论并不存在，也不可能存在」（p663–664）。所以：

- 能造出「前提全真而结论假」的具体场景 → 可以说无效。
- 造不出 → 只能说「型式误用」「前提未获担保」「相干性失败」「某条 CQ 未答」。
- 归纳版反例（「为假的可能性多大」）给不出数，因为「如何估价反例的概率」「如何决定何时停止建立反例」无解（p637）。所以归纳论证永远不给「无效」，只给「支持力到哪一档」。

### 2. 不能给「结论为假」

针对人身族与承诺族在型式表里「一律只能得『降低可信力』而非『结论为假』」（p556–558）。这条要写进 UI：结论为假是极罕见的输出，触发它必须有独立的反驳性证据。

### 3. 不能给「完整谬误名录」

型式各家列举悬殊：佩雷尔曼上百、黑斯廷斯 9、金泡因特纳 60、沃尔顿等 96、格瑞安理论 576 而合理型式 70 余、敦提 25 而 Araucaria 逾百（p518）。完全性被判无解。所以界面上必须常驻一句「名录开放，认不出是正常的」。

## 四、四个理论死结与处置

这四处是学派自己承认未解决的。软件不该假装解决，应该把死结变成可见的不确定性。

| 死结 | 原文 | 处置 |
|---|---|---|
| **组合／收敛不可判定** | 「没有一种检验能够……捕捉到我们关于组合式和收敛式的全部直觉」（p422） | 输出「主判＋次判＋所用检验＋置信度」，不做唯一裁决。UI 允许一键切换，切换后攻击策略随之改写。切换时提示「这会改变该打哪一条」 |
| **相干性没有理论** | 「我们没有相干性的理论」（p596）；戈维尔主张最后只能诉诸直觉（p608） | 不输出「相干／不相干」二值。输出一个证据式提问：「这条前提增加了结论为真的可能性吗」。判「不相干」必须附「若补充 X 则相干」的挽救路径 |
| **可接受性只有一般理论** | 「这个可接受性的一般理论，并不决定何时一个特殊论证的特殊前提是可接受或不可接受的」（p588） | 用弗里曼三问落地：什么类型的陈述？靠什么资源担保？该担保是否生成假设？再叠「再取证代价」比较。输出「可接受／遭合理怀疑／需辩护」，不给「真／假」 |
| **「看似」由谁认定** | 三派互不兼容：战略机动版（p682）、修辞版（p730）、基于主体版（p738） | 强制填 `appearsValidTo`（对哪类听众、在哪一阶段显得有效）。这是唯一能让「看似」落地的字段，空着就等于没判 |

## 五、数据结构改动清单

对照当前 `src/shared/types.ts`，六处需要改：

1. **加结构层**。现在只有 `premises[]` 和 `intermediate[]`，没有边、没有分组。缺了它，`refutations` 无法回答「打这条够不够」。需要 `structure: { type, groups[], edges[], testUsed, alternativeType }`。
2. **拆 RSA 三标准**。现在只有 `premises[].acceptability` 和单个 `defeat`。需要：每个前提带 `relevance`（状态＋依据＋挽救路径）＋`acceptability`；整体带 `sufficiency: { local, global, threshold, actual }`。
3. **加门槛与支持力**。`context.threshold`（必然／较高概率／相对优势／悬而未决）＋ `supportStrength`。没有这一对，「够不够」无从谈起（p581）。
4. **对话类型补全**。现为 7 类，书里是 8 类（争吵、辩论、说服、探究、谈判、信息寻求、行动寻求、教育对话，p685），另建议补第 7 类「制度性对话」（p654–655）。
5. **加 `inferenceKind` 与 `criticismClass`**。前者决定评估程序，后者决定这条批评有没有规范力量。
6. **谬误条目按进路分列**。同一名称在不同进路下条件不同（诉诸权威在卡亨是三问、在约翰逊归入仓促结论或不相干理由、在卢默属虚假理由）。现在的 `FallacyDefinition` 是「一名一条」，会掩盖这种分歧。

## 六、界面用词表

术语用错，等于把学派的分歧抹平。以下为硬性用词：

| 用 | 不用 | 理由 |
|---|---|---|
| 批判性问题（CQ） | 检查项、考点 | CQ 是型式自带的合法攻击点，不是清单 |
| 削弱性击败／反驳性击败 | 弱反驳／强反驳 | 二者是性质之别，不是程度之别 |
| 前提未获担保 | 前提错误 | 前者是责任问题，后者是真值断言 |
| 相干性失败 | 跑题 | 后者是修辞评价，前者是规范判定 |
| 型式误用 | 用了谬误 | 型式本身无好坏 |
| 此处不构成谬误 | 这里没错 | 前者是判定，后者是否定判定 |
| 在目前证据下 | 事实上 | 前者带模态，后者冒充终局 |
| 支持力到「相对优势」 | 论证比较强 | 前者可对门槛，后者不可 |

## 七、这套理论对产品定位的最终校正

原设计把「谬误检测」当核心。读完第 15—16 章后，这个定位站不住：

- 谬误不是一种东西，而是至少四种：违反对话规则、型式误用、认识过程失败、资源约束下的合理策略（附录 B 第一节）。四种进路对同一段文本会给出互相冲突的判定，而书里只并列不裁决。
- 更麻烦的是伍兹那条：对资源有限的个体主体，「传统的谬误事实上不是谬误」，有些恰是「认知上有效力的不足资源调节策略」（p737–738）。这意味着**大量被骂作谬误的东西，其实是正常人在资源约束下的合理做法**。
- 所以产品的核心不可能是「找出谬误」。只能是：**把论证摊开成可检验的结构，指出它在哪一步上缺了什么，并允许结论是「这里没问题」。**

一句话：这个软件卖的不是判决，是**定位**。判决由用户自己做，软件负责让他看清自己在判什么。
