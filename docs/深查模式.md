# 深查模式

第六个分析模式（`deep`），2026-11-24 落地。

它回答的问题不是「这段论证站不站得住」——那是诊断已经回答过的；它回答的是
**「刚才那份诊断漏了什么，这些遗漏经不经得起反驳」**。

所以它不是第七副透镜。透镜决定「用什么理论问」，深查决定「问完之后再查一遍」；
六副透镜的边界、互不翻译、不折算总分这几条，一个字都没改。

---

## 一、为什么是两遍

一遍诊断有一个结构性缺口：模型写完一份看起来完整的报告，就很难在同一口气里
指出「这份报告自己漏了什么」。让它「再检查一下」通常只会得到同一套结论换个说法。

深查因此拆成两次调用，共用同一份 system：

| | 输入 | 输出 |
|---|---|---|
| 第一遍 | 原文 + 诊断的全部要求 + 深查块 | 一份标准诊断，外加 `deep.findings` / `deep.unlocated` |
| 第二遍 | 同一 system + 原文 + 第一遍的 JSON | 只输出 `{"challenges":[...]}`，逐条反驳第一遍的发现 |

第二遍**不许新增发现**，只许改状态、写最强反驳、写「什么会改变它」。
这条限制由本地账本强制执行：出现第一遍没有的 id，记一条 diagnostic 并丢掉。

两遍的费用与等待约为标准分析的两倍，模式横幅里写明这一点。

## 二、发现长什么样

类型只影响分组，不参与判定：

| `kind` | 中文 |
|---|---|
| `missing-premise` | 未说的前提 |
| `cq-gap` | 该问没问 |
| `equivocation` | 词义漂移 |
| `burden` | 举证责任 |
| `evidence` | 证据缺口 |
| `structure` | 结构断点 |
| `rhetoric` | 修辞替代 |
| `scope` | 适用条件 |
| `alternative` | 另一种解释 |

每条发现必须带四样东西：

- `targetId`：报告里真实存在的主张 / 中间结论 / 检查项编号；允许为空。
- `quote`：原文的逐字子串；允许为空。
- `theoryRef`：`theory-base.ts` 里真实存在的主张 id；提示词按透镜给一份短清单，
  模型只能从本透镜的清单里选，都不贴切才允许为空。六副透镜共用一张通用清单，
  最后只会得到六份措辞不同的通用批评——walton 的漏点是 CQ，toulmin 的是担保，
  两者的理论依据本来就不该相同。
- `ifChanged`：什么证据或条件会改变这条发现。

指不到任何位置的候选**不丢**，进 `deep.unlocated` 单独列出，并写明为什么指不到。
把「说不清在哪」的发现混进正常计数，是这一层最需要避免的假精确。

### 每副透镜有自己的深查清单

深查不是「拿一张通用清单把六副透镜再问一遍」。每副透镜在 `LensFragment.deep` 里
写自己的优先查找方向与可用 `theoryRef`，只在 `deep` 模式下装进 system：

| 透镜 | 优先找 | 可用锚点（节选） |
|---|---|---|
| walton | 族/型式认错、CQ 只答一半、元问题没先判 | T3-02 / T3-06 / T3-08 / T3-12 |
| pragma | 对话类型或阶段判错、规则违反被写成语气问题、举证转移没单记 | T2-07 / T4-01 / T4-02 / T4-05 |
| ars | 三标准有一关被跳过、受众被默认、相干未过仍评充分 | T2-02 / T2-04 / T2-06 / T4-03 |
| pta | 型式放错格子、把识别写成判定、二阶问题没问 | T3-01 / T3-05 / T3-06 / T2-06 |
| toulmin | 担保没写出或撑不住、backing 缺席、例外没处理 | T1-08 / T2-03 / T2-06 / T2-09 |
| copi | 成立条件不满足、同名异义、漏掉「其实合法」的反例 | T5-01 / T5-02 / T5-03 / T5-04 |

真模型评测里，walton 的两条发现落在「CQ 元问题」与「隐含前提」，
toulmin 的两条落在「自曝替代原因没被当例外」与「行动建议与结论之间没有桥」——
不是同一套通用批评换了说法。

### 状态

| `status` | 中文 | 含义 |
|---|---|---|
| `open` | 未反驳 | 第一遍写下、第二遍还没来得及处理 |
| `confirmed` | 站住 | 扛过了第二遍写下的最强反驳 |
| `weakened` | 被削弱 | 反驳成立了一部分 |
| `rejected` | 被推翻 | 反驳成立，这条发现应撤回 |
| `unresolved` | 未决 | 第二遍没给出可用的反驳，或第二遍没跑完 |

**「站住」只表示它扛过了这一次反驳，不表示它是真的。** 界面与 Markdown 导出
都带这句边界，不把它抬成判决。

## 三、本地只核对四件事

判断（发现本身、反驳、状态）由模型写出。本地不判发现真假，只核对：

1. **落点**：`targetId` 在结论 / 前提 / 中间结论 / 检查项里是否存在。
2. **引文**：`quote` 去掉外层引号后，是不是原文的逐字子串。
3. **理论依据**：`theoryRef` 是不是主张库里真的有一条。
4. **状态与 id**：状态在五个枚举里、id 不重复、每条都有第二遍的反驳。

落点与引文同时对不上 → 记入 `unlocated`，不进正常计数；
只对不上一样 → 留在卡片上标出 `targetOk` / `quoteOk` / `theoryOk`，不丢。
所有对不上的地方都写 `DEEP_*` diagnostic，界面可见。

这条边界与产品定位一致：本地做定位、字面比对、结构核对、计数，
**不独立判定「这条发现对不对」**。

## 四、失败时怎么写

| 情况 | 报告怎么写 |
|---|---|
| 第一遍没返回 `deep` | 记 `DEEP_MISSING`，深查栏写「这一遍没有返回发现账本」；最常见的原因是模型把 `deep` 拼在根对象外，被 `extractJson` 丢掉——v3.1.1 起 `deep` 已写进深查专用 schema |
| 第一遍返回空账本 | 保留空账本，界面写「空着不是没有问题，是这一次没有写下来」 |
| 第二遍请求失败 | 第一遍诊断照常可读；全部发现标 `unresolved`，记 `DEEP_INCOMPLETE` |
| 第二遍返回空 `challenges` | 记 `DEEP_CHALLENGE_EMPTY`，发现保持第一遍状态 |
| 第二遍出现未知 id / 重复反驳 | 记 diagnostic，不新增发现 |

旧报告没有 `deep` 字段时，界面与导出都不长这一栏，不补空标题。

## 五、界面与导出

- 报告第一节是「深查发现」，排在总结之前：先看漏了什么，再看诊断写了什么。
- 每条卡片写类型、标题、细节、落点、引文、理论依据（可点开主张库）、
  「什么会改变它」、第二遍的反驳与状态。
- **落点与引文可以点回报告**：落点按编号分两类——C/P/I 回原文标记或重构卡，
  CQ/检查项回逐关检查并高亮那一行；引文先找包含它的主张，找到就选中并滚到
  原文标记，找不到就退回原文那一节。只导航与高亮，不改报告，也不新增判定。
- 落不到原文的候选单独一段，不与正常发现混排。
- Markdown 导出在整体分析之后插入「深查发现」一节，逐字来自同一份数据。
- **跨报告的发现库**在「历史」面板第三个页签：把本机所有深查报告里的发现摊平，
  显示份数、条数、落不到原文的候选数，按终态/类型筛选，可按标题、引文或原文搜；
  点一条回到那份报告（发现栏在第一节）。总述下一行写「反复出现」：出现在两份以上
  报告里的类型，按**报告份数**排序，最多三条——同一份里写三条同类型不算。
  它只读已落盘的账本，不重新分析；读不出来的报告份数单独说，
  不把「少读了几份」当成「没有那些发现」。

### 自省：只汇总，不另判

深查报告在「深查发现」后多一块自省，只把四类线索按来源摆开：

- **模型自认**：`selfCheck.unknowns` / `withdrawIf`；两栏都空时照实写「没写」，不补。
- **本地数的**：`auditReport` 的结构矛盾与缺口，原样搬入。
- **深查账本**：`deep.unlocated` 与被削弱 / 推翻的发现；全部被削弱而判读仍「站住」时，单列「两层并列」。
- **版本**：`promptHistoryOf` 发现脱节时写一句；版本与指纹对得上不写。

不新增判断、不改档位、不打分；没有线索整块不出现，普通诊断也不长（报告没有深查账本与第二遍终态）。
Markdown 导出同源。

## 六、验证

| 关卡 | 守什么 |
|---|---|
| `check:contract` | 落点 / 引文 / 理论依据核对、`unlocated` 分流、id 去重、第二遍合并、未反驳 → `unresolved` |
| `check:report` | 缺反驳、落点/引文/理论依据失败、id 重复、空账本都能被抓；另有发现库 10 条、自省 13 条纯函数断言（分来源计数、空栏照实说、版本对齐不虚报、结果确定） |
| `check:export` | 深查导出件有「## 自省」、来源标签分得开、边界句写明「这是自省，不是判决」；普通诊断不凭空多出一节 |
| `check:archive` | 发现库的 `archive:deep` 存在且纯读、走同一次 `reportScan`、带回坏文件数；preload 暴露 `DeepArchiveView`；历史页签与样式接线 |
| `SMOKE_PANEL=history` | 历史面板有「深查发现」页签；默认没有深查账本时说的是「还没有深查发现」，不是空白；`SMOKE_MODE=deep` 时读到至少一条发现，不是空态 |
| `check:corpus` | 42 段语料里两条深查语料（`deep-lab-meeting` / `deep-policy-note`），六种模式都有覆盖 |
| `check:flow` | 六种模式的判定与清空范围，深查给档位 |
| `SMOKE_MODE=deep npm run smoke` | 账本、终态、第二遍反驳、`unlocated`、理论依据与自省四类线索落屏；默认 smoke 守「非深查不长自省块」 |
| `pack:check` | 打包产物里深查账本的探针字段齐全，普通诊断不长深查账本，也不长自省块 |
| `npm run eval` | 两条深查语料走真模型两遍：42/42 有结果；v3.2.0 下两条深查各 2 条发现、终态均 `weakened`，walton 落 T3-06、toulmin 落 T2-03/T1-08，落点与引文全部对上；walton 的第二条发现 theoryRef 为空 |

修完由 v3.1.1 重跑确认；细节见 `docs/评测报告.md` 的 2026-11-24 补记。

## 七、不做什么

- 不加第七副透镜。
- 不让本地写一条新发现，也不给发现打分、排序成「最值得看」。
- 不把发现数折进判读档位，不因为「发现多」就降档。
- 不把「站住」写成「已证实」。
- 不在第二遍里允许模型改判读或新增发现。
