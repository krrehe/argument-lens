# 第七编 · 理论到代码

> **核心问题**：如果一条理论没有落到某个字段、某条守卫、某个界面元素上，它是不是只是装饰？

这一编是验货单。凡在这张表上的，说明它真的在约束软件行为；凡不在这张表上的，要么写进「未落地」，要么承认它只是背景知识。

## 二、七道守卫在理论上的位置

守卫不是工程补丁，每一条都对应一个理论断言：

| 守卫 | 拦的是什么 | 对应理论 |
|---|---|---|
| **G1** | 名录透镜给出了终局判定 | 名录法只能对照，不能判决（15） |
| **G2** | 范围门判不适用却仍给了检查项 | 不适用的尺子量出的刻度是假的（1、20） |
| **G3** | 削弱性击败写成「结论为假」 | 削弱≠反驳（4） |
| **G4** | 命名缺门槛 | 写不出「使它成为该谬误而非别种的条件」就收回标签（16） |
| **G5** | 型式 id 不在库内 | 给错名字比不给名字坏（14） |
| **G6** | 检查项 system 与透镜不符 | 六份模块互不引用（架构约束） |
| **G7** | 固定清单未列全 | 留空会被读成「没问题」（24） |

**每一条都往 `diagnostics` 写一条记录**，因为静默修正是另一种撒谎。用户看到的修正必须是可见的修正。

## 三、这一轮新增的三处落地

本轮（理论学习）带来的实际代码变化，只有三处，但都是真的：

### 1. `SchemeDefinition.criticalQuestions[].why`（第三编的落地）

型式库从 14 型扩到 22 型，每条 CQ 都补了一句 `why`：这一问守的是担保的哪一环。

**为什么这条重要**：它把「CQ」和「检查表」在数据层面分开了。写不出 `why` 的 CQ，就是清单上的一格，应当删掉；写得出，它就是这条推理实际依赖的条件。

**检查方式**：库里的每一条 `why` 都必须能回答「如果不问这一条，哪种错误会漏过去」。答不出的就是凑数的。

### 2. 证言不正义的边界（第五编的落地）

针对人身型式加 CQ4（元问题）：降低可信度的依据是具体条件还是身份特征。

同时在内核提示词里单列一节，在专家意见的 `inapplicableWhen` 里写明。

**为什么必须写进代码**：模型天然顺着文本语气走。一段带偏见的文本，模型很容易把偏见复述成分析结论。那时工具不是在指出偏见，是在放大它。

### 3. 理论卡（第二、三、五编的界面落地）

`src/shared/theory-notes.ts` 为六副透镜各写一张卡：道理在哪、谁反对它、它怎么答、测不出什么、可查出处在哪。

界面上是透镜面板里的一个折叠区「凭什么这么判（想追问的人点这里）」。

**为什么要有**：用户读完一份判定，最自然会问「你凭什么」。只答「某某说的」是把权威当理由——而这套工具连专家意见都要追问六条 CQ。它自己不能靠权威站住。

## 四、未落地清单（诚实版）

这些是这一轮**没有做**的，以及为什么：

| 项 | 状态 | 原因 |
|---|---|---|
| Dung 式攻击图 | 未做 | 结构图只画支持。攻击关系抽取受限于「支持/攻击取决于父节点」这个结构性天花板；算得出来，抽不出来 |
| 双透镜并行 + diff | 未做 | 架构支持（`repair.alternativeReading` 已提供跨透镜文本），但界面没做。这是下一项最有价值的功能 |
| 历史记录 | 已做，但有条件 | 报告按 id 落盘，修订对照只比「同一透镜、同一模式」的两版；没有全文搜索，切分仍是启发式。这一行原先写「未做」，是陈旧说法，第十轮重写历史面板时没回头改 |
| 门槛的领域默认值 | 未做 | 现在必须手填。做默认值是危险的：默认值会让「无法判定」这个真实状态消失 |
| PTA 中文落地验证 | 未验证 | 主谓切分在口语里经常不成立。代码允许三特征全 undetermined，但此时应视为透镜失效——目前只给警告 |
| `copi` 候选上限 3 | 硬编码 | 若某段文本确实同时吻合四类，第四条会被静默截掉（只在 diagnostics 体现） |
| 认知解释进入判定 | 不做 | 论证式推理理论与 myside bias 只用于**设计取向**（多提问、少断言），不参与任何判定。它们的实证基础仍有争议，不足以支撑判决 |
| 支持力四档的聚合 | 有意不做 | 任何聚合权重都是编的。宁可给粗糙但诚实的分布 |

## 五、怎么检验这份理论支撑有没有用

三条可操作的检验，不用读完整套文档也能做：

**检验一：删掉一条理论，看代码会不会坏。**
随便挑一条（比如「元问题优先」），把它从提示词里删掉。如果输出看不出变化，说明它本来就没在起作用——那它应该从文档里降级为「背景」，而不是继续假装是约束。

**检验二：找一个反例，看文档有没有接住。**
比如「有没有一个论证，三标准全过但仍然不是好论证？」——Govier 的第四条件就是为这个问题准备的。如果文档答不出，说明它只是复述，没有承重。

**检验三：看结论能不能被推翻。**
每条 C 档判断都写了「可以被推翻」并给了代价。如果一条判断找不到推翻它的方式，它就不是判断，是信念。

## 六、争议层：把「没谈拢的地方」也做成字段

前五节讲的都是「理论给了什么约束」。这一节讲相反的一面：**理论之间本身不统一，这件事也必须进代码**，否则软件会假装自己站在一个没有分歧的共识上。

前文每一编都写了「互相对立的立场」，但那些对立原先只活在文档里。第七轮把它们变成了数据：`src/shared/disputes.ts`，11 条，每条两组对立立场 + 本工具站位 + 出处。

| 做法 | 为什么这么做 |
|---|---|
| 每条争议必填「接受这一派的代价」 | 只写主张不写代价，就是替自己那一边说话。这一栏强制把站边的成本写出来 |
| 站位指定到某一派，不写「各有所长」 | 「各有所长」等于没站边，读者无法据此攻击任何东西 |
| 触发由 `disputesIn(diagnosis)` 纯函数推出 | 争议是查表不是生成。让模型自陈「我这里可能有争议」，它一定说得比实际多 |
| 与「不确定」分成两套显示 | 混在一起，「有争议」就变成万能免责声明，从而失去信息量 |
| 站边用蓝灰而非红绿 | 红绿是评价。「哪一派更对」在这里是未知，用红绿等于把未知说成已知 |

这一层对本编的意义是：**「落到哪个字段」不止有判定字段，还有一个专门装「我们没站定」的字段。** 一个只记录结论的系统，无法表达「这一步有两种站法」；而无法表达它的系统，迟早会用一句「仅供参考」把差异糊过去。

详见 `docs/理论争议.md`。

## 八、主张级索引：把「落到哪个字段」变成可查的

前七节都在讲「这条理论落到了哪」。但它们有一个共同的粒度问题：**一副透镜一张卡**。而一副透镜背后有七八条互不相同的主张——「按 RSA 三标准判」这一句，往下至少挂着六条：三标准是漏斗不是打分、可接受性问理由不问意愿、Freeman 的三问、场域依赖决定门槛、充分性没有通用阈值……

卡片只能给整副透镜的「道理在哪」，给不了一条的根据。所以补了第四层：`src/shared/theory-base.ts`，102 条主张，跨十编（第八至十编是后来补的三条线索：批判性思维、哲学与人文视野、其他论证传统）。

每条四个实质字段，其中 **`decides` 是准入门槛**：

| 字段 | 不合格的例子 | 为什么不合格 |
|---|---|---|
| `claim` | 「论证具有可废止性」 | 术语堆叠，外行读不懂，等于没解释 |
| `tier` + `refs` | 「研究表明……」 | 没有具体文献，无法核查 |
| `decides` | 「应当重视前提可靠性」 | 指不出字段、指不出行为，等于没有落地 |

**指不出落点的主张不许进库。** 这条规矩的用途不只是给用户看——它同时是一面镜子：写不出 `decides` 的地方，就是这一编的理论其实还没落到代码里的地方。这个库因此也是一个自查工具。

三档标注与判定里的 `tag` 是同一套纪律，判据写在 `docs/理论主张库.md`。当前分布 A 22 / B 38 / C 26：**后两档加起来比第一档多，这是实情**。把 C 档 26 条标成 A 档，这个库会显得很硬，然后每一条都经不起追问。

界面上的两个入口互指：顶栏「参考」里的「理论」打开全文，侧栏透镜卡底部列出**这副透镜专有**的那几条（六副共用的 66 条底座单独交代数量，不混进列表——第一版混在一起，侧栏显示「这一栏站在 39 条主张上」，而 39 条等于全部，等于没有信息）。

这一层有一类脱节风险，必须写明：**代码改了、主张没改**。类型检查管得到字段名打错，管不到语义过时。

`npm run check:theory` 能抓住其中一部分，且都是出过事故的那几类：

- decides 里的代码标识符必须真的存在于 `src/`——库里曾经有三条写着 `burdenOfProof`、`speechKind`，字段根本不存在（**幻影字段**）；
- 别处（比如报告边界栏）引用的主张 id 必须在库里——**幻影 id**；
- 每编必须有配套文档、条目够数，非工程编不得整编 C 档；
- 每个细分域（专题域要求 ≥3）、每副透镜（≥4 条专有）都要有足够厚度；
- 任意两条主张的相似度不得过 0.45（中文 bigram 重叠系数）——防注水。

它抓不到的那一类更大：**字段还在、语义已经变了**。字段被改名或改了含义，`decides` 里的字照旧能匹配上，检查全绿，而那条主张已经是在说别的东西。这一类没有自动检测办法，只能靠人工对读第一节那张总表与下面第十节那张索引。这一条仍是这一层最大的弱点，写在这里而不是藏在注释里。

## 九、一句话收束
这套理论的用处不在「知道得多」，而在**知道自己在哪一步不知道**。

六副透镜并列、型式识别允许 `none`、CQ 允许 `unanswered`、门槛允许「无法判定」、名录透镜拒绝给结论——这些设计没有一个是谦虚的姿态，每一个都是从具体争论里逼出来的。

底稿最后那句话仍然成立，而且这一轮把它坐实了：

> 这个软件卖的不是判决，是**定位**。判决由用户自己做，软件负责让他看清自己在判什么。

## 十、主张 → 落点 全表

上一节讲的是「这一层有什么」，这一节是可查的索引：**102 条主张逐条落到哪**。

这张表由 `src/shared/landing.ts` 生成（`node scripts/run-gen-map.mjs`），而那张表由 `npm run check:landing` 逐条验过存在：块在、透镜片段在、函数在、界面区块在。
**表里的地址不是写给人猜的，是检查器每次都会核一遍的。**

四种落点：

| 种类 | 意思 | 处数 |
|---|---|---|
| 代码 | 落在 src 里的某个函数、类型或常量 | 70 |
| 透镜片段 | 落在某一副透镜的规则、程序或索引里（属于提示词） | 17 |
| 界面 | 落在报告的某个区块 | 10 |
| 提示词 | 落在内核四模式的某一块 | 10 |

代码占三分之二。这不是偏爱工程，是 T7-07（本地能算的不调模型）的执行结果：
专题分析、边界栏、修订对照、争议命中全部本地推导，它们自然有代码地址。
而「该不该做这件事」那类主张（不评动机、不声明视角、不评制度权力），
地址只有一个——边界栏里那一行。它们落在**声明**上，不落在行为上。这一点表里看得出来，也应当看得出来。

读法：一行的落点列有两格时，第一格是主要的那处；说明列写的是「在那处变成了什么动作」，
不是「在那处出现在了文档里」——后者不算落点。

## 附：上一版这张表错在哪

上一版把 70 条写成「（行为层）」。那个词把两种完全不同的情况混在一起：
真的有提示词指令（只是没有对应字段），和根本没有落点（只有库里那一行字）。
混着的后果是：一批装饰性条目藏在一个听起来中性的词下面，
