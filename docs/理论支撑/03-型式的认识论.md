# 第三编 · 型式的认识论

> **核心问题**：「这条 CQ 没被回答，所以论证在这一处没站住」——这句话凭什么算一个结论，而不是一份待办清单？

这一编是整个架构最核心的一处。如果答不出，`checks[]` 就只是一个打勾表，而打勾表已被证明是徒劳的（见第五编）。

---

## 一、型式不是形式

这是最容易被混淆的一处，混了整套方法就失效。

| | 逻辑形式 | 论证型式 |
|---|---|---|
| 例 | `P→Q, P ⊢ Q` | 「专家 E 说 A，E 在这个领域可靠，所以 A」 |
| 判据 | 句法结构 | 内容与语境（谁在说、说的是不是他的本行） |
| 评价 | 有效／无效，二值 | 抗 CQ 的强度，分档 |
| 反例的杀伤力 | 一个反例模型即推翻 | 反例只推翻对应的那条概括 |

**关键差别**：逻辑形式的正确性靠句法保证；型式的正确性靠**一组默认条件成立**保证。而默认条件不是句法的，是世界的——专家是否真在那个领域，是经验事实，不是形式事实。

所以两件事同时成立：

- 型式可以「看起来像有效的」而实际不成立（这是谬误的外观条件）。
- 型式也可以「不符合任何有效形式」而完全正当（这是演绎沙文主义要避免的）。

底稿 R11 就是从这里来的：**只有能给出反例模型时，才许说「无效」。** 否则只能说「前提未获担保」「相干性失败」「某条 CQ 未答」。

## 二、CQ 的三种理解，只有一种站得住

「批判性问题」这个说法本身是含糊的。至少有三种理解：

### 理解一：清单（ Checklists ）
「这个型式的论证，通常要考虑这几件事。」
- 强处：好懂，好执行
- 致命处：清单是**建议**，不是**义务**。没考虑某一项，最多是「不够周全」，不构成缺陷。而且清单可以无限加长——为什么是这五条不是六条？没有答案。

### 理解二：必要条件的否定（ Necessary conditions ）
「这个型式要成立，这几条必须为真。」
- 强处：有规范力量。少一条，型式就不成立。
- 软处：太强。要求逐条都为真，几乎没有任何真实论证能通过。而且「必须为真」需要能判定真假，而多数 CQ 涉及的是「有没有交代」而不是「是不是事实」。

### 理解三：默认条件（ Defaults / Presumptions ）
「这个型式的推理默认了这几条。默认条件未被建立，结论就还没有站住——但也不等于结论为假，只是它还没被授权说出口。」

**本软件采用第三种。** 理由是它同时满足两个要求：

- 有规范力量：默认条件是这条推理**实际依赖**的东西，不是外加的建议。没建立，推理就是悬空的。
- 不至于过强：不要求条件为真，只要求它被建立（by argument, by common ground, by explicit statement）。「文中没交代」是一个可以确认的事实，不需要判定世界的状态。

这个立场有一个直接后果：**「未回答」是一档完整答案，不是缺口。**

它表示的不是「我不知道」，而是「文中确实没有交代这一环」。这两句话完全不同：
- 前者是分析者的状态
- 后者是关于文本的事实

软件输出的是后者。这就是为什么 `answer` 的第四个值是 `unanswered` 而不是 `unknown`。

## 三、为什么元问题优先

型式库里有些 CQ 标了 `meta: true`。它们问的不是「这条推理的某个环节成立吗」，而是「**这条推理该不该用这个型式**」。

例：实践推理的 CQ1「是否存在与之冲突的目标」，类比论证没有元问题，专家意见也没有——但实践推理、实效论辩、针对人身、诉诸恐惧都有。

元问题优先的理由是**范畴错误会污染一切**：
- 拿「实效论辩」去评一段纯事实争论，会问出「Y 本身合意吗」这种对事实命题无意义的问题。
- 拿「针对人身」去评一段科学争论，会问「品性相干吗」——答案是「不相干」，然后就没了。但如果在这里继续逐条评 CQ，会产出一堆假问题，而且看起来很像分析。

**强制后果**：元问题答否时，后续 CQ 全部标 `not-applicable`，并在 `basis` 里写明「元问题答否，后续免除」。这不是省略，这是正确的评价范围。

底稿第 6 步写的「元问题优先」就是这个意思。它的代价是：有些文本会在元问题处就止步，输出很短。这是对的——一份短而准确的输出，好过一份长而失焦的输出。

## 四、三条真实的反对，与回应

### 反对一：型式靠内容区分，没有识别程序

> No formal guidelines exist for argument type identification, making the task very difficult both manually and automatically.
>
> 〔A 档 · 转引自论证挖掘领域的评述；同类判断见 Dundee 等对 Walton 型式库的评价〕

更具体的版本：两个不同型式可以有同一逻辑形式。「专家说 A」和「知情人说 A」形式完全一样，区别在说话人的身份，而那不在句法里。

**回应：接受，并且改变产品形态。**
- 型式识别降级为**候选**，不是结论：`schemeId` 允许 `none`，允许 `alternativeFamily`，允许在 `alternativeNote` 里写「族可能认错」。
- 识别失败不是错误，是一个合法输出状态（`applicable=false`，建议换透镜）。
- 界面不显示「本次型式：专家意见」这种判决式措辞，而显示「按专家意见这一型来问，因为……」并要求给出 `familyBasis`。

**这条回应是产品形态被外部证据改写的典型例子。** 不是「我们做得更好」，而是「这件事做不到，所以换一种做法」。

### 反对二：没有无效性理论（Massey 式）

> 不存在无效性理论，也不可能存在——因为有效论证与无效论证可以实例化同一个无效形式，所以「没有论证能凭逻辑理由被判为谬误」。
>
> 〔B 档 · 据底稿 p663–664 转述 Massey 的不对称论题〕

**回应：CQ 本来就不判无效。**
CQ 判的是「某个默认条件未被建立」。这不涉及有效性，因此不受 Massey 论题影响。这是一个**规避**而非**反驳**——Massey 是对的，只是他的靶子不是我们。

值得说清这一点：很多「回应批评」的做法是把批评说成错的。这里是承认批评成立，然后说明它打不到。

### 反对三：CQ 的聚合没有规则

这是最实在的一条。原书只给了近似处理——「论证强度 ≈ 未被充分回答的 CQ 数目」——但没有给聚合规则。三条 CQ 未答比一条未答严重多少？元问题未答与普通 CQ 未答能否相加？都没有答案。

〔B 档 · 底稿 p562 附近，作者自认这是已知缺口〕

**回应：不聚合。**
- `checks` 逐条保留，不合成总分。
- 支持力四档（必然／较高概率／相对优势／悬而未决）是**定性判断**，由分析者给出并说明理由，不是从 CQ 计数算出来的。
- 界面显示「10 项里 3 项未通过」，而不是「强度 7/10」。

**为什么不聚合**：任何聚合权重都是编的。编出来的权重会被当作精确信息使用，而它实际上只是分析者的偏好。宁可给一个粗糙但诚实的分布。

## 五、PTA：把「六十选一」改成三次小判断

型式识别难，是因为它要求一次做大分类。Wagemans 的型式周期表换了个做法：不问「这是哪个型式」，问三个正交特征。

1. **一阶／二阶**：前提的主词能否再拆。若前提的主词就是结论那个命题，是二阶。
2. **谓词／主词**：同主词不同谓词 → 谓词论证；同谓词不同主词 → 主词论证。
3. **事实／价值／政策**：前提与结论各属哪类陈述。

三特征相乘得 36 型，并配了 ATIP 识别程序。

**为什么这个改法在工程上更可行**：三次二选一／三选一的准确率，远高于一次六十选一。而且三个特征可以分别报错——「一阶谓词我有把握，事实／价值我判不了」是一种可以输出的状态，单值型式字段表达不了。

**代价**（必须写清）：
- PTA 要求先做形式化重构，口语文本不能直接套。
- 中文口语里主谓切分经常不成立（「这事儿吧，说白了就是」）。
- 36 型不是穷尽，Wagemans 自己没这么说。

**本软件的处置**：三个特征允许全部 `undetermined`，此时视为**透镜失效**（`applicable=false`），而不是「中性结论」。理由：三个特征都判不出，等于这副透镜一个信息都没产出，那它这次就不该给结论。

## 六、这一编落到代码里的东西

| 理论判断 | 代码位置 | 具体形式 |
|---|---|---|
| 型式 ≠ 形式 | `SchemeDefinition.skeleton` | 骨架用自然语言 + P1/P2/∴C，不用符号式 |
| CQ 是默认条件 | `SchemeDefinition.criticalQuestions[].why` | 每条必须写「这一问守的是担保的哪一环」 |
| 未回答是完整答案 | `answer: 'unanswered'` | 单独一档，不并入 violated |
| 元问题优先 | `meta: true` + 守卫 | 元问题答否 → 后续全 `not-applicable` |
| 识别不可靠 | `schemeId: 'none'` | 允许，且不视为错误 |
| 不聚合 | `checks[]` 逐条 | 无总分字段；界面只显示分布 |
| PTA 可全空 | `pta` lens 三特征 | 全 `undetermined` → `applicable=false` |

## 七、出处分档

**A 档**
- 「No formal guidelines exist for argument type identification」——论证挖掘领域对型式识别难点的评述（经前一轮外部校准引入，原句保留）
- SEP, *Informal Logic* —— 型式法作为谬误法的替代

**B 档（据教材转述）**
- Walton, Reed & Macagno 2008 的型式库规模（60 主 + 44 子）与「暂定假设」自评
- Massey 的不对称论题（p663–664 转述）
- CQ 聚合规则的缺失（p562 附近）

**C 档（我的设计判断）**
- 「默认条件」这一理解——三种理解里我选它，理由是规范力量与可判定性的平衡；这是一个哲学选择，可以被质疑
- 「不聚合」——拒绝制造不存在的精确度
- 「PTA 全空即失效」——宁可不用，不给中性结论
