# 理论支撑 · 读法

> 前面两份文档（`理论底稿.md`、`外部文献校准.md`）解决的是「规则是什么」和「规则准不准」。
> 这一套解决的是第三个问题：**这些规则凭什么有约束力，以及它们各自被谁反对。**
>
> 三者的分工：
> - 理论底稿 → 操作规则（R1–R11）与八步流程
> - 外部文献校准 → 一手来源对照、机器能力的实证上限
> - 理论支撑（本目录）→ 每条规则的根据、围绕它的争论、以及它在代码里落到哪个字段
>
> **本目录是散文。** 拆到「一条主张」颗粒度的可引用版本在 `src/shared/theory-base.ts`（40 条，界面顶栏「参考」里的「理论」可查），
> 它的标档与取舍写在 `docs/理论主张库.md`。两者是同一份东西的两种形态：这里讲道理，那里能指认。

---

## 一、为什么还要写这一套

因为原来的文档有一个致命的使用场景没覆盖：**用户追问「你凭什么」**。

底稿的写法是「R3：三标准不对称，顺序不可平列｜p602」。这在内部够用——它约束了软件行为，也标了出处。但它回答不了下面这类问题：

- 「为什么相干性是致命的，可接受性不是？」
- 「你说这条前提不可接受，可接受的标准是你定的吗？」
- 「凭什么你说我漏了隐含前提，而不是你替我补了一个我没有的意思？」
- 「学术上不是还有人说谬误根本不存在吗？」

答「书里写的」是把权威当理由。而这个软件的全部立场，恰恰是反对把权威当理由——它连专家意见都要追问六条 CQ。所以它自己不能靠「某某说的」站住。

**这一套文档的做法是：把每一条规则背后的分歧摊开，包括那些没能被解决的分歧。** 一个承认自己站在争议某一侧的工具，比一个假装没有争议的工具可信。

## 二、三档可信度，全文强制标注

每一处断言都要能归到下面三档之一。混着写就是学术不诚实。

| 档 | 含义 | 写法 | 例 |
|---|---|---|---|
| **A · 一手** | 我能指到具体文献的具体位置，且表述与原意相符 | 直接写「某书某页说」并给出可查的版本信息 | 「Fricker 把证言不正义定义为 *identity-prejudicial credibility deficit*（2007, p.28）」 |
| **B · 转述** | 我依据的是教材、综述、二手的整理，没有核对原书 | 必须写明「据某教材转述」，不许伪装成一手 | 「据武宏志《非形式逻辑导论》整理，Walton 的型式库为 60 主型式 + 44 子型式」 |
| **C · 我的判断** | 这是我的设计取舍，可以被推翻 | 显式写「这是设计判断」，并说明推翻它会付出什么代价 | 「把未回答单独列为一档，是我的判断：它比硬答 yes/no 诚实」 |

**一条硬规矩**：C 档不许伪装成 A 档。文档里凡是出现「研究表明」「学界公认」却没有具体出处的，一律降级为 C，或者删掉。

这条规矩在软件里的对应物是 `tag` 字段（known / computed / inferred / general / framework / guess）。文档的标注纪律与产品的标注纪律必须是同一套——否则文档会变成产品做不到的承诺。

## 三、每一编的统一格式

```
核心问题        这一编要回答哪一个「凭什么」
互相对立的立场   至少两种，且都是有人真正主张过的
本软件的站位     站哪边、为什么、代价是什么
强制后果        落到哪个字段、哪条守卫、哪个界面元素
出处            分档列出
```

「互相对立的立场」这一栏不许省。省了它，文档就退化成教条；而教条一旦遇到反例就会整块崩塌，因为它没有承重结构。

第八至十编有个共同点：多数主张落到的是**不做的事**。读的时候不要按「新增了什么功能」去找，
要按「拦住了什么」去找——报告末尾那栏「这份分析自身的边界」是它们最集中的落点。

## 五、这套文档不做什么

- **不做文献综述。** 只写能改变软件行为的部分。写不进代码的理论，哪怕再重要，也只在这里留一句「知道但没用上」，并说明为什么。
- **不追求立场中立。** 每一编都有「本软件的站位」。中立是假的：选了 RSA 就已经站在 Johnson & Blair 那边，不承认这一点才是不诚实。
- **不假装争议已解决。** 学界没解决的问题，文档里必须仍然是问题。软件把这个未解决状态显式呈现给用户（`diagnostics`、`alternativeReading`、`unknowns`），文档不能比软件更自信。
