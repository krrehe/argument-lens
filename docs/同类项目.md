# 同类项目：四类、三家最近的、以及它们都没做的事

> 检索于 **2026-11-02**。只读公开页面——README、产品帮助文档、论文摘要、学校新闻页。
> **没有安装试用任何一个。** 所以这里能回答「有没有、长什么样、机制是什么」，
> 不能回答「好不好用、准不准」。
>
> 搜索能证明存在，不能证明唯一。下文每处「没见到」都应读作「本轮检索没见到」。

---

## 一、先说结论

1. **同类分四层，各管一段，没有一家把四段接起来。**
   论证挖掘（学术，管抽取）、论证图谱（人自己画，管结构）、谬误/操纵检测（管贴名字）、
   对抗式推理（管施压）。本项目横跨四层，但每一层单独看都有成熟先例——
   **「新颖」不是卖点，「怎么接」才是。**

2. **最接近的组合是三家的拼盘**：Skeptik 的谨慎措辞（「这可能是……」而不是「这是」）、
   Steelman 的对抗轮次与可证伪条件、Argdown 的「文本即源、图是渲染」。
   三家各占一角，没人同时做第四角——**保留「此处合法」**。

3. **行业默认是给结论。** 我读到的检测类产品里，给总分或给标签是常态
   （Criticaide 的 Overall credibility score、LogicShield 的论证强度评分、ARGUS 的贝叶斯置信度），
   不给的是少数。所以「不给单一判定」不是技术做不到，是**立场**——
   代价是用户会期待一个分数，界面必须解释为什么没有。

4. **两条外部实证，一条支持我们，一条警告我们。**
   ArgBench（ACL 2026 Findings）发现「论证质量评估」是 LLM 五项技能里最难的一项，
   跨任务泛化也最差——这支持「判定不要交给模型」。
   而 adversaria 的项目说明引 Nemeth 的研究：**被指派的**魔鬼代言人效果弱于真实异议，
   甚至可能让人更坚持原立场——这直接警告我们的红队模式。

## 二、四类同类

| 类 | 代表 | 核心机制 | 与本项目的关系 |
|---|---|---|---|
| 谬误 / 操纵检测 | Skeptik、Criticaide、sophistry-skills、得到「拷问」、LogicShield、各类 fallacy finder | 逐句扫描，命中就给名字；多数给整体分或严重度 | **同向**：都承认「一段话里有几处接不上」值得指出；**反向**：多数以名字为主输出、以分数收尾 |
| 对抗式推理 / 红队 | Steelman、adversaria、Advocatus Diaboli、ARGUS、Hegelion、Socratic Council | 主张分解 → 多轮对抗 → 汇总成决策记录 | **同向**：轮次与「可证伪条件」值得借；**反向**：多 agent 辩论最终收敛成一个答案，把分歧当噪声 |
| 论证图谱 | Kialo、DebateGraph、Argdown、Rationale/bCisive、MindMup、papergraph | 人把主张与支持/攻击关系画出来，工具只承载结构 | **互补**：它们不判断，只让结构可读；Argdown 的「源文本可 diff」与我们的「提示词指纹 + 报告重放」是同一种工程直觉 |
| 学术基础设施 | oAMF / AIFdb / xAIF、MAMKit、CQoT、ArgBench、CoCoLoFa / MAFALDA | 统一格式、模块化流水线、数据集与基准 | **上游**：抽取与评测的公共地基；其中 CQoT 与我们同源（图尔敏 + 批判性问题），但方向相反 |

### 各类一句补充

- **检测类**的成熟度差距很大。学术侧的 Skeptik 明确用「这可能是 X」的措辞、分三层给解释；
  而网页版的 fallacy finder 多是关键词命中（客户端跑、不发服务器），本质是名录法的最低配。
  中文开源里有 `sophistry-skills`：诡辩手法知识库 + 命令行检测器 + JSON 输出，路线是模式匹配。
- **对抗类**几乎全靠提示词与外壳。它们的共同假设是「让模型扮演反方，就能逼出盲点」；
  我们的假设是「把判定搬出模型，才谈得上可复算」。这条分歧比功能差异更根本。
- **图谱类**不判断、也不抽取，所以从来不需要回答「名字该怎么给」。
  Argdown 值得单独看：论证写在 Markdown 式源文件里，图由源文件渲染——
  改了论证，diff 在文本上，不在图上。
- **学术类**里 CQoT（arXiv 2412.15177）最值得读：它把图尔敏六要素拆成 8 条批判性问题，
  让模型自检，8 问里过 7 问才放行，MT-Bench 上比 CoT 平均高约 5 个百分点。
  同源，但方向相反——**它用 CQ 改自己的推理，我们用 CQ 审别人给的论证**。

## 三、值得看的三家

### 1. Skeptik（亚利桑那州立大学，浏览器扩展，原型）

读自 ASU 官方新闻页与论文摘要。做法：LLM + 轻量启发式，在新闻原文里标出 9 类谬误，
点击展开三层解释——**澄清、证据与反证、预防性语境**（下次遇到同类怎么认出来）。

值得看的是它的克制：项目负责人原话是「目标不是告诉人该想什么」，
标注措辞是「This may be an example of…」，并且论文自己承认检测结果没有与专家标注对照过。
一个被媒体写成「AI 抓谬误」的项目，内部的说法比外部标题保守得多。

**差距**：我们只有两层（命名卡里的「什么时候其实合法」「最可能错在哪」），
没有第三层「下次怎么认出来」。这条差得不小，但**现在不做**——
路线图说这个项目缺的是证据，不是功能。

### 2. Steelman（HN 上的个人项目，Next.js + Claude）

读自作者自述（转载页，二手）。做法：把立场拆成**经验主张**与**价值判断**两类，
三轮升级的对手逐轮施压，用户每轮辩护，最后产出 Decision Record：
哪些主张活下来、哪些没有、以及**在什么条件下你会改主意**。
设计约束是「AI 从不替你写」，最后那份记录里每个字都是用户自己的。

**能借的**：「可证伪条件」是一个字段，不是一句修辞。
我们的红队模式有反驳与档位，但没有把「什么证据能让我撤回这条判断」变成必填项。
值不值得加，取决于它是否只改界面——**若牵动提示词，就要走完整套版本流程，成本另算**。

### 3. Argdown（开源，Markdown 式论证语法）

论证写成文本，图是渲染结果。这条对工程有直接含义：
**图的正确性可以由源文本重放来验证**，而不靠人对图。

我们已有 `npm run replay`：同一份模型原文重跑当前代码，逐字段比对。

**这一条我核过了**（同日）：`StructureMap` 只收 `Diagnosis` 数据与选中态，布局在 `useMemo` 里算，
不从磁盘或网络取数；`check:lens` 用 `react-dom/server` 把它渲染成字符串再数图元。
所以「图由数据决定」成立，不靠人看图。

缺口在另一处：`check:replay` 比的是**字段**，不比渲染结果。
「同一份报告重放后，图是否逐字节一致」目前没有断言。
要补得先红后绿，还要接受 SVG 坐标里的浮点抖动——**留作候选，不在此刻动手**。

## 四、值得防的三家

### 1. Criticaide（Electron + 本地 llama.cpp + Phi-3.5，MIT）

形态离我们最近：Windows/macOS 桌面、本地模型、隐私优先、多 agent
（筛选 → 调度 → 五个专科 agent：认知偏差/情绪操纵/逻辑谬误/来源可信度/技术准确性 → 汇总）。
立场离我们最远：输出里第一项是 **Overall credibility score**。

它是「我们决定不做的那一面」最完整的样本：同一段文本、同一套 agent、同一个价位，
最后压成一个数字。这个数字有用——它好比较、好排序、好进报表。
代价是它把「哪里接不上」和「整体可信不可信」混成了一件事。

### 2. 多 agent 辩论框架（ARGUS / Hegelion / Socratic Council）

这一类把「多个模型吵一架」产品化：正方立论、反方反驳、裁判聚合，
贝叶斯校准出置信度，或直接 Synthesis 成一个答案。
ARGUS 是 MIT、27 家供应商；Socratic Council 是 16 个席位、Apache-2.0；Hegelion 是正-反-合三段。

它们的共同动作是**消解分歧**。我们六副透镜的规矩正相反：分歧本身是输出，
压成一个总分等于宣称六套理论可以通约。这不是「我们更好」，是**目标不同**——
它们要一个更可信的答案，我们要一张能自己判断的图。

### 3. adversaria（Claude 插件，三个 agent + argument graph + verdict）

Advocate 立最强辩护、Adversary 找漏洞、Judge 读前两者的图给出**裁决**。
工程上比我们轻（全靠提示词与图），但结构清楚。

最该读的不是它的结构，是它引的一条研究：Nemeth 的结论是
**被指派的**魔鬼代言人不如真实异议有效，还可能让人更坚持原立场
（转引自该项目说明，我未核 Nemeth 原文）。

我们的红队模式就是「指派」的对抗，而且是 AI 扮演、用户知道它在扮演。
这个风险是真实的。**能做的不是取消角色，而是给每条反对意见标上「这是被指派的反方」，
并让它自带撤回条件**——把「指派」的弱点换成「可检验」。

## 五、能落到我们身上的事

**这份文档只回答「外面有什么」。** 哪些能吸、哪些撞五条不可动摇、逐件核过之后的结论，
都在 `docs/融合清单.md`；当前进度在 `docs/路线图.md` 末尾的阶段状态。

11-02 初版这里列过一张「四条能落到我们身上的事」待办表，11-04 收走了：
表里标「做」的「为什么不给分数写到界面上」其实早就在首屏空态（`App.tsx`），
标「先查字段是否已存在」的 `withdrawIf` 三处都有，而表本身没跟上这些事实。
一份会自己过期的待办表，比没有待办表更误导人——路线图附则要求进度只写在一份文档里。

一条留给将来评测的外部实证：CoCoLoFa（EMNLP 2024，7706 条新闻评论、8 类谬误）上，
微调的 BERT 检测 F1 0.86、分类 0.87，**高于当时的 SOTA 大模型**。
意思是「专用小模型 + 高质量标注」在分类任务上仍可能赢过大模型——
将来若要扩 `eval`，公开数据集是现成的外部对照。但那些都是英文语料，
中文这一格仍然是空的；**我们一次都没在它上面跑过**。

## 六、这次检索的边界

- **未安装、未试用任何一项**，包括得到「拷问」。所有机制描述来自 README、帮助文档或论文摘要。
- **榜单站不可信。** 搜索结果里「2026 最佳论证软件」这类页面（sigmadax、statpit、wifitalents、worldmetrics）
  是批量生成的 SEO 内容，彼此高度雷同，**没有作为任何事实的依据**。产品名与定位只取厂商页面或论文。
- **二手来源已标出**：Steelman、adversaria、Advocatus Diaboli、ARGUS、Socratic Council、Hegelion、
  papergraph、LogicShield、sophistry-skills 均读自转载页；oAMF 读自 README 转载。
  一手的只有 Criticaide、logikon（GitHub 原页）、Skeptik（ASU 官方页）、CQoT、ArgBench、CoCoLoFa（论文摘要/著录）。
- **ArgBench 的中文二手摘要里有具体百分比**（如「83% 选中间档」）。我只核到论文原文的结论层面
  （质量评估最难、泛化有限、基座模型不超过 32B），没核到那几个数字，所以正文不写它们。
  要引数字，先读 arXiv 2604.17366 原表。
- **「没有同类同时做四件事」是检索结论，不是事实结论。**

## 七、这些项目里，什么能吸、什么不能

逐项到许可证与代价的清单在 `docs/融合清单.md`。

一句话：**能合法吸的（MIT / Apache）恰好是我们不需要的那部分**——评分、聚合、裁决；
我们缺的那部分（判定口径、中文语料、真实使用证据）不在别人的代码里。
落地的是入口与格式层面的两件（Argdown 导出、全局快捷键读剪贴板）
和「拿对方的官方解析器当裁判」这个验证方法；**判定与提示词一件没动**。
逐件结论、撞了什么、卡在什么条件，见 `docs/融合清单.md`；进度见路线图阶段状态。
