# 路线图

这份文档回答一个问题：**接下来该做什么，不该做什么。**

它不列功能，因为功能不缺。它按「消灭哪个未知」排序，而不是按「哪个功能大」排序——一个长期项目的死法，通常不是功能不够，是力气花在了已经知道答案的地方。

---

## 一、现在的处境

三组数字能说清：

| 事实 | 数字 |
|---|---|
| 代码规模 | `src/` 下 73 个 TS/TSX 文件、23,881 行 |
| 断言规模 | 静态两千余条，另有端到端的基础 / 进行中 / 按停 / 示例四组，以及各 `SMOKE_*` 开关带来的成组断言。**这里不列分项条数**：每加一块代码就加一块守它的断言，分项数字每轮都在变，而没有任何断言守着这张表——按 `AGENTS.md` 第五条的规矩，实时数以 `npm run verify` 与冒烟输出为准 |
| 真实用户数 | **1**（102 份报告、**6 组不同文本**，其中 **99 份是同一段「取消早读」的四个版本**——89 份逐字相同、8 份加了两句、1 份删到只剩开头、1 份改写成提纲；14 份带模型原文） |

**工程质量远超产品验证。** 这不是自谦，是一个具体的不平衡：两千条断言证明的是「界面上该出现的东西出现了」，而「判断对不对」只有 40 条语料、一家模型、六分钟、十七万 token 的评测在管。而那 40 条里，最近两批（17 段）一次都没跑过模型。

那份评测进不了每次改动，因为它要花钱（现在余额为空）、要六分钟。**但「改动之后报告变了，是谁变的」这个问题已经答得了**：P0-1 让每份报告存下模型原文，P0-2 的 `check:replay` 拿它离线重跑解析与十一道裁决，0.8 秒、不联网。所以现在分得开两件事——代码改坏的（重放会红），和模型换了说法的（重放不动，只有 `eval` 看得见）。

剩下的不平衡在产品那一侧，而且不在工程量上。2026-11-03 重新数了一遍存档，比原来那句「89 份是同一段」更准确：**102 份报告落在 6 组文本上，其中 99 份是同一段「取消早读」的四个版本**（89 份逐字相同、8 份加了两句、1 份删到只剩开头、1 份改写成提纲）。**同一个样本跑一百遍，得到的是一百份报告，不是一个样本的一百次验证。**

这也是做了两件事的原因：示例从一段改成六段——按钮本身在教人反复试同一段；输入框下面加一行「这段跑过没有」——同一段文字再跑时，把「已经跑过 89 次」摆在按下去之前。两件都回应同一个判断：**这个软件此前从不告诉人「你其实只试了一种文本」。**

2026-11-04 补了第三件：按钮下面再摆一行「样本账」，把「本机一共几份报告、落在几组不同的文字上」这个**全局**事实直接说出来。前两件只在你正贴着某一段时提醒重复，第三件不需要你贴任何字；它也是报告之外唯一一处文字全部来自本地存档的显示——裸提示词无从知道的东西，正是本地工具该拿出来的东西。它仍然只数事实，不劝、不评价、不打分。

2026-11-05 补了第四件，方向与前几件相反：报告末尾多了一个空框，记「读完这份报告，你下一句想说什么」。字由人写，软件只保管原话、只数「逐字相同」的次数，不分析这句话、不分类、不给选项。它存在的唯一理由是：第四节那条判据写了很久，一直零输入——不是没人想说，是**软件里从来没有一处地方收这句话**。补上通道不等于有答案：现在本机还是零条，一个人写的话也不构成样本。

2026-11-05 又落了一件往数据方向走的：输入框下多了一行「同题复跑」，把**同一版提示词、同一段逐字原文、同一个模式**的多份报告摆到一起，逐字段数「几次一样、几处变过」。它给出了这个项目第一条量出来的稳定性证据——本机那组跑了 15 遍的同一段字，245 个字段每次都一样；「感觉像随机提示词」那个印象，第一次有了一个可以对着看的数字。它也顺手暴露了一处解释不了的差异（v2.0.0 的一组 8 份里 279 个字段不同），而存档没记模型名与温度，所以那一栏只陈列、不解释，并把这句话写在界面上。这些数字来自本机存档，换一台机器、多跑几遍都会变——实时数以那一栏自己显示的为准。

2026-11-05 再补一件，把上一件留下的洞补上一半：新报告开始记下**跑它的模型、供应商主机与生效温度**。上一件跑出真数据时，v2.0.0 有一组 8 份报告相差 279 个字段，而那批存档里没有模型名也没有温度——差异被看见了，却永远说不清是「模型在抖」还是「我换了模型」。现在这一栏落在报告里，同题复跑会把「这一组里换过模型」直接点名，报告脚注也写「由哪个模型、什么温度跑出来」。旧存档没有这一栏，界面写「没记模型」而不回填：补出来的模型名会让一份跑在旧模型上的报告自称跑在新模型上。记了也不等于知道全部——同一个模型名背后是不是同一版权重，存档不知道。本机现存的报告全是旧档，所以这一栏眼下在真数据上是空的：它改变的是**下一份报告能不能被解释**，不是这一份。

2026-11-05 又往前一件：报告里的图不再「一律全画、位置固定」，开头多了一条**挑图**——五张图列在一起，勾上就显示、勾掉就收起来。这一件补的是「更多可视化」缺的那一半：原来只有结构图、逐关检查、判读刻度三张，且不能关。新增两张都是数据里早就有、却只以文字出现的关系：**反驳落点**（每条反驳打在哪一处依据上，实心表示挂到了具体关卡、空心表示只打到那一处）与**修补对照**（左边是现在的链断在哪一步，右边是补上缺的那一句之后接不接得上）。三条规矩让「没画」与「画不出」分得开：画不出的照样列出来并写明原因；关掉的那张留一行占位加就地打开（因为目录里的入口还指着它）；全关也行，写「图 0/N，文字照常」，不替用户恢复默认。选择存本机，只影响显示，不改报告内容、存档与导出。透镜产物图不归这条选择条管——它跟着透镜走，是那一栏的主体。

2026-11-04 又拿到一条真实使用证据，却是定性的、否定的：**用的人没感觉到它和「喂给 AI 一段提示词」有差别**。对照下面「什么情况下该掉头」里那条「多数人的下一句是『所以呢』」，这可能是它的早期版本。这一轮的「回到原文重读」是最小一步：不动提示词、不花钱，把「本地那层有没有产生可观察的差异」变成一个用户能发起的操作。它有没有用，得由人判断，脚本验不了。

想把这件事做成并排盲看（模型原文 vs 本软件），**现在数据不够**：103 份存档里只有 15 份存了模型原文 `raw.text`，落在 **2 组文本**上，其中 14 份是同一段「取消早读」。拿它做对照等于把 14 份重复当成 14 个样本——正是这份文档一直在防的错。所以接着做了几件不依赖真模型、能立刻由人发起的操作（见末尾阶段状态）；盲看的解锁条件写在 README「已知限制」。

2026-11-09 把「像 AI 加提示词」这条主线结案一次。四轮量化（均为本机存档实测，换一台机器会变，**实时数跑 `npm run audit:provenance`**；它两种口径都量、不进 `verify`，因为依赖你自己的存档）都指向同一个结论：

| 轮次 | 量到的事实 |

| 45 | 15 份带模型原文的报告里，1290 个 ≥12 字字段有 1262 个（**97.8%**）逐字来自模型原文；只数判定正文 11 个区块的更严口径是 1080 / 1108 = **97.5%**，两种口径结论一致；裁决留痕 9 份全是格式类，**没有一条改写判断** |

| 48 | 407 条主张里 406 条 `text` 与 `quote` 不同、308 条能读出连续字面改动；而结构一致性（span 403/407、悬空 id 全 0）几乎零命中——**再做一块结构面板就是空面板** |
| 49 | 架构拆分、边界断言，是工程债；产品主线一点没动 |

**结论：这条主线没有被解决，而且「再往报告外加一块本地计算」这条路已被真实数据证伪。** 本地能独立复算的只有结构与字面；评级、可接受度、举证责任、检查项答案仍全部来自模型。而这台机器上没有 Key、没有本地模型、余额为空，真模型评测（P1-2）跑不了；103 份存档落在 5 组文本上（98 份同一段早读），「下一句」零条，P2 也没有输入。交接书「三十秒版」原写「判定全在本地十一道裁决」，与上面四行冲突——它让每个新会话都以为判定已经在本地，于是反复往「本地再加一点计算」上使劲；现已按实测改口，README「接入模型」那句「镜片不变」也补上边界。

所以下一步不该由代码决定，只有三道闸：**① 余额到位跑跨模型评测**，用真数据回答「判定到底来自谁」，再决定动不动提示词；**② 你给十段自己的真话并在报告末尾留一句**，让 P2 判形态该不该掉头；**③ 承认它是「带本地复核的提示词工具」**，把承诺收缩到复核，不再宣称判定在本地。前两条要你的钱与时间，第三条要你的判断——都不是再写一块代码能替代的。**2026-11-12：③ 已被用户选中**（审查报告里的路径 B，措辞收为「模型输出可读化 + 回看工具」），主线据此结案；① 与 ② 仍可单独做，但不再是「让软件不像提示词」的解锁条件。见 [产品定位](产品定位.md)。

**但只算了一半。** 报告侧四项（结论文字 / 前提文字 / 只在结论里 / quiet 句）**未计**：这三段只有原文，没有真模型报告；把空报告传进去，纯函数会写「报告结论文字里没有这个词」，那是缺输入不是事实。这一轮把「不说假话」放在了「多算一块」前面。三层区别必须记住：外部公开摘要 ≠ 使用者自己专业里的真文本 ≠ 真实使用证据 ≠ P2 输入；摘要是元陈述、不是论证正文；词表由本次分析挑、不是领域专家给的。所以**本机 103 份存档带学术字面线索仍是 0 份**，人填完词会不会更会读仍零证据，4.8% 没动，「不按学科切换标准」没推翻，示例六段与 40 段评测语料没动、`src/` 一个字没碰、不需重打包。要往判定层走，仍要真模型报告或余额到位的跨模型评测。

- 界面：语境区单开一个渲染，不再走通用 kv 表（否则 `grounding` 会渲染成一坨 JSON）。每格先给徽章再给内容，假定格另起一行显示「换成别的样子」。旧存档没有这一层，照实说「这份存档由提示词 vX 分析，那个版本还没有语境出处」，版本号取报告自己记的那一个，不写死在页面里。顺手把 `persuasion`／`argumentation`／`general` 这些枚举值翻成中文——读不懂 `persuasion` 的人，也就读不懂报告在说什么。

新加 `check:context-source`（56 条）进 `verify`（52→53 项），守的是成因：三档可验、指不出原文一定降级、`guess` 缺 `ifChanged` 留痕、旧存档不补假、规则真进了 30 份提示词。反证十三条逐条真红——**其中两条第一次是假绿**：断言写的是「源码里有 `ctxif` 这个词」，而把三元条件改成 `false` 之后词还在、渲染已死、检查照绿。改成验「它是否仍挂在 `gr.ifChanged` 的判断上」才红。这条与上一轮的教训是同一个：断言查「存在」会骗人，要查「还挂着」。

## 二、P0 · 让验证变便宜（0 元，最优先）

**要消灭的未知：改了代码之后，我怎么知道有没有改坏已有的判断？**

现在答案是「不知道」。P0 把这个问题变成「一条命令，几秒钟」。

### P0-1 保存模型原始输出

`Diagnosis` 加 `raw`：模型返回的原文，连同 `prompt.version` / `prompt.fingerprint` 一起落盘。

- 体积：一份约 8 KB（现在报告 12 KB），可接受
- 隐私：**没有新增暴露面**——`passage` 已经存了原文全文
- 顺带修一处：`prompt` 字段已经填了，但 87 份里只有 59 份有。旧存档不回填是对的（不造假版本），但**界面该在缺失时显示「未知版本」而不是空白**

做完这一条，报告就能自述「我是哪版提示词、由哪段模型原文解析而来」。

### P0-2 离线重放

**状态：已完成（2026-11-02）。** `npm run replay`：读存档里的 `raw`，本地重跑解析 → G1–G11 裁决 → 自检，
与存档逐字段比对，列出差异。不联网、不花钱、0.8 秒。

做出来的比原计划多一样东西：`check:replay` 进了 `verify`。原计划里这条命令要手动跑，
而「要手动跑的东西实际上从不跑」正是 P0 要消灭的那种状态。现在仓库里冻着六份基准
（`scripts/fixtures/replay/`：三份真实报告 + 两份构造的 + 一份假模型的查谬误，见下），每次 `verify` 都重放一遍。

**判据不是「零差异」。** 版本升级本来就该有差异。判据是：**每一处差异都能被解释**——要么是这次有意改的，要么是新发现的 bug。无法解释的差异，就是回归。

那么「解释」这件事怎么落到代码里？拆成三类，只有第一类算回归：

| 类别 | 例子 | 算不算回归 |
|---|---|---|
| 值变了 / 字段没了 | `verdict.level` 被削弱 → 判不了 | **算**，必须能解释 |
| 存档没有、现在有，但**是空值** | `labels[0].quote: null`（这一栏是后加的，旧代码在那处同样没内容） | 不算，但要列出来 |
| 运行时才决定的诊断 | `JSON_REPAIRED` / `TEMPERATURE_CLAMPED` / `PROMPT_OVER_BUDGET` | 不比对，写明为什么 |

第二条的边界必须收紧：只要新增的东西**有内容**（比如代码开始多报一条裁决留痕），就落回第一类。
松一档，就会出现一个很坏的洞——报告明明多了一条警告，检查却绿着。

**两份基准是构造的，得说清楚。** 真实那三份跑出来一条 G 裁决都没触发（模型很乖），
于是 `fx-g3-overrun`（把原文改成「削弱性击败被写成结论为假」）和 `fx-g6-system`
（把一条检查项的 system 改成另一副透镜的）是改原文做出来的。它们锁的是**当前行为**，不是正确行为：
哪天发现 G3 本身判错了，改完要 `--accept` 重新录，而不是让它红着。

**第三份不是构造的，但也不是真的**：查谬误模式那一份来自假模型。加它是因为模式要拉开——
G8 只在「不给档位」的模式里生效，而原先六份里五份都是诊断模式，把 G8 整段删掉也照样全绿。
这件事本身也写成了断言：基准必须同时包含「给档位」和「不给档位」的模式。
删掉一份基准能让检查变绿，是基准类检查的通病，只能用这种结构性断言顶住。

**它能验的边界**：只验「同一段原文下，解析与裁决是否稳定」，验不了模型下次会不会换个说法。
另外手里 101 份存档只有 13 份带 `raw`（该字段 11 月 1 日才加），旧报告的重放覆盖面是零——
这一点命令自己会打印出来，不用记。

### P0-3 一条命令跑完全部

`check:*` 散在 `package.json` 里，靠人记住。一个人维护的项目，**记不住的东西等于不存在**——
断言再多，跑不起来就是零。

`npm run verify`：类型 → 全部 check，一条命令一个退出码；清单从 `package.json` 动态发现，
新增的 check 自动纳入（硬编码的清单会静默漏掉后来加的那些，而它照常打印「全部通过」）。

另有 `npm run check:docs`：交接文档点名的命令与路径必须存在，`verify` 跑的每一关必须先写进 `AGENTS.md`
——**新增一条检查却没写进交接书，下一个会话就不知道它在**，这是文档版的假绿。

### P0-4 失败可见

**要消灭的未知：界面上说「成了」的事，是不是真的成了。**

这一类问题在代码审查里一次找出六处，共同点是**界面上表现为「什么都没发生」**：异议写不进文件、报告存不进历史、配置不合法照样保存、旧报告读不出来。用户点了一下，屏幕没有变化，他只能以为是自己没点中——而这类 bug 最难报，因为当事人说不清发生了什么。

四条规矩：

1. **写失败一律往上抛。** 抽 `src/main/jsonl.ts`（不 import electron，于是检查脚本能在纯 node 里造一个写不进去的路径真跑一遍），IPC 层把异常翻成 `ok:false` + 原因。
2. **失败与结果分开显示。** 报告照给（钱已经花了），但报告顶上多一条「有一件事没做成」；混进错误条里会让用户以为报告是坏的，而报告是好的。
3. **每个空 catch 必须写 `@allow-silent:` 与理由。** 允许静默，不许不留据。`check:robustness` 扫描 `src/main` 与 `src/renderer/src`，抓到没写理由的空 catch 就红。现在 5 处，每处都写明了为什么可以静默。
4. **凭据不回读。** `settings:get` 不再返回解密后的 Key 明文，只回「有没有 / 解不解得开」。为让输入框显示出来而把凭据复制进渲染层，换来的好处顶不上那条通道。

顺带收紧的两处：渲染进程开 `sandbox`（preload 只用 `ipcRenderer` 与 `contextBridge`，关掉沙箱换不来任何东西，只把 node 运行时留在了渲染层一侧）；模型报错回显走 `briefOf`，截到 160 字并抹掉 `sk-` / `Bearer` 片段——有些网关会把请求头原样回显。

### P0-5 每一屏都被人眼看过

**要消灭的未知：界面上那些「只存在一会儿」的状态，到底长什么样。**

P0-4 修的是「失败不可见」，那还可以从代码里读出来。这一条修的是另一类：**只在特定时刻出现的屏，没人见过**。它们不报错、不影响构建，代码读起来也像对的——只有把它拍下来才会发现问题：

- **分析进行中**（30–90 秒）：主区显示的是首屏空态「先给一段真话」，而用户刚刚贴了文本、按了按钮；阶段名算出来却没人显示。
- **按了分析之后的按钮**：文案是整句阶段名，把按钮撑成三行，顺带把「128 字」和「填入示例」各挤成两行。
- **设置页**：这一屏要读 IPC，静态预览页跑不了，于是从来没被截过图。首次启动的引导版正是它。
- **保存被拒**：同一句错误在正文末尾与按钮上方各显示一次，相隔 40 像素。

处置办法不是「以后注意」，是给每一屏留入口：

1. 预览页支持 `?running=<阶段>&wait=<秒>`、`?dlg=settings[&onboard=1][&bad=1]`，`bad` 会自动替人按一次保存，让校验失败那一行进入画面。
2. 端到端加 `MOCK_DELAY_MS` + `SMOKE_RUNNING=1`：把假模型的响应拖住 4 秒，然后断言三件事——面板出现而不是空态、阶段名来自主进程（不是写死的占位）、**「已等」在走**（隔一秒取两次，第二次必须更大）。只截图不断言，等于给坏掉的界面留了张好看的证据。
3. 反向验证两条：停掉计时器 → 「已等」那条红；拿掉面板 → 四条全红。

**2026-11-19 补：长文覆盖账把「只覆盖一小部分」摆到判定旁边。** 起因是一句质疑：「一大堆话只有几句话被分析，你觉得没有问题吗？」
先复算本机 107 份存档里够 800 字的三份：6268 字那份 167 句、**有位置的条目只落在 8 句（5%）**、31 段里 25 段零引文；

结论是**有问题，而且原来的覆盖账还在替模型开脱**：它数的是结论／前提／中间结论／谬误名／合法招这五类带位置的条目，
检查项的 `basis` 是自由文字、不计入——所以「8 句」不是「只分析了 8 句」，但也不是「其余没读」；
而边界说明里那句「没被落上不等于分析漏了」在 4078 字那份上不成立：未落上的第 6、7、10、11 段是完整的类比与因果推理。

判定那格加一句范围（`coverageScopeText`，只在 `partial` 时出现）、速览第③句带「引文 8/167 句」。

②检查项带 span，让 `basis` 里引到的句子也能被覆盖账数到。两条都要真模型跑十段长文才算数，现在做不到。

**同日再补：把「看见了」接到「能动手」。** 范围句只到「知道」为止，读者下一步得自己想起来切分条在输入区、隔着一整份报告。

它只导航，不代跑、不花钱，批跑的调用次数与确认仍在切分条上那一道（判定区不许出现 `runBatch`，断言守着）。
端到端长文跑道新增 5 条断言：按钮真的出现、点前列表本来收起、点后真的展开、滚完停在视口里、跳过去时闪一下。

所以这颗按钮解决的是「知道却没动手」，还解决不了「抽取预算不随长度增长」。

**同日三补：语境从「标了出处」走到「说清它进了哪一步判断」。** 上一轮给七格标了 known／inferred／guess，只回答了「这格是不是原文说的」，
没回答「这格错了会错到哪儿」。而结果页那一栏写着「后面所有判断都锚在这上面」——六副透镜里**只有三副的判定真的读语境**：
walton 读对话类型与阶段，pragma 再读对方立场，ars 读受众与受众类型；图尔明只看骨架、PTA 只看三个结构特征、名录对照只给名字，一格都不读。

**2026-11-21 十四补：让人明白「这个论证为什么有问题」——四句并列换成一条主线。** 用户原话是「记住你是让别人明白为什么这个论证有问题的，必须有主线，修改软件」。回头读首屏：原先是「四句话」——他要你信什么 / 最薄的一处 / 说明到什么程度 / 怎么补。四句都对，但它们是**四件并列的事**，不是一条能复述的推理；读者读完了知道四件事，仍说不出「所以他到底哪儿错了」。而且「最薄的一处」取的是第一个 `violated` 检查项，与「承重」无关——可能只是枝叶，真正让整段垮掉的那一句在「枢纽前提」栏里，排在两万像素以下。所以这一轮不加功能、不动判定，只改**叙述结构**：新增纯函数 `src/shared/spine.ts`，从报告已写下的字段里按一条因果链取五环——**他让你信什么 → 这一步靠哪一条 → 哪一处接不上 → 所以算到什么程度 → 要站住得补什么**，顶端压成两句人话（因果一句 + 出路一句）。五环用一条竖线串着，环号是小圆节点；每环三行：名字、一句人话、从哪一栏读来；右端一格是档位/枢纽/没答。三条硬边界写进函数的开头：① **不新增判断**——断点用与判读栏同一个 `pinOf`（为此把它从 `verdict-trail` 导出，不另写一套顺序），档位走 `LEVEL_LABEL`/`GRADE_LABEL`，否证范围走 `WHAT_REFUTED_LABEL`（此前界面上从没显示过这个字段，第一次显示时果然把 `argument-only` 原值印了出来，截图抓到才改成中文）；② **判了不适用时先说范围**，不去找「最薄的一处」——尺子都不用了，断点是假刻度；③ **空着就说空着**：没补法、没承重路径、模式本来就不给档位，三种情况三句话，不许一句「未发现明显问题」全盖住。位置上把主线提到 `DensityBar` 与导出条之前——先有话说，再有工具条。另加两处让主线成为整页的组织原则：被引用的五栏（结构图/枢纽/逐关/判读/修补）栏头标上对应的环号 1–5，点断点那一环还会把逐关检查里那一关一起选中（只滚过去，人还得在表里再找一遍）。`check:after` 155 → 191 条，守五环顺序、复用 `pinOf`、枚举不上屏、五环落点存在、栏号只挂五处、主线在工具条之前，以及拿冻结基准真跑一遍（191 条里 7 条是行为断言，不只查字面）；9 组反证逐组真红（含「产出四环」「第一环正文清空」「不适用仍指逐关检查」）。**踩到的坑**：新样式表 `styles-spine.css` 只加进了 `main.tsx` 没加进 `mock.tsx`，截图脚本走的是后者，于是「改完截图一模一样」——文件字节数一字不差才发现；这种两处清单不同步不会红，已记在这里。verify 59、基准重放 6 份一致、smoke / dist / pack:check 全绿，首屏重拍 `docs/ui-preview.png`、留档 `docs/screenshots/ui-spine-2026-11-21.png`。**没验的**：主线读起来像不像一条推理、还是又一张五行清单，只能人眼判断；真机长报告上的观感没量过；导出的 Markdown 里没有主线（导出面向改稿，这一轮没动 `report-markdown`）；分支只覆盖了一份冻结基准加两条构造出来的模式/范围变体，真模型在六副透镜上的写法没跑过。判定、档位、提示词、库一个字没动。

**2026-11-21 十五补：层层递进——把「一条线上的五段」改成「三级台阶」。** 用户看完十四补只回一句「层层递进参考认知科学等等」。回看首屏：五环确实用一条竖线串起来了，但**串起来不等于递进**——五环仍然同屏平铺，读者一次要拿住五个带正文的块。认知科学里这是老问题：工作记忆同时只能握住 4±1 个组块（Cowan 2001），超出之后人会退回「扫标题」，而那正是这份报告最想避免的读法。另两条也用上了：模糊痕迹理论（Reyna & Brainerd 1995）说人先抽要旨再处理逐字，且抽到要旨后逐字就不再被记住——所以第一级必须给要旨、细节只能往后；自我解释效应（Chi et al. 1989）说读者在心里替文本回答「为什么」时理解最深——所以每环的标题从陈述句改成**问句**，让他先自答、再对照。第三条是老派的 Toulmin（1958）：claim / warrant-backing / qualifier 正是人在自然语言里追问一个主张时几乎必然走的三步，递进不是我排的版，是读者自己会走的路。落到界面上：五环分成三段——**一 是什么**（1 环）/ **二 为什么**（2 环）/ **三 所以呢**（2 环），段标右端一句提示说清这一级在问什么（「两步：这话压在哪一句上，那一句又站不站得住」），问句链是「他在说一件什么事 → 这话压在哪一句上 → 那一句又凭什么 → 所以只能算到哪一档 → 要站住，还差什么」，每一问都由上一答逼出来。这条「递进」可被机器检验的定义写进了断言：抽掉中间一环，后一问就指空——所以 `check:after` 直接守 `第二问含「哪一句」且第三问含「那一句」`。`spine.ts` 新增 `SpineSegment[]`，与 `rings` 是**同一批对象**（`flatMap` 出来逐个 `===`），各造一份的后果是改文案时必漏一处。**踩到两个坑**：① 竖线原先画在容器 `.spine-list::before` 上，靠 `top/bottom: 22px` 猜端点——它不知道最后一环的正文有几行，于是线的下端插进正文行间，像一根没剪断的线头；整页截图看不出来，裁出序号列放大才看见。改成每环给自己下一环搭一段桥（`.spine-row:not(:last-child)::after`，`top: 32px` 圆底、`bottom: -12px` 接下一环圆顶），最后一环没有下一环，线自然收口，单环的那一级也自动没有线。② 用 heredoc 写反证脚本时 `\\n` 被折成真实换行，整个文件 `SyntaxError`，按行重写那一段才修好——这类转义事故与「写进去的是我以为的字符」是同一个坑，上一轮色值扫描混进退格字符也是它。另修一处排版：提示最初夹在段名与发丝线之间，`flex:1` 的线把提示推到栏最右，读者要横跨半屏才能把「为什么」和「两步：…」连起来——改成「段名 · 提示 ——线」，两句本来是一句话的两半。`check:after` 191 → 203 条（新增三段顺序、每级 ≤2 环、三段正好装五环、同一批对象、提示非空且互不相同、五个标题都是问句、指代链、界面真按 `segments` 渲染、每段只渲染自己的环），反证 9 → 15 组逐组真红（含「四段」「一级三环」「另造对象」「标题改回陈述句」「提示清空」「界面撤掉分段」）。verify 59、check:docs 92、基准重放 6 份一致、smoke / dist / pack:check 全绿；首屏留档 `docs/screenshots/ui-spine-steps-2026-11-21.png`。**没验的**：「层层递进」读起来是不是真被感知、还是只变成三段并列的清单，只能人眼看；三级之间的视觉重量差（段标一律 14px 半粗）是否够，没做眼动或计时；真机长报告滚动时的节奏没量过；分支仍只覆盖一份冻结基准加两条构造变体。判定、档位、提示词、库一个字没动。

## 三、P1 · 语义质量的最小证据（小额，我做）

**要消灭的未知：报告的内容到底准不准。**

### P1-1 语料扩到「每个陷阱至少三条独立文本」

现在 40 段、18 类毛病，**每一类至少三段、体裁互不相同、至少被两种分析模式考过**，五种模式都必须有语料（`check:corpus` 守着）。不追求 100 条——**数量不是问题，覆盖的独立性才是**。同一段文本跑 82 遍得出的是 82 份报告，不是 82 个样本。

判据：一条陷阱只有一个样本时，无法区分「软件抓到了」和「这段文本太典型」；两段时可以区分一半，但区分不了「换个问法还抓得到吗」——所以门槛从两段涨到三段，并把「模式」单列出来。这一条是 2026-11-05 涨的，起因是矩阵显示十类只有一种模式，而**查谬误这一档在 28 段里一次都没被考过**。

**门槛涨了，证据没涨。** 三段是形状，不是结论——这 17 段新增语料一次都没跑过模型。

### P1-2 跨模型一致性

同一组语料，用两个模型跑，比对：型式识别、档位、检查项 answer。

这一步同时是两个问题的答案：
- **质量证据**：差异率高的字段，说明软件把它当结论的地方其实不稳定
- **模型换代的对冲**：如果整个价值都随模型浮动，那么「换模型就归零」是真的；如果有相当一部分字段跨模型一致，说明那部分价值来自软件自己（本地规则、静态表、结构约束）而不是模型

差异率超过 30% 的字段，只有两条出路：**用本地规则压住**，或者**在界面上标为「需人工确认」**。不许继续当作确定结论显示。

### P1-3 判定手册 + 一次独立标注

把「什么算型式认对」「什么算过度诊断」写成可复核的条目，找一个人独立标 20 份，算一致性。

**不追求一致性高。** 追求的是**知道它有多低**。如果两个人看同一份报告得出不同结论，那问题不在模型，在报告的表达——这比分析错更严重，因为它意味着报告不可判读。

## 四、P2 · 真实使用（只有你能做）

**要消灭的未知：谁在用它，用完之后做什么。**

10 段你自己的、真实的、没为这个软件准备过的文本。跑完只记录一件事：**看完报告之后的下一句话是什么。**

- 「哦，原来我这里是这个问题」→ 诊断成立，继续加深度
- 「所以呢」/「然后我怎么改」→ 处方层还不够，或者形态不对
- 「它说错了」→ 语义质量还有硬伤，回 P1

这件事我做不了，也不需要花钱。它是整份路线图里信息量最大的一步。

**2026-11-05 起，「记录」这一步不需要另外准备了**：报告末尾有一个空框，写完点「记下」就落进 `userData/nextlines.jsonl`；同一句重复几次会被数出来，原话逐字保留。剩下的仍然只有你能做——拿十段自己的真话去跑，并且愿意在那个框里留一句。

**已经为它做的一件事**（2026-11-01）：报告可以导出成 Markdown——带判定与限定、原文引文、下一步的可勾选清单。理由很直接：如果用户的工作是在 Word 里改稿，那么「回应用看一眼报告」本身就是一个很高的门槛，而 P2 要观察的恰恰是「看完之后做什么」。带不走的报告，连被使用的机会都没有。

但导出本身不是答案，它只是把 P2 的门槛降低了一格。**没有真实文本跑过之前，不要因为它好用就以为它有用。**

## 六、不做清单

长期项目最容易死在不断加东西上。以下几条明确不做，附理由：

| 不做 | 理由 |
|---|---|
| **不加第七副透镜** | 六副是设计决定，不是待办。加一副会让「为什么是这六副」这个已经回答过的问题重新变成问题 |
| **不再给已有代码堆检查断言** | 静态已两千余条。给没动过的代码补断言，不能提升判断质量，只会让**绿色变多、真问题变少被发现**。这一条不是说「新代码不许有断言」：每加一块代码，都要先红后绿地加一块守它的断言（`AGENTS.md` 三条操作规矩的第一条），否则新代码就是无人看守的一段。区别在「保护新增」与「给旧代码刷绿」 |
| **不做云同步 / 账号** | 会毁掉「本地运行、密钥自持、报告不出机器」这个立场。这是它相对在线工具唯一的硬优势 |
| **不扩谬误名录** | 39 条到 40 条不改变任何人的体验。名录的边际收益早已见底 |
| **不做 Web 版 / 移动端** | 同上，除非 P2 证明有人要用 |

## 七、节奏

一次会话做一个**能被断言证明完成**的块。一个块 = 一次提交 + （若碰了源码）一次重打包。

不要按里程碑排，按块排。里程碑会在中途变形，块不会。

## 八、什么情况下该掉头

规划的另一半是承认失败的条件。写在动手之前，才不会被沉没成本绑架：

- **P2 的 10 段文本，多数人的下一句是「所以呢」** → 问题不在分析深度，在形态。该考虑从「出一份报告」改成「陪你改一遍」——那是另一个产品，不是这个产品的下一个版本。
- **P1-2 跨模型差异超过 50%** → 说明报告的结论主要来自模型的临时发挥。该收缩承诺：少说，但说得准；把「确定」的部分与「模型认为」的部分在界面上彻底分开。
- **半年内 P2 无法完成** → 承认它是个人工具。停止 P3，把维护成本降到最低（只修 bug，不加功能），这也是一个体面的结局。
