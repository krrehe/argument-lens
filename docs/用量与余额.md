# 用量与余额：为什么是这样

这一页只回答两个问题：**这次花了多少**、**钱还够跑几次**。所有设计取舍都从这两问出发，凡是答不上这两问的，一律不做。

## 一、不内置价目表

最容易做的版本是内置一张「常见模型价格表」：DeepSeek 多少、GPT-4o 多少。一眼看上去很贴心，实际上是这个功能里唯一会主动害人的地方。

- 价格会变。写死的表三个月后就可能全错，而用户不会去核，他会直接相信。
- 同一家供应商，不同上下文长度、是否缓存命中、是否高峰，单价都可能不同。
- 显示一个错的钱，比显示「还没填单价」糟糕得多——「没有」会让人去问，「错的」会让人当真。

所以：单价让用户自己填，两个数字，填一次。输入框的 placeholder 给「例如 2 / 例如 8」这样的量级提示，但不预填任何具体数值。面板里明写「这里不内置价目表」以及为什么。

同样的理由，不做「预算告警弹窗」。顶栏数字变色就是告警，弹窗拦下来的那次分析，往往正是用户要用的那次。

## 二、估算必须自带标记

OpenAI 兼容接口不保证返回 `usage`。本地 Ollama 老版本不给，不少中转代理也不给。

拿不到 usage 时只有两条路：不记，或者估。不记等于让用户永远不知道花了多少，所以估。但估出来的数必须一路带着标记：

| 位置 | 标记 |
|---|---|
| 记录 | `estimated: true` |
| 明细表 | token 数字右上角一个小「估」 |
| 报告顶部 | 同上 |
| 面板底部 | 「其中 N% 是接口如实返回的，M% 是本地估的」 |

估算系数是经验值：中文约 1.5 字 / token，西文约 4 字符 / token，误差大致 ±25%。够回答「大约几分钱」，不够对账。

**估算和实测绝不混成一个数字。** 一旦混了，用户拿它去对账发现对不上，就会连这里所有的数字一起不信——包括真的那些。

## 三、余额只做锚点，不假装能查

没有统一的余额查询接口。DeepSeek 有 `/user/balance`，OpenAI 没有，各家格式不一，多半还要单独授权。做一堆只对一家管用的适配，不如不做。

所以只存一个**锚点**：某时刻「此刻还剩多少」。之后每次分析从里面扣。

```
剩余 = 锚点金额 − 锚点之后的支出
```

好处是校正成本极低：用户任何时候打开供应商控制台看一眼，填进去就对齐了，**不需要先算清之前花了多少**——那件事本来就是这个应用在替他做。

刻意没做「充值记录」「流水对账」「多账户」。那会让它变成一个记账软件，而用户要的不是记账，是「还能跑几次」。

## 四、「还能跑几次」优先于「还剩多少钱」

三个大数字里，第一个是「还能跑 ≈ N 次」，不是余额。因为「还剩 19.86 元」对大多数人没有意义，「还能跑 900 次」有。

算法：`剩余 ÷ 最近 10 次成功记录的均价`，向下取整。

用最近 10 次而不是全部历史：模型换了、文本长度变了，均价本来就会漂。用全部历史会让「刚换成贵模型」的用户看到一个过于乐观的数字。

锚点或均价缺一个，这个数字就是 `null`，界面显示「还不知道」并说明差什么——**不显示 0**。0 是一个具体的断言，而这里的事实是「未知」。

## 五、记账的存储：追加式 jsonl，按月分文件

```
userData/usage/usage-2026-10.jsonl   一行一条，只追加
userData/usage/meta.json             单价与余额锚点
```

- **为什么不是 SQLite**：数据规模是「一年几千行」，查询只有「按天聚合」。换来的能力用不上，却多一个会损坏、要迁移、要备份的东西。
- **为什么按月分文件**：单文件会无限长，每次读全量、写要重写。分月之后，算今日 / 本月 / 近 14 天只碰最近两个月。
- **为什么只存流水不存净额**：净额写错就无从追溯，流水错了还能一笔笔对。

## 六、单价随记录冻结

每条记录存下当时的 `priceIn` / `priceOut`。改价只影响以后，不翻旧账——否则用户昨天用 A 模型花的钱，今天会因为填了 B 模型的价格而变样。

例外只有一种：当时还没填单价的记录（`priced: false`）。它们按现价补算，面板底部会写明「其中 N 条按现价补算」。这是有意的折中——总比让那几条永远显示 0 元好。

## 七、这份账唯一系统性偏小的地方

失败调用也记一条，但记 0 元：超时、JSON 解析失败这些情况钱大概率已经花了，只是拿不到 usage。**不估一个金额填进去**，因为记账里最忌讳把猜的数字混进真账。

代价是真实支出会略高于显示值。这一条写在面板底部，不藏。

## 八、被否掉的方案

| 方案 | 为什么否 |
|---|---|
| 内置价目表 | 会过期，且用户不会核；错的钱比没有更糟 |
| 自动查余额 | 无统一接口，只能对一家有效 |
| 预算上限 + 拦截 | 拦住的那次正是用户要用的 |
| 每次分析前弹确认框 | 高频操作上的确认框＝训练用户闭眼点「确定」 |
| 把 token 数显示到个位精确值 | 假精确。接口给的就是整数，估算给的是 ±25% |
| 记账做成独立 Tab | 它是背景信息，不是工作流的一步 |
