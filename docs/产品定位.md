# 产品定位（2026-11-12 定）

这份文档记一个**产品决定**，不是一次实现，也不是一份验证结果。

用户从审查报告给的三条路里选了 **B**：论证镜定位为**「模型输出的可读化 + 回看工具」**。

---

## 一、决定

- **判断由模型写出。** 评级、可接受度、举证责任、检查项答案、反驳，都来自那一次调用。深查模式的发现、第二遍反驳与终态同样由模型写出；本地只核对落点、引文、理论依据、状态与 id。软件不声称对「这段论证站不站得住」做独立判定。
- **软件的活是**：把模型那份输出整理成能逐句核对的结构；把每一处对回原文；把越界的地方纠出来并留痕；把报告存下来，能重开、能对照、能逐节读；让读者自己写下不同意见并与报告并列。
- **主线「像 AI 加提示词」按这条决定结案**：不再把「提高本地判定占比」当作解锁条件，也不再往报告外面加一块本地计算，去证明「不只是提示词」。

一句话概括边界：**改的是承诺，不是判定质量。** 这个决定没有让任何一句判断变得更对，也没有让软件比昨天多懂一段论证。它只是停止说一句自己兑现不了的话。

---

## 二、为什么这么定

依据是当场可复算的数字，不是感觉。2026-11-12 跑 `npm run audit:provenance`（本机 104 份存档）的输出：

| 事实 | 当场值 |
|---|---|
| ≥12 字字段逐字来自模型原文 | 1371 / 1399 = **98.0%** |
| 只数判定正文 11 个区块 | 1173 / 1201 = **97.7%** |
| 判定点：模型给出 / 本地实时算出 / 报告自指 | 2022 / 101 / 104 → 本地占 **4.8%**（101/2123） |
| 存档里写下的本地判定 | **0**（骨架缺口是显示时实时算的，不落盘） |
| 带模型原文的存档 | 16 份，98% 那个比例只在这 16 份上算 |

**这些是历史快照，实时数以命令输出为准。** 脚本自己注明：带 `raw.text` 的报告集中在极少数几组文本上，占比不能推广；字面命中不等于判断对；本地那几类只是结构与字面，不回答「站不站得住」。

证据基础同样窄，来自 `论证镜-审查报告-2026-11-12.md` 的存档统计：

- 按原文完全相等分组只有 **8 组**（组大小 89, 8, 2, 1, 1, 1, 1, 1）；项目自带审计用相似度归一化报 **6 组**，两个口径不矛盾。
- 最大组是 **89 份同一段「取消早读」**，判读文字只有 **2 种**，结构组合只有 **3 种**。
- `premises[].burden` 308/308 全为 `proponent`，`refutations[].burdenAfter` 284/284 全为 `proponent`，`context.stage` 101/104 为 `argumentation`——对话维度是被填写的值，不是被推进的状态。

`docs/路线图.md`「一、现在的处境」已经逐轮记下这些结论：第 50 轮「再往报告外加一块本地计算这条路已被真实数据证伪」，第 51 轮「让本地挑判定的错也是一块空面板」，第 52 轮承认三道闸不穷尽。**本决定不推翻任何一条，只是不再把它们当待办。**

## 三、能力边界：能说什么，不能说什么

| 能说 | 不能说 |
|---|---|
| 判断由模型写出；软件把它拆开、对回原文 | 软件判定 / 软件认为 / 判定在本地 |
| 本地做原文定位、字面比对、结构核对、越界纠偏、计数 | 本地独立判定这段论证成立与否 |
| 报告存下来能回看、能对照、能逐节读、能写异议 | 软件替你判断哪一栏更重要、哪一节值得读 |
| 把报告已写下的五处判断按「主张 → 承重 → 断点 → 档位 → 出路」串成一条主线，每环标明从哪一栏读来 | 主线是第六副透镜 / 软件自己判了一遍 |
| 十一道裁决在输出越界时纠偏并留痕 | 十一道裁决兜住了判定质量 |
| 深查发现与反驳由模型写出；本地只核落点、引文、理论依据与状态 | 本地判定某条发现对不对 / 「站住」等于证实 |
| 这些处数是按这份报告逐字复算的 | 算得多等于判断更对 |

措辞只有一个家：`src/shared/provenance.ts` 的 `SOURCE_HEADLINE` / `SOURCE_LABEL` / `SOURCE_NOTE`。界面抬头逐字取自纯函数，`check:provenance` 的 `OLD_CLAIMS` 守着旧宣称不许写回来。新增文案照这个口径写，不要另造一套「更顺口」的说法。

---

## 四、放弃什么，保留什么

**放弃的**

- 把「本地独立产出的判定点占比」当主线指标，继续往上加小数点。
- 用「又加了一块本地计算」来回答「是不是只是 AI 加提示词」。这个问题在 B 之下不再由代码回答。
- 把举证责任、阶段、下一发言人做成可被论辩事件推进的状态（路径 C）。原型 `dialogue-state/` 只验过 reducer 的 18 条断言，没有接进 `src/`，本决定下不接。

**保留的，一个都不撤**

- 十一道裁决、原文定位、逐字比、骨架缺口、结论口气、来源账、长文覆盖账、导出、历史、异议持久化与锚点/跨报告异议地图、报告目录与逐节读、工作台回看、全库检索、检查器字段与枚举的人话化（口径同主程序术语表）、存档只读体检（坏文件与索引对不上的地方可见，但不删不修）。它们本来就不是判定权主张，是**可读化与可复核**。
- `npm run verify` 与全部冒烟跑道。绿灯仍然只说明接线与字面一致，不说明判断对——这一条不因定位改变而放宽。
- **质量证据的可选路径**：真模型评测（P1-2）、十段真实文本与「下一句」（P2）、并排盲看（路径 A）随时可做。但它们现在回答的是「判断对不对、人看完有没有变化」，**不再是「让软件不像提示词」的解锁条件**。A 不再是主线的一部分，只是一次可以单独决定要不要做的评测。
- 路径 C 明确不做，除非用户重新拍板。

---

## 五、这个决定不提供什么

- 不提供「判断对不对」的证据。
- 不提供「比裸提示词强」的证据——那要人把模型原文与本软件并排盲看。
- 不提供真实使用证据。P2 的「下一句」仍是零条，本机存档仍压在同一段早读上。
- 不提供「主线被解决」的说法。B 是**关闭一项承诺**，不是补上一项能力；把它写成「问题解决了」就是下一句谎话。
