# 理论争议：把「学界没谈拢的地方」做进界面

这份文档说明一件事：为什么软件要专门开一栏讲争议，哪些争议被收进来，以及这一层**不能**用来干什么。

数据在 `src/shared/disputes.ts`（11 条，每条两组对立的立场 + 本工具的站位 + 出处）。本文只讲规矩，不复述内容——两处写同一段话，早晚会不一致。

---

## 一、先分清两件事

| | 不确定 | 有争议 |
|---|---|---|
| 是什么 | 我们没把握 | 学科本身没有共识 |
| 谁的毛病 | 工具的 | 理论的 |
| 在哪显示 | 每条依据的置信度（高/中/低/未定） | 独立的「这里有什么争议」一栏 |
| 该怎么用 | 别太当真，去核对 | 知道该攻哪里，或知道可以不同意 |

这两件事混在一起的后果很具体：**「此事有争议」会变成一句万能的免责声明**。任何判错的场合都能说「学界本来就有分歧」，于是这句话失去信息量，用户也就不再区分「它错了」和「它站在少数派那边」。

所以硬规矩是：争议栏不写「可能不准」，只写「谁主张什么、代价是什么、本工具站哪边」。

---

## 二、每条争议固定四件东西

1. **争点**，写成问句。写成陈述句的，多半是替某一派站台。
2. **每一派的主张，与接受它的代价**。只写主张不写代价的，是在替自己那一边说话；本项目里「代价」一栏是必填，不是选填。
3. **本工具站哪一派，以及为什么**。站边要说明理由，不说明就只是偏好。
4. **可核查的出处**。拿不准是谁说的，就写「常见反对」，不编人名年份——这一条和 `theory-notes.ts` 用同一套纪律。

第 2 条是最容易偷懒的地方。举例：「身份特征不能用来打折可信度」这一派，代价是界线必须划得很细——因为「他说错了、他收了钱」而打折是正常评估，不是不义。写下这条代价，读者才知道这一栏不是道德表态。

---

## 三、11 条争议，各自守着哪一处判定

| 争议 | 争的是 | 本工具站 | 落到哪一栏 |
|---|---|---|---|
| 型式判定 | 型式靠内容认，还是非得先有形式判据 | 按内容认，但型式名不进结论 | 逐关检查 |
| 未答的分量 | 某条检查没答上，算不算已经打倒 | 分档：未答只削弱，有据的违反才加档 | 逐关检查 |
| 适用域 | 不想说服谁的话，能不能用十规则判 | 严格限定，不成立就整副透镜退场 | 语境坐标 |
| 受众相对 | 可接受性看受众，是否等于没有客观标准 | 问的是「有没有理由」，受众只是参数 | 语境坐标 |
| 补出来的话 | 没说出口的前提，凭什么算他的 | 必须补，但一律标推定并写出检验句 | 结构图 |
| 能不能切 | 没形式化的口语，能否直接切三特征 | 先重构再切，切不动就写「未定」 | 逐关检查 |
| 够不够 | 多强的证据才算够，谁定 | 看领域，但门槛必须先写出来 | 判读 |
| 反证算不算 | 三关全过但有反证，还算不算好论证 | 要第四关，但不并进三标准 | 击败 |
| 给不给名字 | 同一个毛病有三个名字，给哪个 | 给候选不给判定，三条门槛不全就不显示 | 命名候选 |
| 可信度 | 「他的话要打折」的依据是什么 | 只有具体条件能打折，身份特征写进「此处合法」 | 此处合法 |
| 不下结论 | 拒绝给结论是严谨还是逃避 | 宁可不说，但必须说清折在哪一步 | 判读 |

六副透镜各至少有一条自带的争论（型式法、语用辩证、ARS、PTA、图尔敏、名录法），另外四条是跨透镜的（未答的分量、补出来的话、反证、不下结论）。

---

## 四、什么时候显示：由已定字段推出，不调模型

`disputesIn(diagnosis)` 是纯函数，输入是已经落定的诊断结果，输出是「这一份碰到了哪几条」。**不再调用一次模型**，三个理由：

1. 争议是「这次结论涉及哪些学理分歧」，是一次查表，不是再一次生成；
2. 再调一次就要再花钱，而这一栏的价值不值得一份 token；
3. 更重要的：由模型自己说「我这里可能有争议」，它一定会说得比实际多——那是免责声明，不是信息。

所以触发条件是硬编码的，例如：

- 出现「未答」的检查项 → 未答的分量
- 有隐含前提 → 补出来的话
- 档位是「不成立／被削弱」 → 够不够
- 三标准无违反但记了击败 → 反证算不算
- 命名候选 ≥ 2 → 给不给名字
- 文本里碰到来源、利益、身份 → 可信度

每条触发都带一句**这一份的具体理由**（含具体数字与字段值），不是通用说明。通用说明在展开区里，具体理由在外面——读者先要知道「这跟我有关」，再决定要不要读那一整段。

---

## 五、界面上怎么放

- **报告里**：放在「判读」之后。读者刚拿到结论，最想问的正是「你凭什么」，放在最后一栏等于承认它只是免责声明。默认露三条，其余折起来但写清数目（「还有 4 处（第 4–7 处）」），不能有悄悄藏起来的部分。
- **顶栏「争议」**：完整的 11 条，可切换「这一份碰到的／全部」。没分析时也能看——它是这个工具的世界观，不是某一次输出的附注。
- **板块标题上的「争议 N」**：从结论跳回分歧；争议卡底部的「报告里的『逐关检查』→」跳回结论。两个方向都要通，否则「相辅相成」只是一句话。
- **配色**：站边用蓝灰（`--accent`），不用红绿。红绿是评价，而「哪一派更对」在这里是未知。用红绿等于把未知说成已知。

---

## 六、这一层不能干什么

**它不能替判定免责。** 判定错了，争议栏不会让错变成对。争议只说明「这一步有两种站法」，不说明「这一步怎么站都行」。

**它不是完整性证明。** 11 条不是学界分歧的全部，是「影响本软件判定」的那些。名录法的分类争议、谬误定义的争议，篇幅上远不止这些。

**它不能反过来当中立证据。** 列出两派不等于两派势均力敌。有些争论里少数派确实少数（比如「谬误的分类学仍在争议中」几乎是共识，而「型式识别该不该先形式化」是真分歧）。所以每条都写了出处，不写「研究表明」。

---

## 七、已知问题

1. **触发条件会漏。** 争议是从结论反推的，某些观念上的分歧可能没体现在字段里（例如「举证责任该由谁承担」在语境不清时根本判不出）。漏掉的表现是「这一栏没提它」，而不是提错——宁可漏，不要编。
2. **一句「这一份为什么碰到它」可能不准。** 它由模板拼出，读到具体数字时仍要回原文核对。
3. **条的密度取决于输出。** 一次分析同时触发七八条是常见的（默认只露三条正是为此）。若长期每条都触发，说明触发条件写得太宽，该收紧——判据是「换一段文本，触发的集合会不会变」。
