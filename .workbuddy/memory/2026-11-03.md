## 第 32 轮：全局快捷键（Ctrl+Alt+A）

按上一轮建议做的「Criticaide 那种入口」，但砍掉了一半：**只读剪贴板，不模拟 Ctrl+C 抓选中**。
理由写进了 README 与 3.15：模拟按键会改剪贴板、有粘贴副作用、且没法在无人值守环境里验证。
宁可要一个确定的剪贴板，不要一个不确定的选中。

### 落了什么

- `src/shared/capture.ts`（新）：`decideCapture` 纯函数，三分支——空框直接填 / 示例直接换 /
  用户自己的字只问不换；超长（12000 字）不填**也不截断**；`quiet` 区分「要说话」与「别打扰」。
  `humanizeAccelerator` 把 accelerator 说成人话，三平台可断言。
- `src/main/capture.ts`（新）：`registerCapture` / `deliverClipboard` / `captureStatus`。
  注册失败（键被占）与非法键（抛异常）都转成一句人话存进 status，界面照着说。
  `deliverClipboard(win, read?)` 的 `read` 只为自检注入，**不碰系统剪贴板**（剪贴板里可能是图片，
  readText 读不到、写回空串等于删了它）。
- 界面：输入框下面一行提示按注册结果说真话；候选条（虚线、按钮下一行靠右）；回话条。
- `check:capture` 第 19 关（verify 19 项）；端到端 9 条断言 + 候选条截图。

### 反证

- 静态四次：超长放行 → 3 红；自己的字直接覆盖 → 4 红；精确比较代替 trim 比较 → 5 红；
  提示去掉「没有覆盖」→ 1 红。
- 端到端两次：覆盖分支改坏 → 3 红；超长改截断 → 静态 4 红 + 端到端 1 红。

### 新踩的坑

- **`clipboard.readText()` 在这个 Electron 版本的类型里是 `Promise<string>`，运行时同步。**
  写 `read: () => string` 直接 typecheck 红。改成 `string | Promise<string>` + async。
- **探针读错了元素**：`[data-cap-note]`（回话条）与 `[data-cap-ask]`（候选条）是两条不同的条，
  断言「问话含没有覆盖」却读了 note 的文本 → 空串 → 假红。断言写错和代码写错长得很像。
- **整页截图 ≈ 没拍。** 这应用整页两万像素高，一行提示缩到全页尺寸占不到一像素。
  要用 `capturePage(rect)` 只截 `.composer` 那块。
- **一句话的排版只有看图才发现。** 候选条第一版文字与按钮同行，文字被压到 207px CSS，
  「替换」正好断在中间——读起来像「要用……替换」。改成文字独占一行、按钮下一行靠右。
  这和「8.5px 的汉字认不出」是同一类：**字数算得下不等于词断得对**。
- **check:docs 两次当场抓住我**：AGENTS 没写 `check:capture`、README 还写 18 项。
  这个机制真的在干活，别绕过它。

### 没验什么

- **真按一下那个键没验过。** 自检造不出全局键盘事件，探针直接把「剪贴板里读到这段」投给渲染层，
  跳过按键与 `clipboard.readText()` 那一行。装好包之后要人真按一次才算数。
- 读剪贴板抛错（被别的进程独占）时现象是「按了没反应」，只在文档里写了，界面上没有通道。
- 注册失败那条路跑过了：`SMOKE_CAPTURE_OFF=1`（透传 `AL_CAPTURE_ACCELERATOR=off`），
  日志里 `status:"off"`、hint 是「全局快捷键没启用：这个版本没有启用全局快捷键」。真的走了失败分支。

### 又一坑：`npm run dist | tail -8` 之后必须看产物时间戳

第一次重打 exit=0，但 `dist/*.exe` 的时间戳还是昨天的——**打包静默跳过了**，日志只剩一段
TLS 错误栈（被 tail 截掉前文）。第二次不带管道重跑，产物才真的更新（12:58 / 13:00）。
规矩：**dist 之后核对 `ls -la dist/*.exe` 的时间**，不能只看退出码。

## 第 34 轮：「这段跑过没有」——把样本量摆在花钱那一下旁边

起因是一句一直被当成背景的事实：102 份报告、6 组文本。只读扫了一遍存档，比记忆里更锋利：

| 事实 | 数字 |
|---|---|
| 报告 | 102 份，0 份解析失败 |
| 不同文本 | **6 组** |
| 128 字那段的四个版本 | **99 份**（89 逐字 + 8 加两句 + 1 删到只剩开头 + 1 改写成提纲） |
| 「你行你上」/ 道歉那段 | 2 / 1 |

所以「89 份重复」这个说法低估了：是同一段话的四个版本。软件在这件事上一句话都没说。

做了 `src/shared/sameness.ts`（字面重合：二元组多重集 Dice）+ 主进程 `allPassages()`（读全文，
102 份 19ms，**故意不缓存**）+ `archive:sameness` IPC + 按钮下面一行。

### 阈值是量出来的，不是估的

第一版把「几乎同一段」画在 0.9，然后拿真实存档量：**128 字加两句变 157 字 = 0.897**。
0.9 会把那 8 份判成「不同文本」，界面就会说「跑过 89 次」——比事实更自信。改成 0.85。

但改完立刻发现另一个方向：我造的「加四成内容」的改稿只有 0.802。所以阈值不能一路往下压，
要分两档：加一两句算「跑过」；大改**不**并进次数，但仍然指出来，说成「有 80% 字面重合」。
「你又跑了一遍」和「你在同一段话上改了不少」是两件事，混成一件两个说法都失真。

### 三处反证 + 一处假绿

- 阈值抬到 0.95 → 4 红（诊断信息自证 0.912）
- 并列时取目录第一份 → 2 红，最坏那条是**句子完全通顺、只有日期错成「最近 1000」**
- 归一化时把引号一律删掉 → 1 红
- 短文本守卫：**两侧都破才红**。只破当前那侧仍绿，只破存档那侧仍绿。
  守卫是合取的——这条写进了断言旁边的注释，免得下一个人破了单侧看见绿就以为断言是死的。
  顺带钉住隐患数值：四个字对五个字，光算 Dice 是 **0.857**，正好压过 0.85。

### 排版又是看图才发现的

第一版左边有个「跑过」标签，和句子里的「已经跑过」重复，读成「跑过 这段文字已经跑过 1 次」；
括号里写「（最近 今天 13:20）」，两个时间副词叠着像病句。改成「（最近一次：今天 13:20）」，删标签。
规则：`.same-bar` 用虚线左边框（未发生的事），不用红（重复跑不是错误）。

### 没验什么

- **「它让人少跑了几遍」没验**——那要有第二个使用者。现在只能说「它会说出来」。
- 字面盲区改不掉：同一段话换个说法重写，重合度掉到 0.4 以下，那一行不出现。这是对的，
  但要知道它不会告诉你「这是同一个论点」。

## 第 34 轮：把「每类毛病两段样本」变成一条会红的检查

路线图 P1-1 的判据是「每个陷阱至少两条独立文本」，但语料里根本没有「陷阱类型」字段——
每条 `traps` 都是自由描述，于是这句话无法执行，只能靠人数，而人数出来的东西会腐烂。

### 轴为什么不是理论、不是裁决、不是谬误名

- 理论（walton/copi/…）说的是「用哪套尺子量」，一段文本一种尺子，按它分组天然每条不重复，等于没分。
- 十一道裁决 G1–G11 管的是「模型输出坏了怎么修」，与文本埋了什么无关。**一开始差点选错这根轴**。
- 谬误名是输出，这个项目反对轻易命名；用名字当分类会把「命名」当成「抓到」。
- 定下来按**毛病**分，18 类，从现有 23 段语料的 traps 里归纳，不是先验列清单。

### 第一次跑就红了，红得有用

`check:corpus` 一上线就报出 5 类各只有一段：分子与分母、读法歧义、自相矛盾、
不相关属性、多重比较。补 5 段，每段**换场景**而不只是换词：公共政策→机构质控、
代词指代→条款范围、反例打全称→两个数字互斥、网络评论→评审意见、亚组分析→多指标 A/B。
23 → 28 段。

### 阈值是量的，不是估的

先写探针量出来：同一段加一句 0.926、加一整句因果 0.806、换词换序重写 0.523、
同类独立样本 0.171。0.25 落在改写与独立之间。探针跑完即删。

### 六次反证，各自只红该红处

改体裁 1 红 / 两段换成同一篇 0.880 1 红 / 幽灵 id 1 红 / 标四类 1 红 /
闭集加空类 2 红 / 拼错类型名 2 红。改组后又补了一次（标成空数组 → 1 红）。

### 两处自己抓到的错

- **`verify` 只取脚本输出最后一行**，我原来先打汇总再打矩阵，于是 verify 里显示的是
  矩阵最后一行「多重比较 2 段…」，看不出这关过没过。改成矩阵在前、汇总在后。
- 文档里先写成「11 类刚好两段」，实际算出来是 **9 类**。改成不写数字、只指路
  （「看 check:corpus 的矩阵」）——没有断言守着的数字一定会烂，这次又是一例。

### 没验什么

- **28 段一次都没跑过模型**（余额为空）。所以「软件在新增 5 段上抓不抓得住」是零证据；
  这一轮验的只是「覆盖的形状」。
- 标注「这段埋了那类毛病」是人写的判断，机器验不了。矩阵满格也可能标错。
