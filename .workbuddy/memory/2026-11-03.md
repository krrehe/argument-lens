# 2026-11-03

## 第 32 轮：全局快捷键（Ctrl+Alt+A）

按上一轮建议做的「Criticaide 那种入口」，但砍掉了一半：**只读剪贴板，不模拟 Ctrl+C 抓选中**。
理由写进了 README 与 3.15：模拟按键会改剪贴板、有粘贴副作用、且没法在无人值守环境里验证。
宁可要一个确定的剪贴板，不要一个不确定的选中。

### 落了什么

- `src/shared/capture.ts`（新）：`decideCapture` 纯函数，三分支——空框直接填 / 示例直接换 /
  用户自己的字只问不换；超长（12000 字）不填**也不截断**；`quiet` 区分「要说话」与「别打扰」。
  `humanizeAccelerator` 把 accelerator 说成人话，三平台可断言。
- `src/main/capture.ts`（新）：`registerCapture` / `deliverClipboard` / `captureStatus`。
  注册失败（键被占）与非法键（抛异常）都转成一句人话存进 status，界面照着说。
  `deliverClipboard(win, read?)` 的 `read` 只为自检注入，**不碰系统剪贴板**（剪贴板里可能是图片，
  readText 读不到、写回空串等于删了它）。
- 界面：输入框下面一行提示按注册结果说真话；候选条（虚线、按钮下一行靠右）；回话条。
- `check:capture` 第 19 关（verify 19 项）；端到端 9 条断言 + 候选条截图。

### 反证

- 静态四次：超长放行 → 3 红；自己的字直接覆盖 → 4 红；精确比较代替 trim 比较 → 5 红；
  提示去掉「没有覆盖」→ 1 红。
- 端到端两次：覆盖分支改坏 → 3 红；超长改截断 → 静态 4 红 + 端到端 1 红。

### 新踩的坑

- **`clipboard.readText()` 在这个 Electron 版本的类型里是 `Promise<string>`，运行时同步。**
  写 `read: () => string` 直接 typecheck 红。改成 `string | Promise<string>` + async。
- **探针读错了元素**：`[data-cap-note]`（回话条）与 `[data-cap-ask]`（候选条）是两条不同的条，
  断言「问话含没有覆盖」却读了 note 的文本 → 空串 → 假红。断言写错和代码写错长得很像。
- **整页截图 ≈ 没拍。** 这应用整页两万像素高，一行提示缩到全页尺寸占不到一像素。
  要用 `capturePage(rect)` 只截 `.composer` 那块。
- **一句话的排版只有看图才发现。** 候选条第一版文字与按钮同行，文字被压到 207px CSS，
  「替换」正好断在中间——读起来像「要用……替换」。改成文字独占一行、按钮下一行靠右。
  这和「8.5px 的汉字认不出」是同一类：**字数算得下不等于词断得对**。
- **check:docs 两次当场抓住我**：AGENTS 没写 `check:capture`、README 还写 18 项。
  这个机制真的在干活，别绕过它。

### 没验什么

- **真按一下那个键没验过。** 自检造不出全局键盘事件，探针直接把「剪贴板里读到这段」投给渲染层，
  跳过按键与 `clipboard.readText()` 那一行。装好包之后要人真按一次才算数。
- 读剪贴板抛错（被别的进程独占）时现象是「按了没反应」，只在文档里写了，界面上没有通道。
- 注册失败那条路跑过了：`SMOKE_CAPTURE_OFF=1`（透传 `AL_CAPTURE_ACCELERATOR=off`），
  日志里 `status:"off"`、hint 是「全局快捷键没启用：这个版本没有启用全局快捷键」。真的走了失败分支。

### 又一坑：`npm run dist | tail -8` 之后必须看产物时间戳

第一次重打 exit=0，但 `dist/*.exe` 的时间戳还是昨天的——**打包静默跳过了**，日志只剩一段
TLS 错误栈（被 tail 截掉前文）。第二次不带管道重跑，产物才真的更新（12:58 / 13:00）。
规矩：**dist 之后核对 `ls -la dist/*.exe` 的时间**，不能只看退出码。
