**坑与结论**：
1. prompt:lint 的 `CONSUMED` 手工清单要补 11 个新字段（grade/clause/at/evidence/fix/downgrade/
   d5/consequence/synergy/protocol/removed），否则「schema 里没有代码不读的字段」红。
2. 加字段会让 `check:sideby` 红两处：顶层 `confidence` 要进 `SECTION_ORDER`（新段，紧跟评级），
   `grade` 一组要进 `FIELD_LABEL`。段 id 是联合类型，加段要同步改 `SideSectionId`。
3. `check:replay` 6 份基准全部有差异，差异只有新增 `verdict.grade`／`confidence` 两栏与一条
   GRADE_NOTE；逐条看过才 `npm run replay -- scripts/fixtures/replay --accept`（该命令先打印再写回）。
4. 反证第 7 组第一次**没红**：样本只有「零条反事实记录」与「两条」，把 `< 2` 改成 `< 1` 抓不到——
   补「恰好一条」的样本才咬住。**样本取值档位不够，断言就是恒真的。**
5. 假模型原来不给 grade，端到端走的是「没有 D 档」分支；补一份完整 D2 记录后新增
   `GRADERESULT` 10 条（档位/条款/位置/四栏/缺口为 0/无 D5 闸门/边界句/置信度不折算）。
6. `npm run smoke` 首次跑出现过一次已知 flake：`capturePage` 抛 `UnknownVizError`（视口裁切），
   之后几十条断言一起假红；连跑两次全绿。不是本轮改动引起。
