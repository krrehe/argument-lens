   而库里「明确不做什么」的主张有 13 条。不评动机、不评品格、不评 ethos/pathos、不评制度权力、

   → check:theory 加断言：10 条「不做」类主张必须挂在边界栏里，且边界栏总条数 ≥13。反向验证过。

## 成本体检：为什么「没干什么」却 token 很多

用户质疑 token 消耗。查真实账本（%APPDATA%/argument-lens/usage）：

- 流水 197 条，其中 **115 条是假模型**（冒烟用的 mock-argument-lens，每次编 3200/1800 token），
  真调用 82 条：60.0 万输入 + 25.7 万输出。
- 按 deepseek-chat 现价算，**总共约 ¥1.1**，单次约 ¥0.013。余额跑空是因为余额本来就小，不是烧得快。
- 一次分析 8,457 输入 token，**其中 8,352 是提示词**（walton.diagnose 的 system 15,461 字符），
  用户那段文本只占 1.2%。这是 API 无状态的必然，不是浪费。

### 找到的真浪费：前缀缓存一次没吃到
`makeDelim()` 每次生成 `文本-a3f9k2`，**被替换进 system 的第 1,790 字符处（11.6%）**。
DeepSeek 自动前缀缓存要求前缀逐字节一致 → 之后 88% 的提示词每次按未命中价计费，差 4.6 倍单价。
更糟的是 `prompt:lint` 有条断言**正在确认这件事发生**（「system 使用的是本次分隔符」）——
旧断言是这个 bug 的看门人，没人再去问该不该。

### 改了什么
1. **提示词 2.4.0**：随机串挪到 user 第一行当「守卫：X」，system 里零随机字符。
   `core.input-boundary` 改成说明这个标记怎么读。24 个组合实测 system 逐字节相同。
   安全性不变（随机串还在，只是换位置）。新断言：system 不含本次随机串、两次渲染全等。
2. **账本**：`isMockCall`（回环 + mock 前缀，两条同时成立）→ 不落盘；历史 115 条也不计入统计
   （保留可追溯，不删）；面板明说排除了几条。
3. **价格**：`KNOWN_PRICES` 内置 deepseek-chat(¥1/¥2)、deepseek-reasoner(¥4/¥8)。
   用户填过一律用用户的；不在表里宁可不写。`pricingSource: user|builtin|none` 区分「账」和「估」。
4. **缓存命中率**：`UsageRecord.cacheHitTokens`（兼容 DeepSeek 与 OpenAI 两种字段名），
   面板显示最近若干次的命中比例。**这是唯一能验证缓存修好了没有的数字。**
5. 规则抽到 `src/shared/usage-rules.ts`（纯函数，不依赖 electron），新建 `check:usage` 18 项。
