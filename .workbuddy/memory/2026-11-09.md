### 本轮新踩的坑

- **清零说明写死四项会说假话**：`检查表都答了` 在「全部标为不适用」的样本上是错的

## 第 48 轮（2026-11-09）：逐字比——把改写贴到正文上

用户只说「继续」。上一轮我已写明「继续在报告外面加栏不会改变手感」，所以先量
「报告正文里还有哪些字是本地能独立复算、却一次都没复算过的」（`scripts/.out/text-scan.mjs`
与 `run-rewrite-scan.mjs`，均未进仓库）：

| 事实 | 数字 |
|---|---|
| 主张 | 407 条 |
| `text`（整理后的命题）与 `quote`（原话）不同 | **406 条** |
| 能读出 ≥2 字连续字面改动 | 308 条 |
| 结构一致性（span 逐字命中） | 403/407，4 处全是同一份 `quality: failed` |
| `supports` / `targetId` / `checkId` / `guards` 悬空 | **全 0** |

第二条更重要：**本来想做的「结构一致性」在真实数据上零命中**，做出来又是一块空面板
（第 47 轮 cycle / scope-conflict 的教训）。所以动手点换成 406 次改写——这才是每份报告
都踩得到的、本地能复算的东西。

做法：`@shared/rewrite`（纯函数）用 LCS 切连续差异片段，片段逐字来自两行、只剥首尾标点；
四种「比不出来」（没引文 / 两句全同 / 只差单字 / 超 400 字）各有说法。界面 `ClaimCard`
把这一小块贴在**每张主张卡的原话那行正下方**，不另起一栏；只列字面、不判改写对不对、
不挑「最值得看」的那条。`check:rewrite` 进 verify（34 项）、18 组反证逐组点名
（含三组界面源码守卫、两组端到端/包内接线守卫）、端到端无条件 11 条（`rw` 置空 → 全红）、
`pack:check` 一条、`?rewrite=1` 入口、`docs/screenshots/rewrite.png`。

**必须记住的边界**：这一件**不改判定、不进正文、不落盘**。本地判定点占比仍是 4.8%，
「像 AI 加提示词」这个问题**没有解决**；它改变的是「406 次改写第一次可见」，不是判定权。
交付与 README 都写明了这一句，别在下一轮把它说成「本地接管了正文」。

本轮踩的坑：
- **断言里的期望值别心算字数**：把 14 字写成 16、7 字写成 8，三条断言一起红，看着像实现错了。
- **LCS 片段会带前导标点**（「，应当恢复早读」）→ 剥首尾标点，剥完仍是原话的连续子串，逐字性不破。

  端到端还能点名核数。
