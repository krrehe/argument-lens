# 论证镜 — 项目长期记忆

本机路径 `D:\2026-10-31-09-22-55`。Electron + React + TS 的「论证镜」：把日常语言里的论证拆开，
指出它站在哪、倒在哪、以及**哪一处其实站得住**。用户立场：**长期开发，代码只由 AI 写**，
他本人提供判断、钱、真实使用证据。

## 会话开场必做（三步，约一分钟）

1. 读 `AGENTS.md`——交接书，写「动它之前必须知道什么」（行数不写在这里：它会变，且没有断言守着）。
2. 读 `docs/路线图.md` 的「一、现在的处境」与末尾「阶段状态」（状态只写在那里，别另起进度文档）。
3. `npm run verify` 确认基线绿（23 项，并发后约 7 秒）。基线本来就红，改完说不清是谁弄红的。

## 五条不可动摇

1. 不给单一判定：诊断/红队/重构有档位，查谬误/提问/对照没有。
2. 「此处合法」一栏不能删。
3. 六副透镜不合并、不翻译，分歧本身是输出。
4. 失败必须可见：写盘失败抛到界面，空 catch 写 `@allow-silent:` 理由，断言不许静默跳过。
5. **文档不能比软件更自信**：没验过的别写成验过的；没有断言守着的数字不写。

## 已固化的操作规矩

- 新增断言**先红后绿**（改坏一处必须红），否则就是给假绿添砖。
- 碰了 `src/` 就必须 `npm run dist` 重打包，否则 dist 与源码不符而 exe 照常能跑。`dist`/`dist:dir` 已固化 `-c.electronDist=node_modules/electron/dist`（离线，不连 GitHub）；打完核对 exe 时间戳。
- 只在特定时刻出现的屏，必须留截图入口（预览页 `?running=` / `?dlg=` / `?reread=1`，端到端 `SMOKE_*`）。
- 交付必说三件事：改了什么 / 验了什么 / **没验什么**。

## 反复踩过的坑

- 用视觉模型估版式会错（估「右偏 115px」，像素扫描实测居中）→ **先量 bbox 再判断**。
- **本会话环境预设了 `ELECTRON_RUN_AS_NODE=1`**。`npx electron foo.cjs` 会被当成 node 跑，
  `require('electron')` 只返回一个路径字符串，报错是 `Cannot read properties of undefined (reading 'whenReady')`。
  真要跑 Electron：`unset ELECTRON_RUN_AS_NODE` 后直接调 `./node_modules/electron/dist/electron.exe`。
- **建快捷方式不能用 WScript.Shell**（COM 实例化被本机安全策略挡，报「Command blocked for security」）。
  用 Electron 的 `shell.writeShortcutLink` 写、`shell.readShortcutLink` 回读核对。
- `verify` 现在并发（typecheck 先跑，其余最多 6 路）。怀疑并发搞红了，先 `VERIFY_JOBS=1` 复现串行。
- `build` 与 `smoke` 不能并发（out/ 写一半就起应用）；先 build 再 smoke。
- 多模式冒烟前先 `rm -rf scripts/.out/smoke-userdata`，否则读到上一轮的存档。
- 同时改坏两处会让反证互相抵消（README 项数被多余脚本补齐），**一次只破一处**。
- 8.5px 的汉字不是「小」，是认不出（「回」被读成豆腐块）。
- **「兼容某个格式」不是声明出来的，是对方的解析器读得进去。** Argdown 导出用 `@argdown/core` 当裁判
  （devDependency，不进包）；自己写的转义看着对，解析器一读就炸——`[P1]` 出现在正文里会直接截断。
- **断言要盖住「源」和「目标」两个方向。** 验「合法项不连边」时只写了「它下面挂关系」与「别人指向它」，
  漏了「它指向别人」，于是改坏代码仍绿。
- **另起一份进度文档，预言在 11-04 应验了**：`docs/融合清单.md` 初版写了「下一件做什么 / 没做没验」，
  快捷键上线两天后它仍写着「没有动手」。修法不是把「没做」改成「做了」，是**把状态整体删掉**——
  清单只留判据与结论，进度只归路线图阶段状态管。

## 两条新踩的坑（第 30 轮）

- **`npm run X | tail` 量出来的退出码是 `tail` 的**。要量真实退出码：`set -o pipefail` 或者干脆 `>/dev/null 2>&1; echo $?`。
- **反证要连「断言本身是否恒真」一起验**。写「绕完一圈回到第一段」时，不轮换也会通过——
  它孤零零地绿着，等于没有断言。恒真的断言比没有断言更糟：它让人以为守住了。

## 第 32 轮新踩的坑

- **`clipboard.readText()` 的类型是 `Promise<string>`，运行时同步。** 写 `() => string` 直接 typecheck 红。
- **`npm run dist | tail -8` 之后必须核对 `dist/*.exe` 的时间戳。** 有一次 exit=0 但产物没更新，
  日志只剩被截断的一段 TLS 错误栈——**打包静默跳过，exe 还是旧的**。不看时间就会以为重打了。
- **整页截图 ≈ 没拍。** 这个应用整页两万像素高，一行提示缩到全页尺寸占不到一像素；
  要判排版得用 `capturePage(rect)` 只截 `.composer` 那一块。
- **字数算得下不等于词断得对。** 候选条文字与按钮同行时被压到 207px，「替换」断在中间，
  读起来像「要用……替换」。只有看图才发现——和「8.5px 的汉字认不出」同一类。

## 第 36 轮新踩的坑

- **`npm run dist` 会连 GitHub 下 Electron 发行包**：2026-11-04 `connect ETIMEDOUT 20.205.243.166:443`，
  真退出 1、exe 还是前一天的；缓存里明明有 `electron-v45.2.1-win32-x64.zip`，它照样去连。
  解法：`electron-builder ... -c.electronDist=node_modules/electron/dist`（本机已解压目录，完全离线），
  已固化进 `dist` 与 `dist:dir`。打包成功也仍要核对时间戳。
- **端到端断言最容易写成三类恒真**：「入口点得开」只验按钮存在（按钮没反应照样绿）、
  「点回报告后报告回来了」在根本没离开时恒真、「这一屏有截图」只要窗口还在就绿。
  这一轮第一次反证 6 红 3 绿，那 3 条全是假的。修法：把「之前确实在那一屏」
  「截图裁到了那一屏的 rect」写进同一个条件。**反证要逐条点名核对，只看整体红不够。**

## 第 37 轮新踩的坑

- **断言写在「踩不到它的样本」上，还是恒真。** 「长词优先」写在两组长短不同但**起点也不同**的重叠词上，
  由 start 升序自然赢，改坏长度排序照样绿；「跨句不许替换」写在没有跨句编辑的主样本上，
  改坏过滤照样绿。反证的第一遍就把这两条抓出来了——修法是造**同起点**词对、造**非空**跨句样本。
- **「还没填」不等于「填错了」。** 两行空输入框被内核判成 `all-invalid`，界面在用户还没动手时
  先说「这几组词都没法用」。纯函数层全绿、端到端才抓到。空状态要说「还没填」。
- **并排盲看现在做不了**：103 份存档里只有 15 份带 `raw.text`，落在 **2 组文本**上，
  其中 14 份是同一段「取消早读」。拿它对照＝把重复当样本。解锁条件（真模型多文本 / 人提供对照材料）
  已写进 README 已知限制与路线图处境，别再凭印象提议「做一次盲看」。
