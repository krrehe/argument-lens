# 论证镜 — 项目长期记忆

本机路径 `D:\2026-10-31-09-22-55`。Electron + React + TS 的「论证镜」：把日常语言里的论证拆开，
指出它站在哪、倒在哪、以及**哪一处其实站得住**。用户立场：**长期开发，代码只由 AI 写**，
他本人提供判断、钱、真实使用证据。

## 会话开场三步

1. 读 `AGENTS.md`（交接书）。2. 读 `docs/路线图.md` 的「一、现在的处境」与末尾「阶段状态」
（**状态只写在那里**，别另起进度文档）。3. `npm run verify` 确认基线绿——基线本来就红，
改完说不清是谁弄红的。**项数、条数一律以命令输出为准，别抄进文档**。

## 五条不可动摇

1. 不给单一判定：诊断/红队/重构有档位，查谬误/提问/对照没有。
2. 「此处合法」一栏不能删。
3. 六副透镜不合并、不翻译，分歧本身是输出。
4. 失败必须可见：写盘失败抛到界面，空 catch 写 `@allow-silent:` 理由，断言不许静默跳过。
5. **文档不能比软件更自信**：没验过的别写成验过的；没有断言守着的数字不写。

## 操作规矩

- 新增断言**先红后绿**（改坏一处必须红），且**逐组点名预期那一行**；只看整体红不够。
  恒真断言比没有断言更糟：写在踩不到的样本上、`0===0`、空文本上找不到禁词、拿常量比常量，都算。
  凡是验「顺序 / 去重 / 唯一」，先造**倒序 + 乱序 id** 样本；凡是「覆盖 N 类」，先问还有哪些轴没进计数。
- 碰了 `src/` 必须 `CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run dist` 重打包，并**逐个核 `dist/*.exe` 时间戳**
  （safe-delete shim 会让 build 中断却 exit=0，只出一个 exe；dist 已固化离线 `-c.electronDist=...`）。
- 改了界面必须跑 `smoke`（`pack:check` 不覆盖它）；`build` 与 `smoke` 不能并发；
  多模式冒烟前 `rm -rf scripts/.out/smoke-userdata`。
- 只在特定时刻出现的屏、默认收起的小块，都要留截图入口（预览页 `?xxx=1`、端到端 `SMOKE_*`）。
- 交付必说三件事：改了什么 / 验了什么 / **没验什么**。
- 本机 git 没配身份：`git -c user.name=workbuddy -c user.email=workbuddy@local commit`。

## 反复踩过的坑（按类合并，不再按轮次罗列）

**断言**
- 源码守卫盯名字会被 import 那一行满足 → 盯调用点。
- 「只读」断言量了被前面调用污染过的样本 → 用全新样本、先取快照。
- 判据脚本失败与判据失效长得一样（Windows 上找不到 npm shim、CRLF 跨行替换串不命中、
  脚本崩溃抛 TypeError）→ 反证出现「全部没命中」时先怀疑脚本。
- 分离的词表会互相吞词（「不一定」里的「一定」）→ 跨类判断共用一份占位记录。
- 字面重合不归一化 = 任何两句都相似 → 阈值两侧各造一份样本。
- `| tail` 量到的退出码是 tail 的 → `set -o pipefail` 或 `>/dev/null 2>&1; echo $?`。
- 两个布尔都为真 ≠ 同一个东西；子串断言会被句子里本来就有的词骗过 → 用整句正则。

**构建 / 环境**
- 本会话预设 `ELECTRON_RUN_AS_NODE=1`：要跑真 Electron 得 `unset` 后直接调 electron.exe。
- 建快捷方式不能用 WScript.Shell（COM 被挡）→ 用 `shell.writeShortcutLink` 并回读核对。
- `verify` 并发；怀疑被搞红先 `VERIFY_JOBS=1` 串行复现。
- `.mjs` 里不能有 TS 语法（`as Record<...>` 会在 ESM 解析期崩，typecheck 覆盖不到）。
- heredoc 吃反斜杠第 N 次（`.mjs` 里 `split('\n')` 落地成真换行）→ 用 Write 工具或 `chr(92)` 拼。
- `AGENTS.md` 上限是 **200 split 行**（末尾换行也算一行）；新增 `check:` 时 `check:docs` 会一次抓两处
  （AGENTS 漏写新关、README 项数没改）。

**界面 / 截图**
- 视觉模型估版式会错 → 先量 bbox；整页缩略图判不了小字与断行 → PIL 裁原图 + LANCZOS 放大。
- 版式看图，**文字用 DOM 探针（`textContent` / `value`）核**；8.5px 汉字不是小是认不出。
- 字数算得下不等于词断得对；把格式化时间插进固定短语要连起来读一遍（「最近今天 18:12」）。
- 探针抢跑（同一个 `executeJavaScript` 里点完就读）看起来像「按钮点不动」→ 分两次 + 等一拍。
- 每行默认态会让「只亮一个」类断言天然失败 → 验「亮的是哪一个」，把实际值报出来。
- `check:css` 连 `var(--x, fallback)` 里的 fallback 也算变量缺定义 → 用实色或已定义变量。
- 图例形状要跟画法一致（实心 / 空心不能用虚线解释）。

**数据 / 措辞**
- 「兼容某格式」不是声明出来的，是对方解析器读得进去（Argdown 用 `@argdown/core` 当裁判，
  `.prg` 用 `@msgpack/msgpack` + `@zip.js/zip.js` 与对方 CLI）。zip 小端 / msgpack 大端。
- 数字恰好相同会掩盖单位错；统计条每个数都要带单位并让端到端逐字核。
- 「还没填」不等于「填错了」；空状态要说「还没填」。
- 判据自己错了的时候，输出看起来和代码错了一样（按 `result` / `landed` 数，两个都报 0，
  实际字段名是 `answer` / `confidence`）。
- 缺口分两种：样本太少，和一整个维度从没被覆盖过。
- `rewriteJsonl` 会把坏行吃掉 → 删除时用 `rewriteJsonlRaw`。
- 同时改坏两处会让反证互相抵消 → 一次只破一处。
- 写死四项的清零说明在「全不适用」样本上说假话 → 措辞不实比排版错难发现，要单独配样本。
