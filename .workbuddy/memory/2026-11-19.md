## 第 68 轮：一大段话只有几句被分析——覆盖账原来在替模型开脱

**用户问**：「一大堆话只有几句话被分析你觉得没有问题吗？」先复算本机 107 份存档，
够 800 字的只有 3 份：6268 字 / 167 句 / 有位置的条目落在 **8 句（5%）** / 31 段里 25 段零引文；
4078 字 / 64 句 / 9 句（14%）/ 22 段里 15 段零；2507 字 / 60 句 / 5 句（8%）/ 11 段里 7 段零。

**两个发现**：
1. 覆盖账只数结论／前提／中间结论／谬误名／合法招这五类**有位置**的条目；
   检查项的 `basis` 是自由文字（里面还引了原文，如 CQ3 引「高彩礼仅只是症状而已」），
   本地定位不到句子、不计入。所以「8 句」既不是「只分析了 8 句」，也不能证明其余没读。
2. 边界说明里那句「没被落上的句子不等于分析漏了」在 4078 字那份上**不成立**：
   未落上的第 6、7、10、11 段是完整的类比与因果推理（「只要吃饱穿暖就该感恩」
   「把好就业偷换成人生幸福」），不是转述或铺垫。这就是替模型开脱。

**改（只改如实，不改判定）**：
- `coverage.ts`：抬头改「有位置的条目落在 8 句上（5%）」；新增 `sharePct`、`partial`、
  `coverageScopeText(pinned,sentences,untouched)`；边界说明改成
  「本地分不出来，所以既不替你排除，也不替你判定」，并明写检查依据不计入。
- `Diagnosis.tsx`：判定那句下面加范围行，**挂在 `cov.partial` 上**（不是无条件渲染）；
  `Overview.tsx` 第③句 extra 加「· 引文 3/42 句」并带 `data-quick-cover`。
- `styles.css` `.verdict-scope`：左边框用 `--weak`（项目里没有 `--warn`，check:css 抓到）。
- `audit-longtext.ts` 的【边界】同步改口径，别让命令行还留着旧保证。
- `check-coverage.ts` 80→91 条；`prove-coverage.mjs` 19→23 组，新增「范围句不挂在 partial 上」
  「数字写死」「速览不带覆盖」「又打包票」四组，逐组真红。
- README 长文覆盖账段、AGENTS 两处、路线图 2026-11-19 小节同步。

**验**：verify 54/54；check:docs 80；check:coverage 91；反证 23/23；smoke 全过；
预览页 `?coverage=1` 用 CDP 读到范围句与速览标记（3/42 句、7%），截图确认不重叠不裁切；
dist 两 exe 重打 + pack:check。

**没修（要紧）**：抽取预算不随长度增长——6268 字与 126 字报告结构一样（4 前提 / 3 检查）。
长文的正路仍是切分后「逐段跑」。要让模型列全论证单元、检查项也带 span，得改 schema 与提示词，
并且必须有真模型跑十段长文才算数；余额为空，这轮只把范围摆到明面上，写进路线图下一步。

## 第 69 轮（2026-11-19）：范围句接上「切给我看」，长文跳转进端到端

**起因**：用户说「继续完善」。先查实情——`%APPDATA%/argument-lens/longform/` **一条账都没有**：
107 份存档里逐段跑一次都没被真正用过，3 份长文全是整篇跑的。也就是说，上一轮把
「只覆盖 5%」摆到判定旁边，只解决了「知道」，没解决「看见之后能干什么」。

**改**（纯本地，不花钱、不改提示词）：
- `Diagnosis.tsx`：范围句右边加「切给我看（N 段）」，挂在 `cov.segmentCount > 1` 上，
  派 `al:segment`。判定区**不许**出现 `runBatch`——批跑的调用次数与确认仍只在切分条上。
- `SegmentBar.tsx`：监听 `al:segment`，展开列表 + `scrollIntoView` + 闪 1.4 秒（`sg-hit`）。
  已载入某一段时只滚不展开（那一屏本来就没有列表）。
- 样式：`.verdict-scope` 改 flex（文字 flex:1、按钮 flex:none、可换行）；`.vscope-act` 线框
  （这一格是说明，不是主按钮）；`.sg-bar.sg-hit` outline。

**验**：check:coverage 91→101 条；反证 23→28 组逐组真红（无条件渲染 / 事件名改掉 /
不展开 / 不闪 / 判定区塞进 runBatch）。端到端 `SMOKE_LONGFORM=1` 新增 5 条真交互断言：
按钮出现、点前列表收起、点后展开、滚完停在视口里、跳时闪一下。全过。
默认 smoke 也过；verify 54/54、docs 80；预览页 CDP 读到「切给我看（11 段）」并截图
`docs/screenshots/longtext-2026-11-19/verdict-segment.png`（旧的同名范围句图已删，被新图覆盖）。

**踩的坑**：往 `wc.executeJavaScript` 的模板字符串里写了 TS 类型标注（`let x: Record<...>`、
`as HTMLButtonElement`），渲染进程直接 `SyntaxError: Unexpected token ':'`——字符串里的代码
不归 TS 管，得写纯 JS。另外第一版拿六段短文（202 字）去验按钮，够不到 800 阈值，
`scope:false` 红得对：换成六段各重复六遍（>1000 字）再验，验完换回短文逐段跑。

**仍然没修**：抽取预算不随长度增长（这轮没动提示词与 schema）。这颗按钮只把「知道却没动手」
补上，不提高覆盖。
