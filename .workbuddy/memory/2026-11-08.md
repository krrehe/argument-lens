## 第 43 轮：与 Project Graph 互通（导出画布工程）

用户原话：「与这个软件进行深度融合 https://github.com/graphif/project-graph」。

判据先行，动手在第二：
- 许可证：桌面应用 **GPL-3.0**（`app/LICENSE`），`packages/serializer` 是 MIT。
  结论：**画布不能嵌**（分发即要求整体 GPL），**格式可以照着写**（格式不是代码）。
- 格式（目标 2.7.0）：`.prg` = zip 容器，里面 `stage.msgpack`（`{_: 类名, 字段…}` 数组）、
  `tags`、`reference`、`metadata`；`{ $: "/3" }` 是按数组下标的引用；`Color` 的 r/g/b 是
  0–255 而 a 是 0–1；`associationList` 第一个是源、第二个是目标，比例 0.99→0.01 是「右出左进」。
- 落地：`@shared/prg-graph`（报告 → 节点/线/坐标，纯函数）+ `@shared/prg-pack`
  （自写 msgpack + 只存储 zip，无运行时依赖）；报告顶部第三个导出按钮；写字节不写字符串。
- `check:prg` 54 条进 verify（30 项）；反证八组逐组点名真红。

### 这一轮新踩的坑

- **zip 的多字节字段是小端，msgpack 是大端。** 第一版全按大端写：文件四段结构都在、
  EOCD 签名落在末尾成了 `504b0506`，只有对方的解析器读的时候才说「找不到中央目录」。
  写字节的东西**要看字节**，不要只看「有 zip 头有 zip 尾」。
- **拿常量去比常量产出的字段＝恒真断言。** `PRG_TARGET_VERSION` 比 `metadata.version`
  在第一版里睡过去了，把常量改成 2.6.0 照样全绿。改成独立字面量 `'2.7.0'` 才真红。
  这是第 N 次：**断言里出现「同一处真值的两个化身」，就等于没断言。**
- **heredoc 吃反斜杠第三次了**：`'... + "\n")'` 落成真换行，SEA helper 直接语法错。
  用 `chr(92)` 拼，或者改用 Write 工具。
- **他们自己的 CLI 当裁判，是可行的**：`tool invoke get_all_nodes --project x.prg`。
  拦路的一步是「工程所有权」要一个独立可执行文件（默认 Rust 编译），本机没有 Rust；
  用 **Node SEA**（`--experimental-sea-config` + postject 注入 node.exe）造了个替身，
  按它的 JSON 协议回 `try-hold-project` / `load-project-references` / `save-project-references`。
  它声明 `engines.node >= 26`，本机 22 实测能跑。
  它读出来的结果：7 节点、6 线，坐标与朝向全对——这是「兼容」第一次不是自我声明。
- **失败的表现与成功长得像**：`spawn` 一个不存在的 helper 与 helper 回错协议都报
  `OWNERSHIP_HELPER_INVALID_RESPONSE`。加一行「往日志文件里写 argv」才看清它先调了哪三个命令。

## 第 44 轮：两份对照（同题复跑的数字，终于能点开）

用户中途插了一句更重要的话：「我的定位是一个论证方向工具，但一直感觉没达到像 AI 加提示词工具」。
这一轮做完的东西正好是那句话的一个答案（软件自己算、不花一分钱、不经过模型），
但真正的诊断写在下面「结构性缺口」那段，下一轮按它走。

- 起因：「同题复跑」只报「8 份里 268 处变过」。这句话分不开「268 个地方都在抖」与
  「一份整个重写、七份一模一样」——而本机实测正是后者：7 份 JSON 6.9 千字、第 8 份 9.7 千字。
- 落地：`@shared/sideby`（纯函数）+ `SideBySide` 面板 + 同题复跑每组后面的号码（勾两份）。
  **按元素 id 对齐、不按下标**；缺失与不同分两种；四种「没有」（不存在 / null / 空串）分写；
  四项（原文/透镜/模式/指纹）各自说，任一不同写在表格**前面**。
- 断言：`check:sideby` 59 条（verify 现 31 项）、端到端 9 条、包内 1 条；反证八组全红。

### 这一轮新踩的坑

- **探针抢跑，长得和「按钮点不动」一模一样。** 点完两个号码立刻在**同一个**
  `executeJavaScript` 里数 `[data-agreement-picked="1"]`，读到 0——React 还没重渲染。
  必须分两次执行 + 等一拍。这条失败当时看起来就是「功能坏了」。
- **恒真断言的新形态：样本空间太小，不是样本有序。**
  ① 所有样本共用同一个提示词指纹 → 把「四项」判成永远「同一版」也全绿（补一份没指纹的样本）；
  ② 样本只有一个区段 → 「区段按读法排」在任何排序实现下都成立（补一份结论 1 处、检查项 3 处的）。
  以前栽的是「样本天然有序」，这次是「样本太窄」。**反证要问：有没有一种坏实现能在我这组样本上通过？**
- **一条断言红着躺了一整轮。** smoke 里「两个导出按钮」自 `.prg` 那一轮就红了
  （那时 `length === 2`，加了第三个出口），而那一轮只跑了 `pack:check`，没人跑冒烟。
  **改了界面就必须跑 `smoke`，`pack:check` 不覆盖它。**
- **heredoc 吃反斜杠第 N 次**：`log.split('\n')` 落地成真换行，`.mjs` 直接 SyntaxError。
  改用 `chr(92)` 拼，或干脆用 Write 工具写文件。
- **裁截图要按面板实际宽度**：980px 面板居中在 1700 视口里 → 350..1355；
  第一次按 300..1060 裁，右栏整个切掉了，图看起来像「只有一列」。
- **`null` 被当字符串印出来**：`JSON.stringify(null)` → 界面上一个英文 `null`。
  三种「没有」必须分开写：不存在 / `null` / 空串。
- **断言只盖一个方向（又一次）**：`premises[...]` 那张表里同时有甲侧与乙侧路径，
  原来的条件只看了一眼乙侧就绿了。现在两侧一起看，并加一条「不许出现裸下标 `[0]`」。

### 结构性缺口（下一轮要动的）

用户的原话是「感觉像 AI 加提示词」。判断：**不是模型的问题，是人写的东西一次都没被用上**。
四处人写的东西（异议、成立条件、下一句、重读/换尺度）全都存了、全都只读不参与。
工具不记得你上次说什么，所以每次都是「把一段话发给模型」。
下一轮的方向：让这些账回到报告上（「这一处你上次不同意」「你自己写过下一句」），
不评价、不改判定、只把两份并列。这件事不花钱、不依赖模型、且只有工具做得到。
