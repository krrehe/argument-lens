### 第 64 轮：历史检索（一百多份报告不能只靠滚）
**问题**：路线图里开着的四项都要花钱或要真人样本，于是挑一件本机证据确凿的缺口——
存档一百多份报告，历史面板没有搜索框；列表每份只露原文开头 72 字，按摘要找等于
只允许人找第一句，而人记住的常常是中间那个词。

**改法**：`@shared/archive-search` 纯函数（parseTerms / findInReport / highlightParts），
七类文字：原文、结论、前提、中间结论、修补、检查依据、判读。多词是 AND 且允许落在
不同字段；按字面找，不认同义词/拼音/词形还原；每份只出一条，写「哪一类、几处」，
片段逐字摘自报告（只折连续空白），命中加底色。主进程 `findReports` 复用 `scanDir`，
不另写遍历。界面 220ms 防抖，新查询立刻清旧结果（否则「0 份」可能属于上一句话）。

**四条设计，都是为了防止说假话**：
- **结果按时间排，不按相关度排**：相关度本地算不出来，按它排等于替用户判断
  「这份更像你要找的」。
- **「一份都没有匹配（在 N 份里按字面找的）」与「另有 N 份读不出来」分两句**。
  合成一句就变成「确实没有」；命中但不在索引里的文件也单独说。
- **片段取第一处，但 count 数全部处数**：「出现一次」与「出现九次」是不同线索。
- **加亮按词长降序试**：先试短词会把长词切碎，界面对着 `terms` 加亮不另算一遍。

**验证**：check:after 98→155；静态反证六处逐处真红（多词 OR／前提拼串／加亮不试长词／
按相关度排／unreadable 恒 0／界面不筛）；真机反证 `archive:find` 恒空 → 红。
两张真机截图 history-find.png / history-none.png：空结果那一屏靠看图才确认它不像「坏了」。
包内自检新增 `FINDRESULT`（`AL_FIND=1`）：真调一次桥，查询词取自原文**中段**，
再搜不存在的词要求 scanned 相同——证明 0 份是扫过盘之后说的。理由：这功能跨
preload / IPC / scanDir 三层，任一层没进 asar 的症状都是「搜什么都没有」而非报错。

**没验**：真模型报告里七类字段取法是否稳（模型随手改字段名，那一类会悄悄消失，
界面上说不出来）；同义词找不到会不会被当成 bug（明确不做，不是遗漏）。
**不是主线进展**：4.8% 没动，真模型评测仍没跑（余额为空）。

**收尾补记**：

  唯一红项正是「历史检索三层接线」，读数 `scanned:0 / terms:[] / hasFirst:false`；
  还原后完整重打，42 项全绿。查询词首字是标点会让人以为「搜了个逗号」，
  往右挪一格取四字，最终读数 `q:"学生就该"`。
- `pack:check` 遇到一次假红「真实用户目录一份文件都没动」：同一时刻另有一个
  不带 `--user-data-dir` 的实例在轮换 Chromium 的 leveldb / LOG.old，
  快照把「别的进程在写」记成「这次自检污染了用户数据」。等那个实例退出后原样
  重跑即全绿。**正确动作是确认没有并行实例再重跑，不是从快照里排除缓存目录**——
  排除后真正的隔离失效可能只剩缓存变化这一条线索，恰好被抹掉。已写进脚本注释。
