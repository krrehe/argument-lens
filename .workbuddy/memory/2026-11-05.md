## 第 40 轮：下一句（P2 的输入通道）

开工三步：读 `AGENTS.md`、读路线图现状与阶段状态、`npm run verify`（当时 25 项绿）。

**为什么做这一件。** 上一轮交付时自己写下的结论是「三屏都是同一句：验得了形状，验不了学会」。
连着加第四个「教人看懂」的屏，是重复一条已经知道没有证据的路线。路线图第四节那条判据
（十段真实文本、只记「看完之后下一句是什么」）写了一个月一直零输入，原因很笨：
**软件里从来没有一处地方收这句话**。所以这一轮补的是通道，不是又一个屏。

### 做了什么

- 报告最底下（所有板块之后）一个空框：写一句、点「记下」或 Ctrl+Enter。
  存 `userData/nextlines.jsonl`，只追加；删除按原样的行重写。
- `@shared/nextline`（纯函数）：原话只去首尾空白；按**逐字相同**分组计数；
  空白条、坏行单独数；一句话总述 + 明细行 + 纯文本导出。不分类、不打分、不写判断。
- `jsonl.rewriteJsonlRaw`：删除时按原样的行重写，读不出来的行不被顺手抹掉
  （`rewriteJsonl` 会 JSON.stringify 每一行，坏行在那一步就没了）。
- `?nextline=1` 预览入口；`docs/screenshots/nextline.png` 是报告末尾那块的原尺寸特写
  （整页截图里它只有几毫米）。
- `check:nextline` 75 条进 verify（26 项）；`SMOKE_NEXTLINE=1` 端到端 11 条；包内断言。

### 反证抓到的两件事

1. **静态守卫盯名字，会被 import 那一行满足。** 第一版写
   `/appendJsonl/.test(MAIN)` 与 `/nextLineIssue/.test(MAIN)`，把调用换成整份重写、
   换成另一套校验，照样全绿——因为 `import { appendJsonl, ... }` 里就有这两个词。
   改成盯调用点（`appendJsonl\(nextLinesFile\(\)`、`nextLineIssue\(\s*input`）后才真红。
   **名字出现在文件里，和它被用来做事，是两件事。**
2. **端到端只验界面数目，会漏掉「只写内存」的实现。** 加了「再读一次盘」这条独立真值：
   走 `nextlines.list()`（读路径）而不是写的时候顺手返回的那份。
   少了它，一个只往 React state 里加、根本没落盘的实现，前面每一条都会绿。

端到端 6 组反证全红：整块不渲染 11 红 / 点了不写盘 7 红 / 截断原话 2 红 /
不落盘 3 红 / 删不掉 1 红 / 挪到报告上方只红「位置」1 条（结构性移动也是真变异）。

### 没验的

- 这些句子能说明什么：现在本机零条，一个人写的话不构成样本。
- 它不判断这句话算不算空泛（那是设计，不是缺口），所以「多数人的下一句是不是所以呢」
  仍然要人把账读一遍才知道。
- 放在末尾意味着只有读到底的人才看得见，样本天生偏少——这是为「数据不变质」付的代价，
  写进了 README 已知限制。
