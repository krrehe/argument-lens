# 论证镜 Argument Lens

一个 Windows 桌面应用，用来**把大模型对一段论证的判断，整理成能逐句核对、能存下来回看的报告**。

输入一段真实的话——社论、评论区争论、广告文案、论文段落、面试说辞——**模型**按一套评估标准写出判断；软件把这份输出拆成结论、显式前提、未言明的隐含前提和推理链，每一处对回原文，让你自己核对它站在哪、倒在哪、**以及哪一处其实站得住**。

判定权不在软件这边：评级、可接受度、举证责任、检查项答案、反驳都由模型写出，本地只做原文定位、字面比对、结构核对与越界纠偏。这是 2026-11-12 由用户拍板定下的产品定位（[产品定位](docs/产品定位.md)）——**改的是承诺，不是判定质量**。

它不给文章打分，也不输出没有位置、没有代价的「谬误名单」。

---

## 为什么不是谬误检测器

这个决定不是趣味问题，是文献和实测共同逼出来的。

**谬误没有公认定义。** SEP 的 *Fallacies* 条目里，标准定义（看似有效而实际无效）的三个条件「All three conditions have been brought into question」。Massey 的不对称论题直接说：不存在无效性理论，因此没有论证能仅凭逻辑理由被判为谬误。

**分类学互相冲突。** 单是 IEP 那份名录里，Begging the Question / Petitio Principii / Circular Reasoning / Question Begging 是四条同义条目；False Dilemma / False Dichotomy / Bifurcation / Either-Or / Black-or-White / No Middle Ground 是六条同义条目。异名同义与同名异义同时存在，且没有裁决规则。

**机器做不好这件事。** 这些是可查的实证结果：

| 任务 | 结果 |
|---|---|
| 232 类谬误细粒度分类（Hong 2024） | 最好模型平均 **34%** |
| 按语用辩证十规则分类（ACL 2025，零样本） | GPT-4 **0.49**，GPT-4o **0.13** |
| 同上，真实语料而非教科书例句 | **0.23–0.29** |
| 把规则讲给模型听再让它判 | **性能下降**，GPT-3.5 与 GPT-4 都降 |
| 双人专家独立标注（FAINA, NAACL 2025） | 数据集按「承认多解」设计——专家也分歧 |

最后一条最要紧：两位受训专家在同一段文本上给出不同标注且都合理，意味着「正确答案」这个概念在这里不成立。**任何输出单一判定的界面都在撒谎。**

所以这个工具做三件相反的事：

1. **给位置，不给名字。** 「第二步把『可能』换成了『将会』，这一步没有支撑」是可对照原话检验的；「犯了滑坡谬误」只能争论算不算。
2. **保留「此处合法」一栏。** 清单式工具最致命的缺口是没有「这里其实没问题」这一项，于是一个做得对的地方也会被扣上名字。
3. **谬误名放在最后，且要过三道门。** 说不出「使它成为该谬误而非别种的条件」「什么情况下这其实合法」「这条判断最可能错在哪」，程序就不显示这个名字。

查谬误模式是这套立场的延伸，不是反悔：名字在那个模式里当主输出，但四样代价一样不能少——原文哪一句、凭什么是这一条、什么时候其实合法、这条判断最可能错在哪。缺一样，程序直接把这条名字丢掉并写明丢的是哪条。位置与代价不变，变的是名字从末端注释升为主输出。

## 六副透镜

同一段文本，换一套理论就是另一次分析。**它们互不翻译，分歧本身是结果。**

| 透镜 | 判定单元 | 什么时候会失效 |
|---|---|---|
| 论证型式与批判性问题 | 一条 CQ（批判性问题） | 认不出型式、一段里混了多个型式 |
| 语用辩证十规则 | 四阶段 × 一条规则 | 广告、社论、独白——说话人不以解决分歧为目标 |
| ARS 三标准 | 单个前提上的一个标准 | 没有阈值、受众未定 |
| 型式周期表三特征 | 阶 × 轴 × 陈述类型 | 中文口语主谓难以切分 |
| 图尔敏布局 | 六要素之一 | 严格演绎里布局冗余 |
| 教科书名录对照 | 名录中的一个条目 | **它本身就是反面教材**：只给候选，程序强制不许给结论 |

最后一副是特意留的。它把「贴标签」这条路走到尽头，并在同一屏里给出该条目的成立条件、何时其实合法、最可能错在哪——让人亲眼看到名录法的极限，比抽象地批评它有说服力。

每副透镜是一份独立完整、装配生成的提示词，可在应用内「提示词」页直接阅读和复制。**用户有权看到自己被什么标准在衡量。**

## 怎么让人看懂

一份判断准确但读不懂的报告，价值等于零。所以界面分两层：**一层说人话，一层把关系画出来。**

**每栏一句人话。** 原文、结构图、逐关检查、判读、重构、反驳……每一栏标题下都有一行浅蓝底的说明，只回答「这一栏在说什么、为什么要看它」。这行字是手写的，不随分析结果变化。

**术语表 + 悬停。** 40 余个术语各有「一句人话 / 再深一层 / 一个例子」。正文里带虚线的词悬停即解释；顶栏「术语表」可全量查。硬规矩：**解释里不许再出现术语**——否则等于把解释做成第二个谜语。

**六副透镜各有一句人话。** 不是把「担保」换成「保证」，是重写整句。

**每张图各治一种看不懂：**

| 图 | 治什么 | 关键约定 |
|---|---|---|
| 谬误落点图（查谬误模式） | 这个名字指的是我哪句话 | 每格一句，按原文顺序；挂着候选的句子下挂「名字 → 检查关」胶囊；与命名卡双向对位；**定位失败或没给位置的不画**，写明原因 |
| 结构图（思维导图） | 他在论证什么 | 左依据→右结论；实线＝原文说的，虚线＝替他补的；左侧色条＝听众认不认；红叉＝这一步接不上 |
| 判读刻度尺 | 到底算不算站得住 | 三档横条 + 指针，被削弱与不成立是两个位置 |
| 判读推导链 | 凭什么落在这一格 | 四步：问了几关 → 钉住它的是哪一关 → 三格各是什么意思 → 落在哪一格。**三格都写释义**，只解释当前那一档，等于让人没法判断它是不是放错了位置 |
| 逐关检查 | 检查表那么多行在说什么 | 一排关卡（✓ 过 / ✕ 没过 / ? 没答），点开看依据 |
| 专题分析 | 这类论证文献上还公认问什么 | 六个专题（类比/因果统计/来源/实践/定义/预设），命中的展开问法，未命中的写明原因；本地推导，不给档位 |
| 学术分析 | 哪些我核过了、哪些只能你自己核 | 体裁判定、待核的引用与数据、八条规范（标「本工具查不了」的三条排场一致）、这一圈的词（词表由你填，本地只按字面定位）、反驳该先从哪层下手；本地推导 |
| 六透镜地形图 | 为什么要换透镜 | 横轴「只管这一段↔整场讨论」，纵轴「给结构↔给名字」 |
| 进行中面板（不是图） | 按了之后这一分钟在干什么 | 阶段名 + 百分比（只在阶段切换跳）+ 已等秒数 + 「停」。**停真的掐断请求**（abort 穿到主进程 fetch）；代价写在旁边：钱可能已经花了，账本里只留得下一条金额记 0 的失败记录 |

结构图的连线来自数据契约里的 Claim.supports：哪条依据在撑哪句话。模型漏填或写错 id 时，程序统一落到「直接支撑结论」并留痕——**宁可画成最朴素的重构，也不画一根猜出来的线。**

**报告目录会记住你上次停在哪一节的哪一段。** 一份报告两万像素，重开时从标题重新找起很蠢。目录顶端因此多一句「接着读：第 7 节 · 判读」——这一版又往下记了一层：**节内哪一段**，写出来是「上次读到第 4 段「为什么在这一格判读不是算…」」。它只在**这一份**报告有记录时出现，换一份绝不沿用上一份的位置。**它不会自动滚过去**——从哪读起是读者的事，软件只留一条回得去的路；点了才跳，落到那一段而不是节首。记录按报告 id 分开存（`localStorage['alPos.v1']`，只留最近 40 份、按时间丢最旧）；停在第一节不记，因为报告一打开就停在那里，记下来等于把上一次真读到的地方抹掉；记录指向的那一节不在了就什么都不说——说「第 12 节」而报告只有 9 节，比不说更糟。段那一层记两样东西：**序号**（这一节正文的第几块）与**开头二十几个字**，缺一不可——只记序号，报告重跑后整体后移会把人带到下一段，而且读起来完全正常；只记开头，两段开头一样就认错，还认得很肯定。两样都在才算「找到」，对不上就退回只说节，并且**明写「那一段这次没找到」**，不悄悄落回节首（悄悄退回去，人只看见位置不对，不知道为什么）。三种情况不记段：正文只有一块的节（那里「第 1 段」等于「这一节」）、刚点过目录落到节首的第一块（人没读它，记下来等于替人认了一次没发生的阅读）、以及空块。比对用的是开头 24 字，给人看的是前 12 字加省略号——面板只有 250px 宽，24 字要占两行，而那两行下面还有「先看判读」和「上一节 / 下一节」；完整那句在悬停提示里（截图 `docs/screenshots/nav-seg.png`）。平滑滚动会连着穿过好几节，所以写盘延后 350ms；刚点过目录就以「点的哪一节」为准（照那一帧的视口记，会记成前一节——这条是冒烟第一次跑就红出来的），但同一个窗口里往下滚到某一块照记——窗口只管「哪一节」，不该把节内位置一起抹掉（**这条也是冒烟跑红的**：第一版把整段位置一起抹了）。边界：它记的是「滚到哪」，不是「读了什么」，也不推断有没有读完；重跑过的报告若那一段文字变了，它只会说「没找到」，不会替你猜是哪一段；「关掉软件再打开」这一半由端到端里「重走一遍打开」作证，真实重启没验过。

开头还有**四句话**（他要你信什么 / 最薄的一处 / 说明到什么程度 / 怎么补），每句可点，滚到对应栏。四句话下面那条「跳到」是整页唯一的紧凑索引：它按这份报告**实际有哪几栏**现算，命题账与枢纽前提有数据才出现（没有就不给一格点了没反应的死入口），先后与正文从上往下一致。这两栏落在一万像素以下，没有这条索引基本没人翻得到——做完藏起来等于没做。点结构图里的 P2，原文与主张卡同步高亮；点检查跑道的 CQ2，表格对应行亮。图与文互为索引，这是「相辅相成」的实际含义。

**等的那一分钟也要交代清楚。** 一次分析 30–90 秒。这段时间主区不是留白，也不是一个一直往前爬的假进度条：它写当前阶段（「逐条走检查项」）、阶段换来的百分比、已经等了多少秒，以及一句代价——**关窗供应商照样计费，而这一条多半来不及记进账本；想留下记录就按「停」**。百分比只在阶段切换时跳，因为主进程只报得出阶段；凭空匀速爬的进度条是在替模型撒谎。

详见 docs/通俗与可视化.md。

## 它承认自己有争议

一份判断最容易被追问的一句是「你凭什么」。只答「沃尔顿说的」，是把权威当理由——而这个工具反对的恰好是这件事。

所以除了「凭什么这么判」的理论卡，报告里还单开一栏：**这里有什么争议**。

先说清它**不是**什么。它不是什么「仅供参考」的免责声明：

| | 不确定 | 有争议 |
|---|---|---|
| 是谁的毛病 | 工具的：没把握 | 学科的：真没有共识 |
| 显示在哪 | 每条依据的置信度 | 独立一栏 |
| 怎么用 | 别当真，去核对 | 知道该攻哪里，或知道可以不同意 |

两件事混在一起，「此处有争议」就会变成万能的挡箭牌，于是它失去信息量，用户也不再区分「它错了」和「它站在少数派那边」。

**每张争议卡固定四件东西**：争点（写成问句）、每一派的主张**与接受它的代价**、本工具站哪一派**及为什么**、可核查出处。代价一栏是必填——只写主张不写代价，就是在替自己那一边说话。

**11 条争议，六副透镜各至少一条**，每条都标着它守着哪一处判定：

```
型式判定 ─ 型式靠内容认，还是非得先有形式判据
未答的分量 ─ 某条检查没答上，算不算已经打倒
适用域 ─ 不想说服谁的话，能不能用十规则判
受众相对 ─ 可接受性看受众，是否等于没有客观标准
补出来的话 ─ 没说出口的前提，凭什么算他的
能不能切 ─ 没形式化的口语，能否直接切三特征
够不够 ─ 多强的证据才算够，谁定
反证算不算 ─ 三关全过但有反证，还算不算好论证
给不给名字 ─ 同一个毛病有三个名字，给哪个
可信度 ─ 「他的话要打折」的依据是什么
不下结论 ─ 拒绝给结论是严谨还是逃避
```

**触发由已定字段推出，不调模型。** `disputesIn(diagnosis)` 是纯函数：出现「未答」的检查项、有隐含前提、档位是「被削弱」、三标准无违反却记了击败、命名候选≥2、碰到来源与身份……每条都带一句**这一份的具体理由**（含具体数字），不是通用说明。

三个不调模型的理由：争议是查表不是生成；再调一次要再花钱；最重要的是——让模型自己说「我这里可能有争议」，它一定说得比实际多，那就是免责声明了。

**两个方向都要通。** 板块标题上有「争议 N」，点了跳到争议栏；争议卡底部有「报告里的『逐关检查』→」，点了跳回结论。顶栏「争议」是完整 11 条，可切「这一份碰到的／全部」——没分析时也能看，它是这个工具的世界观，不是某次输出的附注。

**站边的颜色是蓝灰，不是红绿。** 红绿是评价，而「哪一派更对」在这里是未知。用红绿等于把未知说成已知。

详见 docs/理论争议.md。

## 花多少钱

不用猜，也不用去翻账单：顶栏一直显示「今日 ¥0.06 · 约 927 次」，点开是完整账本。

**三条硬规矩：**

1. **你填的价永远优先，内置价只填空档。** 供应商会调价，写死的表迟早是错的。
   所以顺序是：你填过 → 一律按你的算；没填过 → 才用内置参考价估个量级（目前只收 `deepseek-chat` 与 `deepseek-reasoner`），
   金额前标「约」、明细里标「估算」。**不确定的模型宁可不写**，那一栏就空着——
   报一个错价，比报「未计价」更坏。
2. **估算必须自带标记。** 接口不保证返回 usage（本地 Ollama、部分代理都不给）。拿不到就按字数估（中文约 1.5 字 / token），但记录里带 `estimated`、明细里带「估」字、面板里单独统计估算占比。**估算和实测绝不混成一个数字。**
3. **余额不假装能查。** 各家没有统一接口，做不到就别装。所以只做「锚点」：你记一笔「此刻还剩多少」，之后每次分析从里面扣。重记一次就校正了，不用管中间花掉多少。

### 一次分析到底花多少

**一次约 7,000–9,000 输入 token，其中 99% 是提示词。** 不是你的文字长——你贴的那段通常只有两三百字——
是这副透镜本身有 1.1–1.6 万字符：六块内核 + 透镜片段 + 23 个型式索引（或 39 条目名录）。
API 无状态，每次都得原样重发一遍。

按 deepseek-chat 现价，一次约 ¥0.01。**一天用 50 次，约五毛钱。**

想省这一项，正确做法不是砍提示词（那是砍掉判定依据），是让前缀能命中接口的自动缓存。
前提是 system 逐字节固定。**v2.4.0 之前这条不成立**：system 里混着本次随机生成的分隔符，
位置在 11.6% 处，之后 88% 的提示词一次都没命中过——每次都按未命中价付，而且账本上看不出来。
现在随机串挂在 user 第一行当「守卫」，system 成了完全静态的常量。

**模拟调用不进账。** 冒烟测试跑的是本地假服务器，返回的 token 是编好的固定值。
那些流水留着可追溯，但不计入任何合计——否则「本月几次」里会混着根本没发生的调用。
面板底部会写明排除了几条。

**「还能跑几次」才是要回答的问题。** 按最近 10 次的均价推算，比「还剩 19.86 元」有用得多。余额告急时输入框下会多一行提示，但不拦你——弹窗拦下来的那次，往往正是你要用的那次。

**每条记录冻结当时的单价。** 改价不翻旧账；只有当时还没填单价的旧记录按现价补算，明细里看得到标记。失败调用也记一条但记 0 元（拿不到用量），所以这份账唯一系统性偏小的地方就是这里——真实支出会略高于显示值。要严格对账，导出 CSV 去和账单逐条核。

账本是 `userData/usage/` 下按月分的 jsonl，一行一条，只追加不改写。面板底部有「打开账本文件夹」——数据在哪，用户有权知道。

## 分析流程

《论证分析全流程 v1.1》把一次评估分成 A–D、F、E 共二十步（v1.0 是十六步）：v1.1 在 D 之后、E 之前插入 **F 分歧段**（F-a 定位分歧源 / F-b 定收束 / F-c 写收敛条件）与 **E4 分歧登记**，B4 依 §0.3 改叫「定枢纽 K」。软件里能落地的是两段：**A 立案**与 **F 分歧账**都由人填，填在输入区、随报告存下来；**B–E 的判定内容**由模型产出，再由本地的十道裁决逐条校对。A 那一段只能人填：文本不会告诉你它是初稿还是删改稿，也不会告诉你「某某认为」是作者的话还是记者的转述。F 那一段更是只能人填——让本地层替模型吐出两套答案，恰恰是 v1.1 第 4 章那句「不许假装判得出」要防的事。

```
重构（补省略前提）
  → 认族（实效 / 因果 / 来源 / 比较）
  → 认型式
  → 逐条问 CQ
  → CQ 全过仍有疑 → 反例法，落回某条 CQ
  → 判定击败类型与证明责任归属
  → 分级结论（带模态限定）
  → 修补建议
  → 最后才可选命名谬误
```

顺序不可颠倒。谬误命名排在倒数第二步，且必须回填 CQ 编号。

报告开头有一栏**全流程账**：把这二十步在这份报告上逐条对一遍——做了 / 只做了一半 / 没做 / 这一档不走，每一步写明本地在报告里看到了什么、缺的那步差在哪、下一步能做什么；账顶还写明这一档的**默认收束**（§0.1）。F 三步的按钮写「去登记分歧」，点了展开输入区那张分歧账卡；E4 落在报告里新增的「分歧账」只读栏。它先看证据再看档位：128 字的速判不会被要求交出修辞审计与自审四问，六百字的标准档没做 C1 三问就是缺。A 阶段没做完却已经给了档位时，它单独说一句「判在立案之前」——按文档 §1，那是返工级的失格，不该混在「二十格缺一格」里说。它只数「做没做」，不判「做得对不对」。**每一行右边那个按钮都是真的能走过去的**：A1/A2 写「去填立案」，点了跳到输入区那张卡并把它展开（报告里没有这一栏，写「看这一节」会让人以为还有一段没读到）；其余各步跳报告里对应的栏，而那一栏这一份报告里没有时（反驳在查谬误与重构两个模式下整块不出现、命题账与枢纽按数据，块没有就不给按钮）——一个按下去没反应的按钮，读起来像「软件卡了一下」，没人会想到是那一栏根本不存在。填完立案**要重跑一次**才进报告：立案只在按下「分析」的那一刻被带走，所以那张卡会明写这一句，而不是让人以为「我明明填了」（截图 `docs/screenshots/flow-go.png`）。

### 严格对照 v1.1：十二项变更，逐条交代落地与不判

用户给的是 `论证分析全流程_v1.1.md`。v1.1 相对 v1.0 有十二处结构变化，这一栏不写「已支持 v1.1」这种话，逐项说清**落在哪 / 本地不判什么 / 为什么不判**。总边界仍是那三条铁律：不动提示词、不改判定、不给分；分歧账只在按下「分析」时被带走，不进模型上下文（`check:divergence` 有一条断言专门守提示词一个字没动）。

| # | v1.1 的变更 | 软件里落在哪 | 本地不判什么 / 为什么 |
| --- | --- | --- | --- |
| 1 | §0.1 三档各加「默认收束」列 | `flowOf().defaultClosure`，账顶一行，Markdown 导出同源自这一段 | 不替人选收束。速判**默认**单判、不走 F 段，但人真登记了仍记「做了」——先看证据，没做才轮到档位说话 |
| 2 | §1 新增 F 段三步与 E4，排在 D 之后 E 之前 | 二十步账，F-a / F-b / F-c / E4 各有自己的证据核算；F 三步按钮「去登记分歧」 | 只看得到 D 之后统一收口的那一份账，数不出全程「当场记一笔」有没有发生；这一句写在账的边界里 |

| 9 | §6 反假阳性新增 13–15 条 | 连同原有条目一起列进卡里的「文档里这几条硬规矩」与导出件 | 不判有没有踩中；只让人在填的时候看得见 |

| 12 | §1 十六步 → 二十步 | 流程账、Markdown 导出、真机断言、包内断言一起改成 20 | 不虚设第 21 格：全场审计的「主张台账」只提一句，报告的数据结构里没有这张表 |

**有意没有做成独立界面的几件**：多方案判决卡模板、分歧报告模板、24 项检查表、校准指标、理论出处 +7、失效边界 +2、全场审计主张台账。前两类是文档模板，做进软件就会变成「软件给了答案」；中间两类是评估者的验收方法，不是能从报告字段里数出来的事实；最后一张表里的数据本地压根没有，只在账的边界里提一句，不摆空格子充数。

**验证**：`check:divergence` 145 条、`check:flow` 156 条、`npm run verify` 46 项；真机两条跑道（默认 125 条 / `SMOKE_DIVERGENCE=1` 132 条）分别验「没登记」与「填齐」，两处反证（断开主进程贴字段 → 3 条真红；坐标退回快照式合并 → 4 条真红）后还原；包内 `pack:check` 也把分歧账填一遍，验 preload → 主进程 → 只读栏三层都进了 asar。四种观感各留一张图：`docs/screenshots/divergence-partial.png`（填了没填齐）、`divergence-suspend.png`（悬置），以及真机产出的 `scripts/.out/divergence-empty.png` / `divergence-filled.png`。包内自检还撞出一处真问题：两份报告里只有一份带了人填的分歧账，「两份对照」把 16 处 `divergence.*` 报成「模型这次说得不一样」，连 `at` 时间戳都算一处。这里没有放宽那条 `0 处` 断言，而是把 `brief` / `divergence` 与原文、模式同列为**输入**排除出比对（`check:agreement` 92 条、`check:sideby` 61 条各守一条行为断言）：人填的账不是模型产物，第二遍才补填它不该被读成抖动。**没验的**：真模型报告上这一栏读起来像不像一份分歧裁决（余额为空，假模型只落在速判档）；人填完这些格是不是更会判，零证据。

三条硬规则：

- **削弱 ≠ 反驳。** 切断前提与结论的联结，只说明结论失去理由，不等于结论为假。这两件事在界面上分栏显示。
- **型式无好坏，误用才成谬误。** 型式本身是中性的，同一套骨架在合适语境里完全正当。
- **批评型式内部要素，责任在提议者；批评型式不适用，责任在回应者。**

## 程序层的十道裁决

模型会越界。以下十类能被代码抓住，每一类都写进「程序裁定」并在界面展示，不静默修正。前七类是设计时就知道要防的，G8、G9 是二十三份真实语料评测跑出来的（见 [评测报告](docs/评测报告.md)），G10 是自检接进生产后从 86 份真实报告里翻出来的：

| 编号 | 越界 | 处理 |
|---|---|---|
| G1 | 名录透镜给出了终局判定 | 强制打回 undetermined |
| G2 | 范围门判不适用却仍有检查项 | 清空 checks |
| G3 | 削弱性击败写成「结论为假」 | 改回 argument-only |
| G4 | 命名缺三门槛之一（条件 / 合法情形 / 误判风险） | 不显示该条目 |
| G5 | 型式 id 不在库内 | 降为 none 并告警 |
| G6 | 检查项 system 与透镜不符 | 改正并留痕 |
| G7 | 固定清单未列全（十规则 / 六要素） | 补齐为「未覆盖」，**不假装评估过** |
| G8 | 描述类模式（重构 / 提问）给出档位 | 打回 undetermined 并留痕 |
| G9 | 同一句既当依据又当中间结论 | 合并为一步，并改写正文里的旧编号 |
| G10 | 判为适用，却一条结论都没抽出来 | 清引文并打回 undetermined |

静默修正是另一种撒谎，所以每一条都留痕。

另外同一编号的检查项出现两次时，保留信息更全的那一条并留痕——两张一样的卡片里有一张是空壳，而且渲染层的 key 会撞车。

## 每份报告都自己过一遍

「结构对不对」这件事，原先只有跑完一次真模型评测（约六分钟、十七万 token）才有答案。最便宜的检查被放在最贵的位置，平时没有任何东西在看它。

现在生成完就自检，本地计算，不花钱。检查规则写在 `shared/report-audit.ts`，生产端和评测端跑的是同一份代码：

| 结果 | 含义 | 界面 |
|---|---|---|
| `invariants` | 结构自相矛盾——引用了不存在的主张、同一句被算成两步、档位与范围门打架 | 记成警告。照着这种报告改，会改错地方 |
| `gaps` | 该写没写——反驳没写对方的反击 | 记成记录。判断本身成立，只是缺了下一步 |
| `notes` | 重复占位的提示 | 记成记录 |

两类必须分开报。真实账上 86 份报告里有 79 份各有一条缺口，而结构矛盾只有 2 份各一条——混成一个计数器，那 79 条会把 2 条彻底淹掉。

## 下一步：从诊断到处方

报告说「CQ2 未答」，然后就没了。诊断到处方之间那一步，过去全靠用户自己走。

「下一步」这一栏把它补上：每条空着的检查项，按它守的论证位置分组，逐条给出**这一环叫什么、要填什么形状的东西、怎么算填上了、不改的代价是什么**。全部由已落盘字段本地推导，不加 token、不调模型。

三条规矩写在 `shared/prescriptions.ts` 里：只给问法不给答案；每条都必须可被证伪（验收标准指回具体的检查项 id，改完重跑，对照栏的 `resolved` 会告诉你补上没有）；不承诺救得回来。

它进过一次坑，值得记下来：最初按「这条反驳没写需要什么证据」报警，真实账上 79 份全中——直到逐条看下去发现大多数是合法的（「家长支持率不是早读有效的证据」这类反驳靠指出推不出来就能确立，不需要新材料）。**一条会把合法情况报成缺陷的断言，比没有断言更糟：它会训练人忽略报警。** 那条已经删了。

## 带走

报告原先只能在这个窗口里看。而真正改稿的地方是 Word、LaTeX、笔记软件——用户需要的不是「切回来看一眼」，是一份能放在旁边逐条对照的清单。**带不走的东西，用得再顺手也进不了工作流。**

「导出为 Markdown」把报告写成一份文件：判定与限定、逐条原文引文、检查项表、下一步的**可勾选清单**、对方会怎么打、这份分析的边界。全本地生成，不调模型，不花钱。

三条自我约束写在 `shared/report-markdown.ts` 里：

1. **不替报告加自信。** 抬头第一句就是「这不是判决书」。导出件会被转发、被贴进别的文档，离开界面之后它比界面上更容易被当成结论。
2. **不留空壳。** 没有内容的段整段不出现，而不是印一个标题配一行「无」——空格子会被读成「没问题」。
3. **不重算任何判定。** 只做排版，处方与边界一律调用原模块。导出件与界面显示不同的判断，比不导出更糟。

判了不适用的报告，导出的是一份短文件：说清为什么不适用，并明说「不适用不等于这段文字没问题」，不出判定段。让一份导出件带上它自己都不同意的档位，是这里最不该发生的事。

顺带补上一个一直没被显示过的字段：`whatIsRefuted`。「只驳倒了论证」和「驳倒了结论本身」对写作者的意义完全不同——前者说明你没写够，后者说明你写错了。它算出来存了几个月，界面上从没出现过。

**「导出为 Argdown」导的是另一件事：谁支撑谁。** Markdown 带走的是「我该改哪一句」，Argdown 带走的是结构本身——一种纯文本的论证语法，换到任何支持它的编辑器里都能渲染出论证图，而改动会落在文本上，可以进 git diff。它不是第二种判定：档位只写在注释里，且照旧带着「不是判决书」；「接不上」只做注释，不伪造成攻击关系；「此处合法」是独立节点，不连边——连边等于声称它支撑了某一步，而它恰恰是「这一步本来没问题」。
`check:argdown` 拿官方解析器当裁判，验的是**读得进去**；MapPlugin + graphviz 渲染成图那条路没跑过，
所以别把「能解析」当成「已经验过在编辑器里画得出来」。

这份导出由 `@argdown/core` 的解析器在 `check:argdown` 里验：**解析器读得进去才算数**。中文正文里出现 `[P1]` 这种引用很正常，直出会把引文切成语法碎片，所以 `[ ] { } # < >` 换成全角，并在文件头写明。没有这一步，「支持 Argdown」就只是一句自我声明。

**「导出为画布工程（.prg）」导的是第三件事：可以自己摆。** 前两种带走的是一份文件，这一种带走的是一个画布——结论、前提、中间结论、反驳、缺口都在，线也在，但位置只是草稿，打开之后怎么排由你定。它对接的是 [Project Graph](https://github.com/graphif/project-graph)（一个节点式画布工具，GPL-3.0）。**没有嵌它的代码，也没有引用它一行实现**：我们只按它工程文件的格式写字节（zip 容器 + msgpack 的 stage 数组），格式事实与出处记在 `docs/与画布工具互通.md`。这条通道守的规矩和前两种一样：节点上的字**逐字来自报告**（不截断、不加「前提 ·」这类前缀，角色靠位置和颜色表达），线只来自 `supports` / `targetId` / 补出来的那一句，不新算任何判定；交出去时丢掉的（打在不存在的目标上的反驳、文本为空的条目）在按钮旁边那一行里说出来，不静默吞掉。

「能打开」不是我们声明出来的：`check:prg` 拿 `@msgpack/msgpack` 与 `@zip.js/zip.js`（devDependency，不进包）把字节读回来，并且用**对方自己的 CLI** 读过一份导出件——见 `docs/与画布工具互通.md` 里那次运行的原样输出。它证明的是「文件被对方解析器读进去了、节点数与连线数对得上」，**没证明**图形界面里的版式好看，也没证明旧版本（低于 2.7.0）能打开它写的文件。

**「复制 Markdown」是第四个出口，但它不落盘。** 服务的是「贴到聊天窗口里问一句」「粘进自己的稿子」这类不需要一份文件的用法：内容与「导出为 Markdown」走同一个生成函数，所以复制出来的字与那份 .md 逐字相同，不存在「界面一份、导出另一份」。写剪贴板这件事与全局快捷键那一侧刻意不提供 `write()` 的边界不冲突——那边防的是软件在用户不知情时改掉剪贴板内容；这里是用户按下的一个按钮，写进去的是他刚看完的这份报告。

导出成功之后，路径旁边多了「打开文件」与「在文件夹中显示」。只显示一句被截断的路径等于把最后一百米留给用户自己走。这两个按钮只认**本次运行里真的写出过的那几个路径**（主进程留一份名单），不是「打开本机任意文件」的通道；文件被移走时说「文件不在了」，不点了没反应。端到端冒烟会真点一次「复制 Markdown」，再从系统剪贴板读回来核对字数与开头——纯函数断言守得住「内容同源」，守不住「点了有没有真的写进去」。

**报告顶部还有一条「这份里你记了 N 条不同意」。** 异议按钮长在每一处判定旁边，记完就变成那一行；一份报告两万像素、十几处能点，记到第三条之后人既不知道一共记了几条，也没法回到第一条去改口。这条账把它们按报告里原来的顺序归组，点「跳到这一节」会展开那一节并滚过去；工作台里钉在句子上的那几条没有可跳的区块，就明写「没有区块可跳」。零条时整块不出现——不摆一个「暂无异议」的空壳。它只归类与计数，不判断这些异议成立不成立，也不提供「按我的意见重算」。截图 `docs/screenshots/digest.png`、`digest-open.png`，预览页 `?digest=1` / `?digest=open`。

**判读之后紧接一栏「命题账」，回答另一半问题：这里每一条主张本来该由什么来定。** 判读只说了一件事——这段话站不站得住；可一份报告里排得很整齐的八条命题，性质并不相同。有的能去查（回原文、核统计口径、重算那一步），有的现在两方都给不出证据，有的是价值与制度选择——论证再多也只能说明代价，不能把它判真判假。把这三样混在一张表里，最顺手的错答案就是拿「证据不足」去否掉一个本来就不该由证据来定的命题。所以这一栏按四类竖排（事实·可裁 / 事实·证据不足 / 框架·体系内成立 / 规范·不由论证裁定），**不横比、不排序、不给分**：四类不是一条尺子的四档，把「证据不足」排在「不由论证裁定」下面，读起来就成了「更不可信」。每一行都带两样东西：凭什么这么归（命中的那个词，或落盘的那条判断）、什么条件下改归另一类（写不出改归条件的分类，和一句结论没有区别）。规范命题主要靠用词认，长词优先——「不合理」不许被读成「合理」，「不得不」不是「不得」；写得含蓄的价值判断（「取消早读是错误决定」）它认不出来，界面上就把这句短处写出来，而不是装作全能。账的最上面先说路由（纯事实／纯规范／混合），因为它对应流程里的 A3——混合命题必须拆开，不拆后面必然串账；拆法就是账本身。它同时出现在导出的 .md 与「复制 Markdown」里（调的是同一份纯函数），所以这段话被贴到聊天窗口时，「哪一条不是证据能定的」也跟着走。守这一块的是 `check:props`（50 条），导出那侧另有 `check:export` 的三条。

**账之后紧接一栏「枢纽前提」，回答第三个问题：这一段其实是靠哪一条撑着的。** 命题账说的是「哪几条不是证据能定的」，可它没说是哪一条在承重。日常批评最容易犯的错，是指出十处措辞毛病（用词不准、举例太少、口气太满），而那些全在枝叶上；真正让整段垮掉的，往往是作者当成「大家都知道」的那一句。指出十处枝叶，不如指出一次「你把 X 当起点用了，而 X 正是要争的那件事」。这一栏只攒两件事：**结论经过谁**（顺着报告落盘的支撑关系走一遍，几步到结论）、**谁身上已经有反对意见**（可接受性可疑／置信低／有反驳打在它身上／是补出来的前提／与结论字面重合）。两样都有的就是枢纽，排第一的那一条单独写一句主句。

它不打分，排序按三件能逐条说出来的事依次比：能不能走到结论 → 它供给的那一步有没有替补 → 有几种**独立的**争点信号（同一种算一种：同一处有两条反驳，仍是一种，只是把「2 条」写出来）。没有权重、没有总分，这条规则本身随界面与导出一起给出去——只给排名不给排序依据，读者就没法反驳它。三种行首标记分开的正是三种处境：「枢纽」（结论压在它身上，而它本身有争）、「孤柱」（必经之路，可现在没人质疑它——**这条最该先去核**）、「白吵」（有人争，可结论根本不经过它，争赢了判定也不动）。连不上结论的命题一律不进枢纽候选。它只摆事实、不代判，也不说「所以这条是假的」；短处同样写着：承重靠的是报告里落盘的支撑关系，那份结构要是模型随手写的，这一栏就是在把一张错的结构画得更精细。守这一块的是 `check:pivot`（51 条）；导出件里同样有这一栏与那句排序说明。截图 `docs/screenshots/pivot.png`，预览页 `?at=sec-pivot`（报告里任意一节都能用这个参数滚过去）。

## 修补了，然后呢

报告最后那一栏「修补」给的是建议。建议本身也是模型说的——它前面刚花了一整页论证「不要相信没有依据的判断」，凭什么修补建议就可以直接信？所以这一轮补了四条通道，把「建议」变成可以自己验收的东西：

**1. 长文切分。** 贴一整篇文章是最自然的输入方式，而范围门会判「这不是单一论证」。「原文」框下面会出现一条切分条：按段落与「所以 / 可见 / 由此」给出候选，注明每段是怎么切出来的（段落边界还是按字数硬切），点选一段才正式分析。切分是纯文本启发式，零调用；切不切、切哪段，决定权在你。**它给的是候选，不是替代品**——直接按「分析」，它不会替你拆。

**1b. 长文逐段跑。** 一篇社论里通常有三到五条论证，而判定单元是一条论证。切分条展开后底部有一个「逐段跑这 N 段」：点一次先给你「N 次调用 · 多少字」，再点一次才真的开跑。它按顺序把每一段当作一段普通原文送去分析（**提示词一个字没改，只换喂进去的那一段字**），每段存一份独立报告。

跑完在报告区顶部出现一张**长文台账**：每行一段，写着段号、字数、以及**那一段自己**的判成什么；失败的那行写着原因并且能重跑，没跑的明说「按停后没跑」而不是留空白。按停之后可以「接着跑」，已经跑成的不重跑。从历史里点开属于某一条台账的报告，整条账会跟着回来（按报告 id 反查）——不然那 N 份报告在历史里就是 N 个互不相干的记录。

台账不做的三件事写在它的「边界」里，也原样写进「复制台账」那份 Markdown 里：**不合并成一条总论证、档位不能相加或求平均、段与段的关系（第 3 段是不是在反驳第 1 段）本地判不了**。跳过也要记账：像问句/口号的段默认不跑，一次最多 8 段，超出的逐条列出理由——不静默截断。台账只存索引（报告 id 与档位），不复制报告正文。

**2. 修订验收。** 修补栏有一个「把这一版填回输入框」：填的是**原文 + 补上的那句前提**，不是「修补后」那一栏——后者是「P1… P2… ∴ C」的重构记号，不是成段的话。填回去只填不跑，你可以先改，按「分析」才花钱。跑完的报告顶部出现对照条：判读档位动没动、未答的检查少没少、有没有「未答变少但硬伤变多」这种需要单独说的情况。对照明确写**只按这副透镜的刻度算**；换透镜、换模式、文本改动太大，它会说「不可对照」，不硬比。每次分析自动存档，顶栏「历史」能回到任何一份。

**3. 五种问法。** 透镜决定「问什么问题」，模式决定「替谁问、判不判」。输入区那一排小按钮就是模式切换：

| 模式 | 类别 | 问的是 | 主输出 |
|---|---|---|---|
| 诊断 | 判定类 | 这段话站得住吗 | 判读档位 + 反驳 + 修补 |
| 红队 | 判定类 | 对手会从哪儿打 | 攻击路线，按杀伤力排序 |
| 查谬误 | 命名类 | 哪些位置对得上教材里的名字 | 名字 + 原文哪一句 + 什么时候其实合法 |
| 重构 | 描述类 | 它的结构是什么 | 主张/前提/支撑关系，不评价 |
| 提问 | 描述类 | 我该问他什么 | 一串可以直接问出口的问题 |

红队是诊断的反方向：同一套型式库、同一套关键问题、同一套刻度，换的是主语——「判读」变成「对手会打哪里」，「反驳」变成「他会怎么说」，「此处合法」变成「打不动的地方」（不是安慰，是省力气）。

**三个模式不给判定档位**（查谬误、重构、提问），`level` 恒为「判不了」，由代码强制（不是模型自觉，也不是解析失败）。理由各不同：先判后画会污染重构——一旦判了「它坏」，重构就会往最弱的读法上靠；判过之后再问，问出来的全是诱导句；而查谬误模式一旦给档位，用户会把「有谬误」直接读成「他说的是错的」，这两件事差得很远。

三个模式的清空范围不同：重构把「反驳」与「命名」都清空（攻击属于红队，命名是评价）；提问**保留**「反驳」并换语义——claim 是问什么、script 是可发出去的原话、steelman 是他最可能怎么答、reply 是你接着问什么；查谬误清空「反驳」，但把「命名」升为主输出，并加一条硬裁决：**每条名字必须指得出原文哪一句、落在哪条检查项上**，缺一样就丢弃并写明丢的是哪一条。说不清是哪一句的名字只是贴标签——用户拿它去对质，第一句就会被问「我哪句话这样了」。

五种模式的提示词都完整可见（`docs/prompts/` 下 30 份，可 diff），互不混装。「可 diff」现在不是一句宣称：`check:prompt-drift` 在每次 `verify` 里把三十份全文、指纹索引表与 `BASELINE.json` 和现场装配逐字对一遍，改了内核却忘了重导出会当场红；`prompt:lock` 在写基线之前拦下「改了内容却没换版本号／没留一行注记」。三步改提示词的完整流程与它守不住的东西写在 [提示词工程](docs/提示词工程.md)。这一轮**一句提示词都没改**——改内容需要真模型评测，余额仍为空。

**「这把尺子」把版本注记交到人手上。** 报告脚注里那个孤零零的 `v2.5.0 · 指纹 …` 回答不了三个月后回看的两个问题：那一版和现在差在哪、本机还有没有那一版的全文。报告末尾现在有一栏，逐字列出该版本在 `PROMPT_VERSION_NOTE` 里留下的那一行注记，并把报告的版本与指纹对回**当前装机版**这一组合（`透镜.模式`）：一致 / 另一版 / 没记版本 / 版号同而指纹不同 / 本机没这个组合，各写各的话。注记全文来自上一轮已经强制留痕的 `docs/prompts/BASELINE.json`，界面、Markdown 导出、`check:prompt-history` 读的是同一份落盘事实，界面不自己解析版本号、不另抄一份注记。最关键的是三条边界摆在同一屏：**本机只留有当前装机版的全文与 30 份指纹，更早版本没有存档，所以旧指纹不能在这里重算一遍**；注记是「当时为什么这么改」，不是效果评价；指纹只能证明当时算过，证明不了那次判定对不对。版本不同时**不比**指纹——拿今天的指纹去比旧报告，比出来的「不一致」是废话，还容易读成旧报告坏了。软件不判哪一版更好、不改任何判定。预览页 `?ph=old|none|unknown|mismatch` 是四种状态，真机截图在 `scripts/.out/prompt-history-real.png`。

**4. 异议。** 工具承认「学科有争议」，也该承认「这个人不同意」。判读、每一条检查、命名候选、此处合法，下面都有一个「不同意」：理由可写可不写。它**只记录、不改判**——报告按它自己的标准写，你保留不同意见。历史面板里能看到你反对过什么；同一个位置反复被反对，就是这个工具最可能出错的地方。如果你发现自己在每次分析里都点「不同意」，该怀疑的是这副透镜，不是每一段话。

回看工作台里的异议还能**钉在具体位置**：默认跟随右侧检查器选中的字段，也可以点原文某一句行尾的「钉在这句」。每条异议因此带着字段路径或句号与引文，点徽标就回到那一处；底部「异议地图」列出这台机器记过的全部异议，按跨报告身份归并，点一条能打开那份报告并定位。锚点只写在 `objections.jsonl` 里，不改写报告、不重新分析、不新增判定。老版本没记位置的异议如实显示「未锚定（旧版）」，不给它编一个位置。同一处只保留最新一条；换字段或换句子才能留下多条——这个限制写在锚点条上，不藏在代码里。

**回看台的检查器也说人话。** 点任意一处，右栏同时给中文名、原英文键名和取值；`weakened`、`proponent` 这类标签旁边有彩色中文，问号悬停出一句解释。中文名与解释取自主程序的 `src/renderer/src/glossary.ts`——`npm run gloss:sync` 把它生成进工作台内联词典，`check:gloss` 每次 `verify` 都核一遍，防止两处说法慢慢说成两件事。**这些中文是工作台加的阅读说明，不是报告内容、不写回报告**；没收录的字段如实写「暂无解释」并保留原名，不编。最下面「原始 JSON」默认折叠、随时可展开逐字取证。三个按钮接的都是已有功能：把异议钉在这处、看完整字段表、去全库检索。状态栏与资源管理器里那些裸数字也补了来由（来自存档索引、不是新跑出来的结果），样张只带部分索引时不再谎称「全量」。

**存档坏了，历史会告诉你。** 以前一个写坏一半的报告文件、一条找不到文件的索引、一次索引损坏，都走 `catch → null / 空表`，界面只会说「还没有报告」，或者点了某一行屏幕毫无变化——文件明明还在磁盘上，软件却替你判了「没丢」。现在打开「历史」会先做一次**只读体检**：报出几个文件读不出来（区分「读不了 / JSON 写坏了 / 能解析但不像报告」）、索引里有几条是幽灵行、磁盘上有几个文件没进索引，逐条给出文件名与原因；索引在本会话坏过、列表已从磁盘重建，也会如实说。目录整个读不出来时不显示任何「0 份」，因为那不可信。点在历史里的一份坏报告上，会按探测结果说清是文件不在、被占用、写坏了还是缺字段。**体检不删、不修、不覆盖任何文件**——要恢复得从你自己的备份拷回来，界面只给「打开报告文件夹」这个入口。回看工作台的状态栏也会提示存档对不上；样张没有本机数据时什么都不显示，不会反过来宣称一切正常。这道边界由 `check:archive` 每次 `verify` 守着。

**一百多份之后，历史有了检索。** 列表里只有每份报告开头 72 字，按摘要找等于只允许人找第一句；而人记住的常常是中间那个词。搜索框每敲一个字就在本机扫一遍存档（延后 220ms，输入不卡），找的是**原文、结论、前提、中间结论、修补、检查依据、判读**七类文字；每份报告只出一条结果，写清「哪一类、几处」，片断逐字摘自报告（连续空白折成一个空格，字不改），命中的那几个字加底色。三条边界写在搜索框下面而不是藏进文档：**按字面找**——不认同义词（搜「晨读」找不到「早读」）、不认拼音、不做词形还原；**多个词是「都要有」**，且每个词可以落在不同字段；**模型写的其余解释**（自检、诊断、命名候选、反驳）不在范围内——不是那些不重要，是本地没有稳定取法，混进来会让「命中」说不清。结果**不重排**：先后仍是时间，相关度本地算不出来，按它排等于替用户判断「这份更像你要找的」。两句话分着说：「一份都没有匹配（在 N 份里按字面找的）」与「另有 N 份读不出来，它们不在结果里」——合成一句就变成「确实没有」；命中但不在列表里的文件（索引与磁盘不同步）也会单独说。这道边界由 `check:after`（98 → 155 条）与端到端九条守着。

## 使用

### 阅读层级：默认简洁，随时切回完整

一份报告有二十几栏。全摊开时它们看起来**等权重**：结论、流程账、命题账、边界、自检、提示词版本挤在一屏里，第一次打开的人不知道先看哪一块。所以真应用默认「简洁」：只把**结论链**一直展开（四句话、结构图、逐关检查、此处合法、判读、反驳、修补、下一步……），**核对层**（全流程账、骨架缺口、专题、学术、命题账、枢纽、争议、边界、语境坐标、透镜专用面板、自检、分歧账、这把尺子、程序裁定）收成一行标题，点栏名即展开；报告第一行有「简洁 / 完整」两个按钮，切到完整就是原来那一页，一栏不少、顺序不变。左栏那一整面透镜说明书同样收成一行（点开看尺度、失效条件与出处，字一个没少），顶部六张理论卡只留名字。

收起的只有**屏幕上的内容**，不是数据：折叠靠 CSS 的 `display: none`，`children` 照常渲染，所有 `data-*` 探针、复算与按 DOM 取数的检查都在；**报告、存档与导出的 Markdown 一个字不变**。从四句话或「跳到」点进收起的栏，会自动展开那一栏再滚过去。选择存在本机 `localStorage['al:density']`，只影响显示，不进报告、不改判定、不碰提示词。三条边界写在工具条的「边界」里，一句不许删——「收起了」最容易被读成「报告少了内容」。

有一处不是显示、但是同一次改动里必须说清的：**打开一份新报告不记阅读位置**。报告的第一栏在滚动容器里并不在 0 像素处，而简洁态下一个区块只有一行标题，两三个标题能一起挤进顶线——「当前是第几节」在刚打开的那一帧就会算成第 2 节。照那一帧记下去，一份一秒前才生成、谁都没读过的报告，重开时会端出一句「上次读到第 2 节」；这句话没有第二处能核对，所以规则改成：打开时只摆高亮不记账，第一次滚动只当基线，回到第 1 节就把作废的那条撤掉。

预览页与端到端冒烟**默认完整**：几十张既有截图和一百多条按展开态写的断言都建立在这一态上，冒烟会真点一下「完整」按钮（顺带验它一栏不少）。简洁态另留一条跑道 `SMOKE_DENSITY=compact npm run smoke`，验的是收起真的发生、点栏名真的展开、以及收起前后正文一个字没少；预览页 `?density=compact` 拍同一页的简洁态。`check:density` 守清单与接线的同源：主线栏不许进收起清单、归层只许用 `@shared/ui-density` 那张表、折叠不许改成条件卸载、默认跑道不许忘了切回完整。

窗口窄到应用的最小宽度（1080）时，栏名不折行、副标题去让位——栏名是这一栏的坐标，断成两行就认不出来；简洁态里被省略号截断的两句长说明都带 `title`，悬停能读全文（截断而没有 `title`，等于把话删了）。窗口宽到 1920 时内容收在 1240px 以内，卡片不会被拉成横带。**说清这条不做的事**：它不是「行长刚好」，12.5px 字号下 1240px 仍排九十来字，正文偏长是全局排版的事，记在路线图的 P2 里。

**没验的**：没有真人样本证明简洁态「更好读」；也只看了 1080 / 1500 / 1920 三种窗口宽度与 100% 缩放，高 DPI 与系统缩放没看过；它只是一次显示层的减法，判断质量、提示词效果与真模型评测一概没有因为这次改动被验证过。

### 安装

- `dist/ArgumentLens-Setup-0.1.0.exe` — 安装版，可改安装目录，建桌面与开始菜单快捷方式
- `dist/ArgumentLens-0.1.0-portable.exe` — 便携版，单文件，双击即用

Windows 10/11 x64。首次启动会引导接入模型。

### 第一次用：示例是六段，按一次换一段

输入框右下角那个按钮会轮换六段不同体裁的话：校园讨论、带货文案、新闻评论、研究摘要、职场管理、养生帖。每段埋的毛病不一样，所以连按三次会看到三份形态不同的报告。

**为什么不是一段。** 以前它只有一段，「再试一次」永远得到同一段：按钮上写着「填入示例」，按下去还是那句话。存档里那一百多份报告，绝大多数就是同一段文字——那不是一百个样本，是同一个样本跑了一百遍。它证明的是软件稳定，不证明判断准。

示例只用来试手。**真正要验的是你自己手里那段话**：广告、领导的通知、群里转的养生帖、论文的摘要。同一段文本反复判，得到的会是同一份报告。

框里已经有你写的字时，这个按钮会先变成「覆盖原文？」，第二下才真的替换——输入框没有撤销，覆盖掉就没了。

### 这一段是不是已经跑过

同一段文字再跑时，分析按钮下面会出现一行：

```
这段文字已经跑过 89 次（最近一次：11 月 2 日 16:00），另有 8 份只差几个字。
重跑一次能看出模型会不会换说法；要看新的东西，得换一段文字。
```

它比的是**字面**重合，不是哈希：改了几个字、加了一两句的改稿也能认出来（真实存档里那 8 份就是这样）。没有这一行，就等于默认「你每次都换了新文本」——而实际存档里 102 份报告只落在 6 组文本上。

它不拦人。同一段文字跑两遍，差多少正是模型稳不稳的证据，那恰恰是这个项目缺的东西之一；所以它只把次数和时间摆在你面前，跑不跑由你定。截图 `docs/screenshots/same-bar.png`。

### 这台机器上到底试过几种文字

按钮下面还有一行「样本账」：本机存了多少份报告、落在几组**不同的文字**上、最多的那组几份、只跑过一次的有几组。点「看明细」能展开每一组（份数、最近一次时间、原文开头二十来字），并把这份清单复制成纯文本带走。

这件事只有本地软件做得到：裸提示词、云端对话都不可能知道你之前跑过什么。这一栏和「这段跑过没有」一样，文字全部来自本地存档，一个字都不来自模型——报告里其余的长句几乎逐字来自模型返回的 JSON。分组沿用上面那套字面重合口径：逐字相同、只差一两句的改稿归一堆；原文为空、文件读不出来的都单独数在总述里，不会被当成「没有」。

它只数事实：不评价样本够不够、不劝你换一段、不给分，也不排优先级。截图 `docs/screenshots/portfolio.png`（左侧栏特写）。

### 同一段字跑了很多遍，报告一样吗

样本账下面还有一行「同题复跑」。它回答样本账的下一个问题：那一组文字里的几十份报告，彼此是什么关系——**同一段字跑十遍，得到的是十份一样的报告，还是十份不同的？**只有本地存档答得了：裸提示词、云端对话都不保存你上次跑的是什么。

分组很严：**同一版提示词指纹、同一副透镜、同一个模式、逐字相同的原文**，四件事同时相同才算「同一次输入」。少任何一条都会把别的东西读成「模型这次说得不一样」——提示词改过一版、换了透镜、原文加了一句，报告当然变，那不是抖动。所以它不沿用样本账的「几乎同一段」口径：那 8 份加了句子的改稿在这里与原文是两组。

比的是字段：多少个每次都一样、多少处变过、每种取值出现几次。没有指纹的旧报告不参与比对（份数写在总述里），没有可比字段的组不会被告「每次都一样」。它不算百分比、不评「稳定」、也不解释差异从哪来——存档没记模型名和温度，所以「模型每次说得不一样」与「你当时换了模型或设置」在这份数据里分不开，这句话就写在那一栏下面。还有一层更根本的：报告一样不等于判断对——同一版提示词反复给出同一份报告，也可能每次都错在同一处。截图 `docs/screenshots/agreement.png`（左侧栏特写）。

### 这份报告是谁跑出来的

每份新报告里多记一栏：模型名、供应商主机、**实际执行的温度**。看着像记账，其实是上一栏缺的那块拼图——同题复跑第一次跑出真数据时，v2.0.0 有一组 8 份报告相差 279 个字段，而那批存档里没有模型名也没有温度，于是「模型这次说得不一样」与「你当时换了模型或设置」永远分不开。差异被看见了，却解释不了。

三条规矩：**三项齐全才写**（缺温度就整条不写——半条记录会让读的人以为温度也是同一个，比空着更误导）；存主机不存接口地址（报告会被导出，路径与 Key 不跟着走）；存的是**裁剪之后真正发出去的温度**，不是设置页里填的那个（被模式上限压到 0.2 却记 0.7，等于给自己留一条假的证据）。

旧存档没有这一栏，显示「没记模型」，不回填——补出来的模型名会让一份跑在旧模型上的报告自称跑在新模型上。记了也只到这里：**同一个模型名不等于同一个版本**，供应商什么时候换权重，这份存档不知道。它不进重放比对（重放不重新发请求，环境不是产物），也不进同题复跑的字段计数（换了模型之后报告变没变，正是那一栏要量的差异本身）。

### 两份摆在一起，看哪一处动了

「同题复跑」给的是一个数字：这一组 8 份里有 268 处字段变过。数字是真的，但它说不清一件事——**变的是 268 个地方，还是一份整个重写、七份一模一样？**

这两句话完全不同，而它们给出同一个数字。所以那一栏的每一组后面多了几个号码（1 是最近一份），勾两个，点「对照这两份」，两份报告就逐处摆在一起：左边甲、右边乙，段落按报告的读法排（结论 → 前提 → 检查项 → 评级 → 修补 → 反驳……），每一条差异都带着两边的原文。

顺手查了一下本机那 268 处是怎么来的：那 8 份里，**7 份逐字相同，第 8 份是另一个东西**（7 份的 JSON 是 6.9 千字，那份 9.7 千字）。汇总数字把「1 对 7」说成了「到处在抖」。这不是模型抖，是一次换了东西跑；而在此之前，这份数据只能在纯文本里翻。

三条边界：**缺失与不同分开**（甲有乙没有，和两边都有但写得不一样，是两件事；缺的那一侧写「这份里没有这一栏」，不写空，空串会被读成「内容是空的」）；**四种「没有」各有各的写法**（字段不存在 / 值是 null / 是空字符串），它们在界面上长得很像，含义完全不同；**四项各自说**——原文、透镜、模式、提示词指纹，任一不同就把那句话写在表格**前面**，否则「换了透镜」会被读成「模型在抖」。它也不评哪一份更对，不排「差得多」的顺序：排序即评价。

按 id 对齐，不按下标。实测本机 9 组重复报告里，同一段的检查项、前提、反驳的 id 与顺序都一致；但按下标对齐只要模型重排一次，整张表就红成一片假差异——那不是两份报告的差异，是对齐方式的差异。没有 id 的元素退回按位置对齐，路径里带 `#`，不冒充成有编号。截图 `docs/screenshots/sideby.png`。


### 结论那句话说重了没有

结论是模型整理出来的，它可能比原文那句话更硬：原文写「可能」，报告写成「一定」；原文说「这说明」，报告直接写成一个断言。

这一块**不采信报告自己的判断**，本地把两句话的字面各读一遍——原文那一句（报告引用的原话）与报告那一句（整理后的结论），按三张词表对：软化词（可能、大概、未必）、硬化词（一定、必然、显然）、因果词（说明、因此、导致）。哪里对不上就列哪里，附上两边的原话，**不判谁对**。

- 软化词一律**长词优先**：「不一定」不会被读成「一定」。四张表共用一份占位记录，否则同一句话会被读成两个相反的口气。
- 报告自己也有一个自评（`modalOverreach` / `modalNote`），此前在界面上从没显示过。现在把它印出来，和本地读到的并列——**两边都说有差别，不等于指的是同一处**，这句话也写在界面上。
- 读不到就说读不到：报告没给原文引文、全文里也找不到对应的一句（或找到的句子一半以上的字都对不上），这一栏写「比不了」，不猜。
- 这一栏不动报告的一个字，也不参与判定。

### 骨架缺口：这份报告把结构接上了没有

前面那些栏都在报告**之外**加东西。这一栏是本地第一次对报告本身说一句「这里接不上」，而且每条都标了**是谁说的**：

- **本地数的**：原文有几句没有任何一条主张、命名或「此处合法」落到上面；依据之间有没有绕成环（A 支撑 B、B 又支撑 A）；一条前提都没列；透镜说了「不适用」却把检查表填上了。这些模型算不出来——它不会回头数自己漏读了哪句。
- **报告自己说的**：检查表里那几条 `unanswered`。它在提示词里的意思是「文中无从判断」，是模型**指认这一环原文没交代**，不是模型漏答。界面上同一栏也写着「答『未回答』不是漏答」，两处说法必须一致，否则你不知道该信谁。

每条缺口带你去看具体位置：没碰到的原句片段、环上的 id、检查项编号。缺口清零时写的是「按这几项查，没找到缺口……只说明骨架接上了，不代表判断对」——**不说「没问题」**，判断对不对本地核不了。下面另有一排纯数字：结构连线几条、原文里几处推理连接词、检查表四档各几条。连接词只数出来，不参与判断（一个「所以」可能承前跨几句，与图上的线不一一对应）。

这一栏不评价内容、不改判定、不动提示词。`check:skeleton` 守语义与来源分开，端到端 11 条守界面接线，截图 `docs/screenshots/gaps.png`。

### 每一句话，是从哪一句原话整理出来的

报告里每条主张都有两行：整理后的那一句（`text`，可检验的命题），以及它引的原话（`quote`）。**这两句几乎从来不一样**——2026-11-09 量本机 103 份存档：407 条主张里 406 条被改写过，其中 308 条能读出连续的字面改动。此前界面把两行并排放着，改动本身一个字不提，得自己一行行对。

现在每张主张卡上、原话那行的正下方，本地把两句逐字比一遍：原话几个字、这一句几个字，哪些连续片段在原话里有、这一句没接上，哪些在这一句里、原话对不上。例如原话「这说明取消早读是错的」→ 整理成「取消早读是错的，应当恢复早读」，本地列出没接上的「这说明」与对不上的「应当恢复早读」。**片段逐字来自那两行**，不改写、不加解释。

- 用最长公共子序列切片段，不是按下标对齐：中间插两个字，后面的字不该全被算成改动。单个字和纯标点不算一处改动；只差一个字时明说「读不出连续的片段」，不给一张空表。
- 四种「比不出来」各有说法：没引文（隐含前提）、两句逐字相同、只差单个字、超过 400 字上限。前两种整块不显示，也不写「0 处」。
- **只列字面，不判改写对不对**，也不替你挑「最值得看的那一处」。界面上那行说明写死了这句话；`check:rewrite` 守它不许变成判断。
- 与「结论那句话说重了没有」不重复：那一块只比**结论一句**的四类口气词；这一块比**每一条主张**的全部字面改动，贴在正文里，不另起一栏。

这一块是显示报告时实时算的，**不进存档、不进导出、不改任何一个判定点**。截图 `docs/screenshots/rewrite.png`，预览页 `?rewrite=1` 可直接滚到它。

### 哪些图，你自己挑

报告开头「四句话」下面多了一条：**这次看哪几张图**。点开是一张清单，五张图各自写着它回答什么问题，勾上就显示，勾掉就收起来。

五张图里，前三张（结构图、逐关检查、判读刻度）默认开着——和这一层出现之前一模一样，升级不会改变你的阅读顺序。后两张是这次新加的，默认关着：

- **反驳落点**：每条反驳打在哪一处依据上，一处被打了几条、什么打法。实心方块表示这条挂到了具体关卡，空心表示只打到那一处——空心的那些不在少数，图上一眼看得出来（具体条数写在那张图下面的统计句里，随报告变，不抄进文档）。颜色只按打法分四类，不分强弱。
- **修补对照**：左边是现在的链，断在哪一步；右边是补上缺的那一句之后，这条链接不接得上。虚线框是**补出来的**，原文没有那一句。右边那个结论框和左边对齐，因为它就是同一个结论。

三条规矩，都是为了让「没画」和「画不出」分得开：

1. **画不出的图照样列在清单里，并写明原因**——「这段没有拆出可用的前提」「这副透镜判了不适用」「这份报告没有生成反驳」。直接过滤掉，你会以为是功能坏了。
2. **关掉的那张不整栏消失**，留一行「这张图你关掉了」加一个就地打开的按钮。因为顶上目录里的「结构图」还指着它，整栏删掉点了会落到空处。
3. **全关是允许的**。写「图 0/5 · 你把图都关了，文字照常」，不替你把图恢复回来——那等于没给你选。

选择存在本机（同一台机器的同一个用户目录），下次打开还是这次的选法。它只影响显示，不改报告内容、存档与导出。透镜产物图（图尔敏布局、ARS 缺口图那几张）**不在这条选择条里**——它们跟着透镜走，是那一栏的主体，不是可选的附加图。截图 `docs/screenshots/views.png`（选中状态）、`refute.png`、`repair.png`。

### 读完报告，回到原文

报告最上方有一句「回到原文重读」。点开是**换一整屏**，不是在报告末尾再添一段；点「回报告」就回到原处。

这一屏把原文按句摆出来，每句下面挂着报告里指着它的条目：主张、命名、此处合法。三件事值得留意——

- **原文一个字没改。** 句子是原样切片，连空行和结尾换行都在；条目文字逐字引自报告里已经写下的字段。
- **同一句上的分歧不合并。** 一句可能同时被「命名」点着、又被「此处合法」判定为站得住，两条并排留着；谁都没提的句子会明说；没能指回原文位置的条目也逐条列出来，不替它们猜一句。
- **不跑模型、不花钱。** 切句复用谬误落点图那套纯函数，位置由 `span` 或恰好出现一次的引文算出，可复算（`check:reread` 守着）。

为什么做成这样：翻过真实存档后发现，报告里的长句几乎逐字来自模型返回的那段 JSON，本地只贡献了落点下标、名录统一与按模式删栏。再让模型（或本地）生成一段「解释」，得到的仍是一份生成好的东西。**这一屏不新写一个字的判断**，只把已经写下的东西换个摆法：原文没变，变的是读者能看见什么。截图 `docs/screenshots/reread.png`。

它不改变判断质量，也不回答「比直接把提示词贴进对话框强在哪」。那要人把模型原文与本软件并排盲看才答得了——见「已知限制」。

### 换个尺度，再读一遍

报告最上方还有一个「换个尺度读」。点开同样换一整屏：你填几组「把原文里的某个词 → 换成什么」，本地就在原文上做**字面替换**，其余一个字不动，两句并排放着。

- **词由你填。** 软件不预设「这段话该换什么」，不猜哪个词是主体，也不做同义扩展。换出来的字不会被第二次替换；跨句的、重叠的、没找到的，都逐条说出来，不静默吞掉。
- **差异可归因。** 统计条写清「替换 N 处 · 其余 M 字未动」；编辑记录能逐字逆变换回原文（`check:rescale` 守着）。每句下面挂着的条目仍是报告里的原话，没有跟着换——换过之后它还成不成立，由你自己看。
- **用的是这份报告当时分析的原文**，不是输入框里现在的字。两栏同字号同排版，免得把好看的那一栏误当成更好的那一栏。
- **不跑模型、不花钱、不动提示词。** 真模型评测没因此重跑（余额仍为空）。

这一招来自知识库里《哲学，有用嘛？》那期：简化问题的情境、保留逻辑结构，让复杂问题里不容易察觉的推理缺陷变得清晰。工具能做的是把尺度换好、把没换的地方交代清楚；「视频没变，变化的是我们」那一半，脚本验不了。截图 `docs/screenshots/rescale.png`。

### 自己列成立条件

第三个按钮是「自己列成立条件」。这是三个重读里**唯一一屏不显示报告文字**的：主区只有原文和你自己写下的东西，报告整块让位。

- **条件由你写。** 「要让这段话的结论站住，得先满足什么」——先自己写下来，再回原文逐句找它给没给。软件不替你列，不预设这段该问什么，也不替你判哪一条满没满足。
- **依据由你点。** 每条条件可以挂到原文的某一句上；挂上去的是那一句的原样切片，带原文坐标，逐字可核对。同一句可以挂好几条，行的顺序不重排（不替你排优先级）。
- **结论由你勾。** 三态「还没想好 / 原文给了 / 原文没给」全是你自己的标记；点「原文给了」不会让界面说这一条成立。软件只数「写了几条、标了几条、几条挂到了原文」，**不算分、不给总结论**。
- **没被问到的句子单独列出来。** 那只是「还没人问」，不是说这几句不重要；点了句子却没写条件、或点了不存在的句子，也逐条说出来，不静默丢掉。
- **不落盘。** 关掉就没了，界面上写明；要留就选中底部那段纯文本自己复制走。不写文件，也就没有「写失败」那一层，代价写在同一屏。

知识库那一层里最像工具的一招是「必要条件清单」：把看着天经地义的结论拆成几条能逐条去问的条件。力量来自**条件是自己列的**——这一屏把它做成一个下次能自己重复的动作，而不是又一份生成好的清单。`check:conditions` 守着原文逐字还原、引文坐标可复算、内核不写判断也不算总分；端到端守着填进去的字真的被本地重算。截图 `docs/screenshots/conditions.png`。

### 读完报告，你下一句想说什么

报告的最底下（所有板块之后）有一个空框。写一句，点「记下」，或者按 Ctrl+Enter。

- **不分析这句话。** 不判它是在提问、在抱怨还是在要一个结论，也不给选项——选项会把人往几个预设的说法上赶，而这一栏要记的正是「人自己会说什么」。
- **原话逐字存。** 只去首尾空白，中间一个字不动；「所以呢」和「所以呢？」是两句，不合并。同一句话记两次就是两条，不去重（去重会把「手抖点两下」藏起来）。
- **只数一件事：逐字相同。** 本机记了几句、其中几组一模一样、最多的一句出现了几次。同一句话重复十次正是这一栏最该显示的东西；它空不空泛，由读的人判断，不由这一栏判断。
- **只在这台机器上。** 存在 `userData/nextlines.jsonl`，不进报告、不发模型、不上报；每一条都能在明细里删掉（删之前会再问一次）。写不进去会当场说，不会显示成「记下了」。

为什么是这个位置、这个形状：路线图第四节那条判据——十段真实文本，只记「看完之后下一句是什么」——写了很久一直零输入，因为软件里从来没有一处地方收这句话。前面三屏再怎么换摆法，回答的都是「软件给了什么」，不是「人接着说了什么」。这一栏是唯一一处由人写、软件只负责原样保管和计数的地方。它长在报告末尾而不是开头：放在开头，等于在人还没读的时候先要一句评价，那样收上来的字回答的就不是这个问题了。截图 `docs/screenshots/nextline.png`。

### 在别处读到一段话，直接叫进来

复制它，按 **Ctrl+Alt+A**（macOS 上是 ⌘+⌥+A）。窗口会到前台，剪贴板里那段字落进输入框——不用先切窗口、再粘、再按分析。

三条边界，都在界面上写着：

- **读的是剪贴板，不是你鼠标选中的那段字。** 抓别处的选中文本要模拟 Ctrl+C，那会改动剪贴板、可能触发粘贴副作用，而且没法在无人值守的环境里验证真的抓到了。宁可要一个确定的剪贴板，不要一个不确定的选中。
- **框里是你自己写的字时，它只问、不换。** 弹一条「要用剪贴板里这 N 字替换吗」，你点了才写。框是空的、或框里是示例，才直接填。
- **超过 12000 字不填，也不截断。** 截断等于替人改原文，而报告里每条判定都挂着原文引文，引文对不上原文比不给分析更坏。会明说「有 N 字、上限 M 字，先选一段」。

这个键被别的程序占着（截图工具、输入法快捷短语都常见）时，输入框下面会直接写「没启用：……被占用了」，而不是留一行「按 Ctrl+Alt+A」让按键永远没反应。

### 接入模型

自然语言的论证拆解没有规则可循，这一步必须靠大模型。除此之外的部分都在本机跑：六套提示词、型式库、谬误判据、原文定位、全部程序裁决。**换一个模型，镜片不变**——「镜片」指提示词与本地规则，不等于报告里的字：`npm run audit:provenance` 当场给出的来源账是 98.0% 的 ≥12 字字段逐字来自模型原文、本地独立产出的判定点占 4.8%，十一道裁决只在输出越界时纠偏（实时数以命令输出为准，不写死在文档里）。**判断由模型写出，软件不独立判定「站不站得住」**——这是 2026-11-12 定下的产品定位（[产品定位](docs/产品定位.md)）。真模型评测（P1-2）回答的是另一个问题：这些判断**对不对**；它还没跑，不因为定位收敛就算跑过。

### 架构边界：写进断言，不写在文档里

2026-11-09 量过一次：`src/shared/` 与主进程 / 渲染层之间本来就零违规，`flatten`、`bigrams`、`dice`、`normalizePassage` 也早已共用，CSS 变量只有一处 `:root`。问题不在这三层，在另外两处：

- `Diagnosis.tsx` 把报告主体与三块「换整屏」的界面塞在同一个文件里，而 `AGENTS.md` 写着「界面组件，一人一块」。三块整屏（回到原文、换个尺度、自己列成立条件）各自只依赖 React 与自己的 `@shared` 模块，**不引用主文件里任何其他函数**，于是整体搬进 `components/RereadScreen.tsx` / `RescaleScreen.tsx` / `ConditionScreen.tsx`，主文件只留报告主体。这是纯搬移：**DOM 一个字没改**，报告、导出、存档、判定全不动。
- `EXCERPT_LEN` 原本在 `@shared/agreement` 与 `@shared/portfolio` 各定义一份，注释还互相写着「与那一栏同长」。现在只有 `@shared/excerpt` 一个家，两处都从它读。

更要紧的是：上面那些干净边界此前**只写在文档里**。`AGENTS.md` 有一句「`src/shared/` 不许 import electron」，但今天零违规、明天加一行照样全绿——而纯函数从此不能在纯 node 里跑。新增的 `check:arch` 把它们变成会红的断言：分层方向、值 import 不成环、同名常量只有一个家、`:root` 唯一、三块整屏不回巨石、组件数冻结线。每条都做过「改坏一处 → 点名那条红」的反证，包括把检测正则改坏后确认违规不再被抓到。

**边界**：它只读源码、只认静态字面量 import；动态拼出来的路径与 `import type` 造成的类型环不在它守的范围。组件数那条是**冻结线不是目标**——只允许继续拆，不允许继续往巨石里塞。拆分本身没有逐字 diff 作证，靠的是 typecheck、全量断言与端到端探针（三块整屏的按钮、DOM 探针、包内接线）保持不变。

### 数据契约分三层

`context / scope / 重构`（六副透镜共享）→ `checks`（统一：六副透镜都归约成「检查项 + 回答」）→ `lens`（分区：型式 / 规则 / 三特征 / 六要素 / 名录，互不通约，不许压成一个字段）。

`verdict` 同时保存**原生刻度**与归一化档位。「CQ2 未答，属削弱性击败」和「被削弱」都要显示——只显示后者，等于把六套理论压成一个仪表盘。

## 已知限制

- **定位边界：判断不是软件下的。** 报告里的评级、可接受度、举证责任、检查项答案、反驳由模型写出；本地只做原文定位、字面比对、结构核对、越界纠偏与计数，不独立判定这段论证站不站得住。`npm run audit:provenance` 当场给出两种口径的来源账与本地占比（实时数以命令输出为准，脚本自带「不能推广到别的文本」的边界）。这条不是待修的 bug，是 2026-11-12 定下的产品定位（[产品定位](docs/产品定位.md)）；它**不提供**「判断对不对」或「比裸提示词强」的证据——那要真模型评测，以及人当评判者的并排盲看。
- **「全流程账」只数做没做，不判做得对不对。** 二十步（A–D 十三步、F 三步、E 四步）逐条对一遍，本地能看到的只有数据结构里有没有落点：立案卡填了没有、前提有几条、结构形状读不读得出、命题够不够两条、检查表答没答过。至于「取的是谁的主张、取全了没有」「这个前提承不承重」「反方最强一击是不是真的最强」，本地算不出来，一栏里全部写成「本地看不出来」，不写「已通过」。档位（速判／标准／全场审计）是本地按原文长度与「结论 + 中间结论」条数估的，不读《论证分析全流程》里的原话；估偏了只会把某几步写成「这一档不走」——**宁可少说做过，不多说**。三处写明的空白：「分流」（一个主张撑多个子结论）在数据结构里无从体现——一份报告只有一个结论字段，要判它得先让报告装得下多个子结论，所以这一行不假装判了；全场审计的「主张台账」只提一句，没有虚设第 21 格；顺序违规只在「A 没做完 + 后面已经有做完的步」时才说那一句「判在立案之前」，A 做了一半（只填了说话人）不报——报了一半的错会让人以为剩下的都合规。立案卡本身也是人填的：软件不猜作者、不认转述、不跨报告沿用，原文一改就作废（拿旧立案解释新文本，比没有立案更糟）。`check:flow` 的 156 条与 `check:divergence` 的 145 条能证明：档位抹掉做过的步会红、顺序违规恒空会红、`objectKind` 默认成「说理」会红（那会让 A2 永远显示做过）、界面与导出件调同一个 `flowOf`、四字段全空时不落盘、点「走这一步」真的展开那一节、速判档里人真登记了分歧账时档位不会把做过的事抹成「这一档不走」。F 段尤其只数填没填齐：坐标填齐不等于判据选对了，收敛条件写了不等于它真可观察。端到端能证明真机上二十行都在、填了立案 A1/A2 变「做过」、没填时 A2 是「缺」而 A1 按档位落；`SMOKE_DIVERGENCE=1` 那条跑道另外证明填齐分歧账后 F 三步与 E4 都变「做了」，没填时那一栏明说「没有分歧账」。证明不了的是两件事：真模型报告上这一栏读起来像不像一份流程审计（余额为空，假模型的报告只落在速判档），以及人多半会把它读成成绩单——所以这一栏里不出现分数、百分比和及格线，那一句「走了 N 步」后面永远跟着「几步这一档不走」（具体几个数随文本变，看总述那一行，这里不抄）。
- **样本账只数字面，也不知道你看完之后的下一句。** 同一段话彻底重写会被算成新的一组，两段只差几个字反而归一堆——它量的是字面，不是「是不是同一个论点」。这一栏能告诉你试过几种文字，不能告诉你它们有没有用——那件事归报告末尾的「下一句」管，两者互不相干。`check:portfolio` 与端到端能证明顺序无关、摘录逐字、空原文与坏文件不被吞、导出里没有本地新写的判断；证明不了这些数字会让人换一段真话来跑。
- **「同题复跑」只在有提示词指纹的报告之间比，而且分不开差异的成因。** 分组要四件事同时相同：提示词指纹、透镜、模式、逐字原文——少一条就会把「换了输入」读成「模型这次说得不一样」。本机 103 份里有 27 份旧报告没有指纹，它们没有参与比对（份数写在总述里），因为把「可能换过提示词」当成「同一版」会让差异看起来像抖动。它也不沿用样本账的相似度阈值：那 8 份加了句子的改稿与原文 dice 是 0.88，样本账会把它们并成一组，这里必须分开。比的是字段：几个每次都一样、几处变过、每种取值出现几次——不算百分比、不评「稳定」、不指出「最该修的那一组」。边界分两层，而且第二层已经动过一半：新报告会记下模型、供应商与生效温度（见上一节），所以「这一组里换过模型」现在看得出来，总述与明细都会点名；早期存档没有那一栏，那几组仍然分不开「模型每次说得不一样」与「你当时换了模型或设置」——份数写在总述里。记了也不等于知道全部：同一个模型名背后是不是同一版权重，存档不知道。这两句话都写在界面上，因为它们决定了那些数字能被读成什么。还有一层更根本的：**报告一样不等于判断对**——同一版提示词反复给出同一份报告，也可能每次都错在同一处。人填的立案与 v1.1 分歧账同属输入，与身份字段一样不进比对——第二遍才补填分歧账时，界面不该把那十几处 `divergence.*` 说成模型抖了。`check:agreement` 与 `check:engine` 能证明：四件事分组、身份字段不算差异、顺序打乱后账不变、缺失字段与数组长度各算一条路径、没有可比字段时不说「一样」、没参与比对的份数不被吞掉、导出里没有本地新写的评价；以及「谁跑的」三项齐全才落盘、温度 0 不被当成没填、换过模型会被点名、这一栏不进重放差异与字段计数。端到端能证明的是另一件事：同一段字真的跑了两遍之后，界面把两份摆到一起、遍数与存档索引对得上、显示的是新账（跑完第二遍不刷新，它会继续显示第一遍那句话，而那句话读起来完全正常）。证明不了差异的成因，也证明不了「一样」等于「对」。
- **「两份对照」能证明两份报告哪里不一样，证明不了不一样意味着什么。** 它比的是摊平后逐路径的值：一个字段算一处，一处分不清「改了三个字」与「整段重写」——那是给眼睛看的，不是给计数看的。四种「没有」分开写，但「为什么没有」不在这份数据里。人填的立案与分歧账按输入排除，不落进「其他」差异（理由见上一节）。按 id 对齐缓解了重排问题，代价是：模型如果换了一套 id（不是换顺序，是重新编号），两份会被读成「整份都不同」，这时表里的处数会虚高，界面上看不出来。端到端只验到「两份逐字相同 → 0 处」这一档，因为假模型两次输出必然相同；「有几处不同」那一档由 `check:sideby` 的样本与预览页截图负责，没有在真应用里跑过。
- **「结论的口气」只比字面上的词，读不出没写出来的那一步。** 它不看语义：报告把「同期下降」写成「因此下降」能抓到，写成「这解释了全部」就抓不到——那一步没有词可用。四张词表是人写的短表（软化、硬化、因果、并存），改表就会改结论，所以它是一场**有据的读法**，不是一个「越界判定器」。报告没给引文时，原文那一句是本地按字面重合找来的（阈值：结论一半以上的字要在那一句里出现过），界面上标着「本地找的」——找错了它会照样往下比。反过来，报告说越界、本地没读到，也照实写「本地只看字面」，不替它圆场也不替它背书；两边都说有差别时，也不替它们宣布「指的是同一处」。`check:modal` 的 61 条与八组反证能证明：长词优先（「不一定」不会被读成「一定」）、阈值两侧各判一次、四种差别各就各位、对得上时闭嘴、读不到时说读不到、核的过程不改报告；端到端 8 条能证明界面上的两句逐字来自报告的 `quote` 与 `text`、这一块长在结论名片之后。**没验的**：真实报告上的表现——假模型那份只落在「推论被写成断言」一种差别上，另外三种只在构造的样本上验过；真模型报告一次都没在这一栏上看过（余额为空）。
- **「骨架缺口」只查结构，不查内容，而且「没碰」不等于「没读到」。** 它把原文切句，看有没有任何条目的 span / 引文落到这句上；一句没被任何条目钉住，可能真是报告漏了，也可能是模型把它并进了上一句，本地分不开。支撑关系的环按报告自己写的 `supports` 算——模型画错了拓扑，本地照着错图找环。检查表那四档也是照 `answer` 字段数，模型判得对不对不在这一层视野里。还有一条更根本的边界：**本地能产出的判定只有这几类结构判断**；评级、可接受度、举证责任、检查项答案这些真正回答「站不站得住」的东西仍然全部来自模型，这一栏把「本地判定」从 0 变成了非 0，没有把它变成主要内容。端到端只在假模型那一份上验过（原文 5 句、1 句没人碰、检查表 3 条里 2 条「文中没交代」）；真模型报告上一次都没看过（余额为空）。
- **架构检查守的是「方向」，不是「依赖图全集」。** `check:arch` 只读源码里的静态字面量 import：把路径拼出来再 import、`require` 一个变量、`import type` 造成的类型环，它都看不见；它也没法判断「这条依赖在业务上该不该有」。三条进程边界、值 import 无环、同名常量唯一、`:root` 唯一、整屏归属与组件冻结线之外，其余架构判断仍然靠人。另外「一人一块」这一轮只落实在三块整屏上：主文件仍放着报告主体的多个组件，那条冻结线是防止它继续变大，不是宣称它已经拆干净。
- **「逐字比」只列字面，切出来的片段可能是半句话。** 它用最长公共子序列对齐两句，片段是「两句话对不上的连续部分」，不是词：原话「错的」被整理成「错误决定」，公共的「错」被留下来，于是片段只剩「误决定」——读起来像半个词，但它是逐字可复算的，本地不做分词，也不猜它本该是哪个词。这一层还有几处明写的边界：没有引文（隐含前提）与两句逐字相同都不显示，也不写「0 处」；超过 400 字就说「本地没比完」；只差单个字就说读不出连续片段。`check:rewrite` 与它的反证能证明：片段逐字来自输入、中间插字不牵连后面、顺序不倒、四种「比不出来」没被静默吞掉、界面没替报告下判断；端到端能证明它**贴在每张主张卡的原话那行后面**（不是报告外面另起一栏），把这一块摘掉后相关断言全红。**没验的**：真模型报告上的样子（余额为空），以及人看完这些片段是不是真的更会看论证。更要紧的一条：它**不改判定、不进正文、不落盘**——本地产出的判定点占比仍是上一栏那个数，这一件改变的是**改写可见**，不是判定权。
- **画布工程导出的兼容性是「读得进去」，不是「摆得好看」。** 我们写的是对方 2.7.0 的工程格式：一个 zip 容器，里面有 `stage.msgpack`（节点与连线）、`tags`、`reference`、`metadata`。`check:prg` 守的是：节点文字逐字来自报告、线不指向空处、坐标两两不叠、字节能被 `@msgpack/msgpack` 与 `@zip.js/zip.js` 读回同一棵树、版本号等于对方当前的常量、按钮到主进程的通道真的接上。另外**用对方自己的 CLI 读过一次**（2026-11-08，输出原样抄在 `docs/与画布工具互通.md`）：它把 7 个节点和 6 条线按我们写的位置与朝向读了出来。这三件事证明不了的是：图形界面里打开是否好看（节点尺寸由对方按内容重算，我们给的宽高只是草稿）；旧版本客户端能否打开新写的文件（我们只写当前版本）；对方改格式之后这份导出会不会失效——那要等 `check:prg` 里那条写死的版本号红了才知道。**不做的**：嵌它的画布（GPL-3.0，链进 exe 就要整个项目开源）、读它的工程文件（反向导入等于让别人的画布去改一份报告）、用它的界面当我们的界面。
- **「挑图」的选择存在本机，而且只验到「写进去」为止。** 它写在 `localStorage['al:views']`，换一台机器、换一个用户目录就回到默认三张；这本来就是界面偏好，不进存档也不跟着报告导出。端到端验的是「勾掉之后图真的消失、写进本机的 id 与界面上亮着的行一致、全显示时两张新图真的画出来」；**「关掉软件再打开仍然记得」这一半没有端到端验过**——只验了写入的值和初始化那行读回（`check:views` 有一条源码守卫）。写在源码上的保证不等于跑过的证据，所以这里写明。另外两张新图各有各的边界：反驳落点按 `strategy` 字段分四类颜色，那是按打法归类，**不表示哪一类更狠**；图上空心方块（没挂到具体关卡）不在少数，那个比例说的是「很多反驳只能指到某一处依据，指不到哪一关」，不是缺陷。修补对照画的是**重写后的写法**，不是重新分析的结果——补上之后到底站不站得住，要拿那段新文本再跑一次才知道，图上不画那个结果，画了就等于替你认定它成立。
- **「下一句」只保管原话，不解释它，而且到现在还是零条。** 它唯一的「分析」是逐字相同：完全一样的句子归一堆、数次数；差一个字就分开（「所以呢」与「所以呢？」算两组）。这不是漏，是这一层不做语义归并——一旦它开始判断「这句算不算空泛」，这份记录就变成了又一份由本地口径写下的判定，而它要回答的恰恰是「人自己是怎么说的」。它也不告诉你会不会因此「掉头」，那要人读。两个代价写在明处：一是它长在报告最底下，只有读到末尾的人才看得见（放到开头会让收上来的字变质），所以样本天生偏少；二是现在本机一条都没有，一个人写的话也不构成样本。`check:nextline` 与端到端能证明：原话逐字存回、顺序无关、空白记录不混进明细、删得掉、确实写进了文件（不只是内存里多一份）。证明不了这些句子能说明什么。
- **「自己列成立条件」只做字面上的对位，也不替人判。** 它不做同义匹配，不会替你找「意思差不多的那一句」；同一句挂好几条、点了却不写、点了不存在的句子都明说，但「这句到底算不算给了这个条件」始终由你读原文决定。这一屏**不存盘**，关掉就没了，要留得自己复制。`check:conditions` 与端到端能证明：原文逐字还原、引文坐标可复算、没有本地新写的判断、没有偷偷算出来的总分、填进去的字真的被重算。证明不了这样读一遍能让人下次自己会这样读，也证明不了它比一段裸提示词强——那仍然要靠人来判断。
- **「换个尺度读」只做字面替换，也不问它教不教得会人。** 同形异义、反讽、指代都不会被识别；换出来的文本可能读不通，那正是要你自己读的东西。`check:rescale` 与端到端能证明：原文逐字还原、编辑可逆、没被点名的字一个没动、例外全明说、填词后本地真的重算。证明不了这次换尺度让你看见了此前没看见的东西，更证明不了它比裸提示词强。
- **并排盲看现在做不出能推广的结论。** 想把模型原文渲染成朴素文本与本软件并排，需要「带 `raw.text` 的报告」；本机 103 份存档里只有 15 份带模型原文，且落在 **2 组文本**上（其中 14 份是同一段「取消早读」）。拿它做对照等于把 14 份重复当成 14 个样本。要解开这个结，得先有真模型在多种文本上跑出的新报告（要余额），或由人提供带模型原文的对照材料。
- **「回到原文重读」只验了形状，没验它教不教得会人。** `check:reread` 与端到端能证明：原文逐字还原、条目没挂错句、这一屏没有本地新写的判断文字、点得开也回得去。证明不了读完之后你能不能指着原文一句说「下次我自己会这样看」，更证明不了这一层比一段裸提示词强。后者要把存下的模型原文渲染成朴素文本、与本软件并排盲看；那一步不花钱，但需要你当评判者。这一屏没动提示词、没动判定，真模型评测仍旧没跑（余额为空）。
- **抽取结构依赖模型。** 重构错了，后面全错。界面允许对照原文核对每一条引文，定位失败的引文会标出来而不是假装对齐了。
- **单次调用，不做多遍自检。** 每次分析是一次模型调用；只有输出格式损坏时会要求重出一次（只修格式，不追问内容，用量记两笔）。多遍批判能提高质量，但成本和延迟翻倍，尚在权衡。
- **「来源账」只做总账与分区说明，没有逐处给每个判定打标。** 报告最上面那条把「模型给出的判断 N 处」与「本地复算的哪几类、各几处」摆出来；四类本地复算（逐字比 / 骨架缺口 / 结论口气 / 引文定位）的处数由 `@shared/provenance` 当场算，口径与 `npm run audit:provenance` 一致。`check:provenance` 能证明这些数不是写死的、界面文字逐字取自纯函数、旧宣称「判定在本地」不会写回来；`?source=1` 是预览页展开那一版的入口。**没做到的**：路线图第八节那句「把确定与模型认为在界面上彻底分开」只完成到「整份报告一句归属 + 本地那几类点名」，正文里每一处评级、可接受度、检查项答案旁边并没有单独标记；逐处打标要动十几处渲染代码，这一轮没做，所以不宣称那条处方已经完成。更要紧的一条：**这一层不改判定、不落盘、不产出新的本地判断**——本地独立判定点占比仍是 4.8%，它改变的是「谁说的」可见，不是判定权。真模型报告上的样子没验过（余额为空）。
- **「这一圈的词」不认术语，只认你填的那几个字。** 它不知道「自在之物」是哲学术语、也不知道「显著性」是统计术语——词表由你给，本地只按字面数出现次数、落在哪几句，以及报告结论／前提文字里有没有；原文与报告文字分开数（实测 406/407 条主张的 `text` 与 `quote` 不同）。动手前先量过 40 段评测语料：15 段学术／准学术体裁里显式定义词命中 **0 段**（全语料也只 1 段），引号词 32 个里跨 ≥2 句出现的只有 3 个，所以「自动认术语／自动判有没有定义过」做出来就是空面板，这一版没做。`check:terms` 与其反证能证明：词表去重保序、乱序句子仍按 index 升序、包含关系的词各算各的、空表与全不命中不说「0 处／没问题」、界面文字逐字取自常量；端到端能证明点开后真的填得进词、填完当场重算，预览页 `?terms=1` 是展开那一版的入口。**没做到的**：不判术语有没有换义，不按学科切换任何检查项、档位或举证责任——`docs/怎么读一篇学术论证.md` 那条「不按学科切换标准」没有被推翻，因为标准始终不在软件里，在你手里。**没验的**：本机 103 份存档里带学术字面线索的仍是 **0 份**；2026-11-09 另从网上取了 3 段公开期刊摘要（哲学认识论 / 认知科学 / 计量经济学），用 `npm run audit:field-samples` 复用界面同一个纯函数**只复算了原文侧**（出现次数、落句、首现、跨句），原文侧不是空面板。**那三段的报告侧四项仍未计**——它们只有原文、没有真模型报告；把空报告传进去，软件会写出「报告结论文字里没有这个词」这种假话，所以宁可明说量不了。但「报告侧量不了」只对**学术文本**成立：本机 103 份存档本身就是真模型报告，这四个字段读的是报告的字与结构，跟学科无关。`npm run audit:field-reports` 用 8 个固定探针词在真报告上量过：结论文字、前提文字、只在结论里三项都会亮，绝大多数报告至少亮一项；只有「出现的句子都没有条目落点」几乎不亮——判据要求该词**所有**落句都没被钉住，而高频词必然跨句（quiet 句本身并不少，词落在其中一句的也不少）。所以这一项在真实数据上是近乎空面板，原因在判据语义，不是功能坏了，也不因此删掉它。探针词是审计用字面串，不是领域词表、不是专家给的、不进产品；这些报告没有一份是学术文本；分组按 `passage` 逐字去重，与样本账按相似度并组的口径不是同一把尺子。实时数跑那条命令，不写进文档。这些是**期刊摘要（元陈述），不是论文正文里的论证段落**，不是你专业里的真文本、不是本机存档、不是使用证据，也不构成 P2 输入；词表由本次分析挑，不是领域专家给的。要看**学术文本上**完整那一栏，仍要有一次真模型分析（余额为空）。出处、逐字文本与六条边界见 [外部学术样本](docs/外部学术样本.md)；三段数据与文档引用块的逐字一致由 `check:field-samples` 进 `verify` 守着，逐词账看 `audit:field-samples`，实时数不写进文档。人填完这几个词是不是更会读自己那一行，仍是零证据。本地判定占比 4.8% 没动。
- **「停」只停这一边。** abort 掐断的是本机在等待的那个请求；请求若已经到达供应商，那边的生成与计费不受本工具控制。账本里会多一条**失败**记录：token 按字数估、金额记 0、余额不扣——所以余额会偏小，偏小的地方正是这里，别把它当成这一趟的真实花费。停下来的这一次不留半份报告：没有结果就不该在历史里占一行。
- **不做一阶逻辑。** 量词、谓词、论域模型与模型构造都未实现。非形式论证的有效性不靠真值表，这条路本就不在核心路径上。
- **修订对照只比「这副透镜的刻度」。** 两版档位的升降不跨透镜、不跨模式换算——那两套刻度本就不可通约。它也不会发现「你的修补引入了原文没有的新主张」这类语义变化，只能看到检查项和档位动了没有。
- **历史只在本机，没有同步。** 报告按时间列，能认出「这一份是从哪一份修出来的」（parentId），也能看到「此后改了几版」——修订链两头都可见。检索按字面在本机七类文字里找，不认同义词、不搜模型写的其余解释、读不出来的文件不在结果里；它不知道「你要找的是哪一份」，只回答「这个词出现在哪几份」。删除要**点两次**（第二次才是确认），因为删掉的报告不会回到对照链里。
- **逐段跑是「把同一个问题问 N 次」，不是「一次读懂整篇」。** 每段各自判档、各自存一份报告；长文台账把各段并排列出，但**不相加、不求平均、不判段与段的关系**。像问句/口号的段默认不跑（切分条里那一段仍可单独点开分析），一次最多 8 段，超出的逐条写明「超出上限」——不静默截断。跳过的段在台账里照样占一行并带理由，否则段号会从 2 跳到 4，读者会以为文章只有五段。台账只存索引（报告 id 与档位），不复制报告正文；「复制台账」走剪贴板、不落盘。真机跑道 `SMOKE_LONGFORM=1 npm run smoke` 验的是：五次调用真的发出去了、五份报告 id 互不相同、台账真写进了磁盘并能按报告 id 反查、点某一行能把那一段的报告调回来。**没验的**：真模型在长文上逐段跑出来的东西是否比整篇一份更有用（要真模型评测与人的盲看，余额仍为空）；也没验过读者能不能把几张分段报告在脑子里拼回整篇——软件不替你做这个拼接。
- **切分是启发式的。** 它只看段落和少数连接词，切不出「藏在句子里」的隐含论证；无标点的长文只能按字数硬切，而且明确标注是硬切。信它之前先看「切给我看」。
- **长文覆盖账只在 ≥800 字时出现，而且只数位置。** 报告主体第二条事实条说「原文多少句、条目落在几句上、按切分条切出的哪些段一句都没被落上」，句子与「有没有条目落上」用「回到原文重读」的口径，段就是「切给我看」的那些候选段。短文本不渲染这一栏（它的引文覆盖本来就高，摆一条 100% 的账是空面板）。**没被落上不等于分析漏了**——长文里本就有转述、铺垫、例子；本地不判该不该覆盖，也不劝、不打分。它不改判定、不落盘，本地独立判定占比仍是 4.8%。`npm run audit:longtext` 在真存档上复算那几个数字（依赖本机存档，不进 verify，没有长文本时明说量不了）；实时数以命令输出为准。真应用里的长文本报告没在端到端冒烟里跑过——端到端只验「短文本时整块不出现」，长文本那一版靠预览页 `?coverage=1`（演示原文由仓库内示例拼接，不是真实使用证据）与静态断言守。
- **用量数字不是账单。** token 可能来自本地估算，单价是你手填的，余额是手记的锚点往后扣的。够看趋势和量级，不够对账——对账请导出 CSV。
- **争议栏的触发是启发式的。** 从结论反推「这一份碰到了哪些学理分歧」，条件硬编码在 `disputesIn()` 里。它会漏（某些观念分歧没体现在字段上），漏的表现是「这一栏没提它」而不是提错。宁可漏，不编。
- **主张库会与代码脱节。** `theory-base.ts` 里每条主张都写了「它让本工具做了什么」，改了判定逻辑理论上要同步改它。`check:theory` 能抓住**落点是幻影**的那类脱节（decides 提到的代码标识符在 src/ 里不存在），管不到语义过时——字段还在、含义已经变了。后者仍只能靠人工对读 `docs/理论支撑/07` 那张映射表。两者放在同一个仓库里，就是为了让脱节看得见。
- **「手册核对」只核到中译本上册页 470。** 这次拿《论证理论手册》逐节对过 36 条主张（见 `docs/理论支撑/11-手册核对.md`），剩下 66 条**留空**，不拿相关条目的结论去填——界面头部那一行账写的就是这个数。写进提示词的 26 条（模式块 9 ＋ 透镜片段 17，两类同样 push 进正文）已经条条有核对；判「文献有反对」又进了提示词的那一条，界面会写出「模型每次都按它判」。**上册第 8、9 章（页 515、578 起）与下册第 10—12 章（页 625 起）都没读到**，压在那套理论上的条目记「本次未核到」；书里根本没有的题（批判性思维教育、解释学、韦伯）记「本书范围外」，两种不许混。另外手册对约翰逊、戈维尔、沃尔顿这些人的主张是**转述**，不是一手——核对能升到「可核到这一页」，升不到「一手文献」，两件事不是一回事。
- **十规则没有按讨论阶段分组。** 语用辩证学确有「哪条规则属于哪个阶段」的划分，但 `PRAGMA_RULES` 里没有这个字段。按记忆补一份映射就是编，所以那张网格图不做——要做得先加字段并核实出处。
- **透镜图只在选中那副透镜时出现。** 假模型每次只返回同一份数据，端到端冒烟走不到另外几张图；它们靠 `check:lens`（服务端渲染）单独验。改了组件名会让它失败，这是故意的。
- **系统语言不是中文或英文时，原生界面会回退成英文。** 安装包只带了 `zh-CN` 与 `en-US` 两个语言包（Electron 默认带 55 个，约 49MB，而界面只有中文，其余一个字节都不会被读到）。界面本身是 React 渲染的中文，不受影响；受影响的是文件对话框、原生菜单这类由 Chromium 提供的部分。`pack:check` 里有一条断言数着 locales 目录，防止这个优化悄悄退化。
- **界面只有中文。** 术语跟中文非形式逻辑文献的习惯一致（隐含前提 / 胜出 / 削弱性击败 / 证明责任）。
- **两个描述类模式只跑过三条真实样本。** 评测里重构 2 条、提问 1 条，接住了主要结构；但事先担心的那处真的中了：指代歧义（「不予采纳」采纳的是谁的）被模型挑了一种读法写进结构，`unknowns` 里只谈证据缺口、不谈另一种读法。提示词因此加了固定格式「另一种读法：…」，样本量还不足以说已经稳了。
- **评测的覆盖只保证形状，不保证标注属实。** 40 段语料对 18 类毛病逐条标注，`check:corpus` 守的是：每条语料都标了、每条最多标三类、每类至少三段、这三段的**体裁互不相同**、至少被**两种分析模式**考过（诊断 / 红队 / 查谬误 / 重构 / 提问五种模式都必须有语料）、各段字面不像（`dice < 0.25`——实测「同一段加一句」0.926、「加一整句因果」0.806、「换词换序重写」0.523、同类独立样本 0.171）。它验不了「这段文本真的埋了那类毛病」：那是写语料的人的判断，机器读不出来。所以覆盖矩阵满格，也可能是标注写错了。另外有相当一部分类刚好只有三段——具体哪几类、各类几段看 `npm run check:corpus` 打出的矩阵，这里不抄数字（没有断言守着的数字一定会烂）。这 40 段里 2026-11-03 之后加的 17 段**一次都没跑过模型**（余额为空），所以「软件在它们身上抓不抓得住」仍是零证据；「每类换场景换模式」这句话现在有断言守着，但它守的是**标注填得对不对**，不是文本里真的埋了那类毛病。
- **导出件新鲜度不等于提示词质量。** `check:prompt-drift` 333 条只验「落盘的那份 == 现场装配的那份」，以及改内容有没有换版本号、留注记；它读不懂这两份文字好不好，也判不了主／次／修订号选得对不对。版本锁挡得住「忘了留痕」，挡不住「留了痕但改坏了」。反证里有一处值得记住：导出器、基线、检查器共用同一份路径常量时，三处一起指错目录，整套断言照样全绿——所以检查器必须从项目根独立再锚一次，那条断言不能当冗余删掉。
- **「这把尺子」只做本机可复算的对回，不做历史复核。** 它认得出「这份报告用的是不是当前装机版」「这一版的注记写了什么」，认不出三个月前那一版具体装了哪些块——旧版全文与旧版 30 份指纹都没有存档，只有报告里留下的一枚指纹，而那一枚**不能在这里重算**。所以这一栏不显示「旧版与现在差了哪几块」，也不把版本不同说成「报告坏了」；找不到注记时明说「不能凭版本号推断当时改了什么」。注记是人写下的理由，不是效果评价，软件也不判哪一版更好。`check:prompt-history` 的 160 条与真机默认跑道能证明：六组关系分得开、三条边界一句不少、界面与导出件调同一个纯函数、基线注记与源码逐字相同、变更史点一下真的展开八行；证明不了的是哪版提示词真的更好——那仍然要真模型评测与人的盲看（余额为空）。
- **提示词的效果没有质量分，只有失效清单。** `prompt:lint` 与 `check:contract` 守结构，冒烟用假模型验链路，两者都不碰真实模型。补上的是 `npm run eval`：40 份真实语料逐条跑真模型，`eval:audit` 检查不变量（报告自相矛盾、指向不存在的主张）与写样本时记下的期望值。它不评分——评分会把「哪一句错了」压成一个数字；也不进 CI——每跑一次花六分钟与十七万 token。改动提示词或知识库之后手动跑一次，读 `docs/评测报告.md`。不做「让模型给自己的提示词打分再迭代」：那等于把判定标准交给被测对象。
- **重放验的是「解析与裁决」，不验模型。** 每份报告存下模型返回的原文（`raw`）之后，`npm run replay` 可以把同一段原文重新喂一遍当前代码，与存档逐字段比：0.8 秒、不联网、不花钱。它回答「报告变了，是我改坏了，还是模型这次说的不一样」这个问题的一半——**代码那一半**。另一半（模型会不会换个说法）仍然只能靠 `eval`。另外，重放只能验**已经存下来的那些原文**：手里 101 份存档只有 13 份带 `raw`（这个字段 11 月 1 日才加），所以它对旧报告的覆盖面是零，而这一点在输出里是明写的（「88 份没有模型原文，未参与重放」）。判据也不是零差异：版本升级本来就该有差异，判据是**每一处差异都能被解释**；解释不了的那一处，就是回归。
- **静默的地方都有据，但仍然可能过时。** 代码里每一个「接住异常却什么都不做」的 catch 都必须写 `@allow-silent:` 和一句理由，`check:robustness` 逐个数（具体处数以它的断言为准，这里不抄那个数字——没有断言守着的数字一定会烂）。有据的几处：重建索引时的坏文件、删不掉的文件、冒烟日志、记账写不进、账本里的半行、快捷键读剪贴板失败。理由写对了不代表它永远对——那条规矩只能保证静默是**一次有记录的决定**，不能保证它现在还成立。
- **请求失败的原因来自服务端。** 报错摘要（`briefOf`）截到 160 字并抹掉 `sk-` / `Bearer` 片段，但那段文字本身仍是对方服务器给的：它可能把你的请求内容原样回显，也可能给出与真实原因无关的话。摘要只用来指方向，不当结论读。
- **提示词库没有按文本动态裁剪。** 同一段文本、同一副透镜，提示词逐字相同。否则指纹失去意义，报告之间不可比。代价是短文本也要带上完整索引（最长的一份约 15800 字符）。
- **「这段跑过没有」量的是字面，不是论证。** 同一段话换个说法重写，重合度会掉到 0.4 以下，那一行就不出现——这是有意的：字面不重合就说字面不重合，拿字面去猜「这是不是同一个论点」只会更不可信。判定在 `@shared/sameness`（纯函数，`check:sameness` 守着）。阈值 0.85 是拿真实存档量出来的（128 字加两句 = 0.897），不是估的；但它是二元组 Dice，改一个字会打断两条，所以短文本改几个字掉得很快（60 字段落改 5 个字约 0.83，判成「不同」）。这个盲区改不掉，只能写出来。它读的是全部存档报告全文（102 份约 19ms），故意不做缓存——缓存漏了失效时机，就会在删掉报告之后继续说「跑过 89 次」。**它只是说出来，不是阻止**：真实证据是「它让人少跑了几遍」，而那要有第二个使用者才看得见。
- **全局快捷键只读剪贴板，不抓「选中」的文本。** 在别的应用里选中一段字、直接按键分析，需要模拟一次 Ctrl+C：那会改动用户的剪贴板、在部分应用里触发粘贴副作用，而且没有办法在无人值守的环境里验证它真的抓到了那段字。所以路径是「先复制，再按 Ctrl+Alt+A」。这个键可能被截图工具或输入法占着，注册失败是常态——界面会写「没启用：……被占用了」，而不是继续显示一个按了不响的键。判定（填 / 问 / 不填）在 `@shared/capture` 里，由 `check:capture` 守着；注册与读剪贴板在主进程，那部分只验过「没注册上时会说实话」，没验过真按一下键（端到端里没有全局键盘事件）。读剪贴板本身抛错（被别的进程独占）时，现象就是「按了没反应」——快捷键回调里没有界面通道，这一条只能写在文档里，不在界面上。

## 往哪走

规划不在 README 里，在 [路线图](docs/路线图.md)。

一句话概括：**工程质量已经远超产品验证**——八百多条断言证明「界面该出现的出现了」，而「判断对不对」只有二十三份语料、一家模型在管。所以接下来排的不是功能，是两件事：让验证变便宜（存原文、离线重放、一条命令跑完），以及拿到真实使用的证据。

**主线「像 AI 加提示词」已于 2026-11-12 结案**：用户选择收敛定位，软件不再承诺本地独立判定，改以「模型输出可读化 + 回看工具」为准。这不是把问题解决了，是关闭一项自己兑现不了的承诺；当场数字、放弃与保留的边界见 [产品定位](docs/产品定位.md)。真模型评测与真实使用证据仍可单独做，但它们现在回答的是「判断对不对、人看完有没有变化」，不再是这条主线的解锁条件。

那份文档里还有一张**不做清单**（不加第七副透镜、不再加断言、不做云同步），以及三条**该掉头的条件**。写在动手之前，才不会被沉没成本绑架。

### 每条规则凭什么

上面这些是「谁说的」。但「凭什么」是另一个问题——用户读完一份判定，最自然会追问这一句。只答「沃尔顿说的」是把权威当理由，而这个工具连专家意见都要追问六条 CQ，它自己不能靠权威站住。

`docs/理论支撑/` 十编回答这个问题，每编统一四段：**核心问题 → 互相对立的立场 → 本软件的站位与代价 → 落到哪个字段**。

| 编 | 回答的问题 |
|---|---|
| 01 论证是什么 | 一段话凭什么算论证；判错的代价为什么不对称 |
| 02 好论证凭什么 | 规范力量的四个来源；为什么拒绝单独采用「受众认同」 |
| 03 型式的认识论 | CQ 是默认条件而不是清单；为什么「未回答」是一档完整答案 |
| 04 语境为什么改变结论 | 同一句话换个场合就换性质；受众是判定参数而非背景 |
| 05 谬误的自然史 | 人为什么会犯；为什么这个工具不该是判决 |
| 06 机器能做什么 | 哪部分是模型能力，哪部分是脚手架；三档能力对应三种界面义务 |
| 07 理论到代码 | 26 条映射表 + 未落地清单 |

全文按三档标注可信度：**A 一手**（指得到具体文献位置）／**B 转述**（据教材或综述，不伪装成一手）／**C 我的判断**（可被推翻，并写清代价）。这套标注与产品里的 `tag` 字段（known / inferred / framework / guess）是同一套纪律——文档不能比软件更自信。

### 再往下一层：每条主张有多硬

十编是散文，理论卡是一副透镜一张。两者之间还缺一级：**一副透镜背后有七八条互不相同的主张**，卡片只能给整副的「道理在哪」，给不了其中一条的根据。

`src/shared/theory-base.ts` 把这个缝补上了：102 条主张，跨十编，每条四个实质字段。其中 `decides`（它让本工具做了什么）是**准入门槛**——指不出字段、指不出行为的主张不许进库。这条规矩同时是一面镜子：写不出落点的地方，就是那一编的理论其实还没落到代码里。`check:theory` 把门槛变成检查：decides 里写下的代码标识符必须真的存在于 src/（排除库文件自己——主张写什么库文件里就有什么，幻影字段在原地当然「找得到」）；这条检查上来之前，库里真有过三处写着不存在的字段。

当前 A 22 / B 47 / C 27。**后两档加起来比第一档多，这是实情，不是谦虚**——一个论证分析工具里真正能追到原文的规定只占少数。把 C 档那 27 条标成 A 档，这个库会显得很硬，然后每一条都经不起追问。

每条主张还带一个**细分域**（20 个，封闭枚举）：编按「理论在回答什么」分，细分域按「话题」分——举证责任的主张散在二、四两编，细分域让它们一屏看全。界面顶栏「理论」可搜索、可按档与细分域筛选；报告里的「专题分析」区块与六个「专题·」域共用这根轴（见下一节）。

### 第八、九、十编：批判性思维、哲学人文视野、其他论证传统

前七编全部来自分析传统下的论证理论。后三编把另外三条线索补进来：

- **第八编「批判性思维」（12 条）**：Facione 的 Delphi 共识把批判性思维分成六项技能——解读、分析、评价、推论、说明、自我校准。本工具代劳三样、代劳半样（解读：切分是启发式）、完全不代劳一样（自我校准：它不回查自己）。这笔账算在 T8-01/T8-07 里，并写进报告底部的边界区块，而不是留给用户自己发现。批判不等于否定（T8-08），这就是重构与提问两个模式的理论根据。
- **第九编「哲学与人文视野」（12 条）**：修辞学（说服有三个来源，工具只评 logos）、诠释学（善意原则的哲学根据）、言语行为（反驳必须落在被断言的命题上）、权力与立场（工具不声明视角、只有一套规范——把局限写成已知限制，比写成「兼容多元」更诚实）。这一编多数主张落到的是**删掉的能力**：不做什么，以及为什么不做。
- **第十编「其他论证传统」（6 条）**：墨家「辞以故生，以理长，以类行」（三物必具）、三表法（历史／见闻／实效）、名家与荀子的名实之辨、因明三支。加这一编的理由只有一条：第九编写了「只有一套规范」，而那句话若不写出另一套长什么样，就只是检讨。六条里三条是**明确的缺口**（「类」这一层没有、名实层次判不了、因明不打算做），一条真能对上（名／辞／说三层与本工具的定义栏、结论字段、支撑链一一对应）。对照写出来才知道差在哪：「墨家离这套工具的距离，比图尔敏远得多。」

这三编有一半篇幅在写本工具不做什么。**「不做」在这个库里是合法落点**——指得出是哪一条设计决定、理由是什么、谁会反对，就比「还没做」强。

### 边界区块：报告自己交代自己省掉了什么

报告末尾（语境坐标之前）有一栏「这份分析自身的边界」，全部本地推导、不调模型。它分三组，因为三类边界的性质不同：**它不评价人**（动机、品格、情绪、制度位置）、**它代劳到哪一层为止**（解读只代劳一半、不回查自己、检查不递归、只说明不理解）、**它只有一套规范**（不按领域换、不按传统换、不声明视角）。恒定十三条，加本次特有的（描述类模式不给判定、无对手方、判成不适用）。每条挂一条理论主张的 id，那个 id 是可以点的：点了打开理论库并定位到那一条，能看到它的出处、落点与反对意见。边界也一样可以被反驳——点不动的话，那行 id 就只是装饰。

界面上有两处入口：顶栏「理论」看全文（可搜索、可按档与细分域筛选），侧栏透镜卡底部列出**这副透镜专有**的那几条（六副共用的 72 条底座只交代数量——第一版混在一起，侧栏显示「这一栏站在 39 条主张上」，而 39 条等于全部，等于没有信息）。主张库末尾附十规则：每条守什么、违反长什么样、落在哪。

**每一条主张展开后都有一行「落在」**：提示词块、透镜片段、代码里的函数、或界面区块。这些地址不是写给人看的注释，是 `npm run check:landing` 每次都会核一遍的——块改名、函数改名、区块改名，检查器当场报错。这条规矩的来历写在 `docs/理论支撑/07-理论到代码.md` 里：上一版有 70 条只写着「（行为层）」，等于 70 个地址是空的。

详见 `docs/理论主张库.md`。

### 专题分析：另一类「其他分析」，但不新增透镜

六副透镜与四种模式之外，报告里还有一栏**专题分析**：六个专题（类比／因果与统计／来源与权威／实践推理／定义与含混／预设与问句），各自是一类论证在文献里的共识问题清单。同一段话落在哪个专题上，决定该多问哪几问。

它刻意做成三件事**都不做**：不新增第七副透镜（透镜决定问什么，专题只是问题清单）；不给档位（档位只有 verdict 一处，给分就把清单法变回打分表）；不调模型（由已落盘的型式族、担保类型、命题类型和原文用词本地推导，零成本、可复现）。未命中的专题照列并写明为什么没命中——只显示命中的，用户就分不清「没命中」和「没检查」。
